@@collection 07_find | Finding files with find
@@about
How find walks a tree and evaluates tests and actions: names, types, sizes, times, permissions, operators and precedence, exec, delete, xargs, and the classic traps.

@@group How find works
@@q single | What find searches
What does `find` look at when it searches?
(+) The attributes of files and directories (name, type, size, owner, time, permissions), walking a directory tree recursively. :: It does not read file contents; that is `grep`'s job.
(-) The text inside the files. :: `grep -r` searches contents.
(-) Only the current directory, without sub-directories. :: It recurses by default (unless `-maxdepth` is used).
(-) A database of file names updated daily. :: That is `locate`; `find` walks the real file system each time.

@@q single | Default starting point
Which statement about `find` without arguments is true (with GNU find)?
(+) It starts from the current directory and prints everything below it. :: Equivalent to `find . -print`.
(-) It searches the whole file system from `/`. :: You must give `/` explicitly.
(-) It prints an error about the missing path. :: GNU find defaults to `.`.
(-) It prints only the hidden files. :: Everything is listed.

@@q match | Anatomy of a find command
Match each part of `find /etc -name '*.conf' -print` with its role.
(=) `/etc` => The starting directory to walk :: Where the search begins.
(=) `-name '*.conf'` => A test that keeps only matching names :: Evaluated for each file found.
(=) `-print` => An action that writes the path :: The default action when none is given.
(=) `'*.conf'` => A glob pattern that find itself interprets :: Quoted so the shell leaves it alone.
(-) A shell redirection :: None of the words is a redirection.

@@q single | Quote the pattern
Why is `find . -name "*.txt"` written with quotes?
(+) So that the shell does not expand `*.txt` into file names of the current directory before `find` runs. :: `find` must receive the pattern itself.
(-) Because `find` refuses patterns without quotes. :: It is the shell's expansion that causes trouble.
(-) Quotes make the search case-insensitive. :: That is `-iname`.
(-) Quotes make the search recursive. :: It is recursive anyway.

@@q single | The unquoted pattern trap
In a directory that contains the single file `one.txt`, you run `find . -name *.txt`. What happens?
(+) The shell turns `*.txt` into `one.txt`, so `find` looks for files named exactly `one.txt` everywhere, and misses all other `.txt` files. :: The command silently finds less than you wanted.
(-) `find` lists every `.txt` file of the tree. :: Only with quotes.
(-) `find` fails with a syntax error. :: It runs normally with the wrong pattern.
(-) `find` lists only `one.txt` in the current directory. :: It searches the whole tree for that name.

@@q fill | Case-insensitive name search
To match `.txt`, `.TXT` and `.Txt`: `find . {{-iname}} '*.txt'`
(x) -name :: Case-sensitive: `.TXT` would be missed.
(x) -i :: Not an option of `find`.
@@note
`-iname` is the case-insensitive version of `-name`.

@@q single | -name and paths
Why does `find . -name 'a/x.txt'` never find anything?
(+) `-name` compares the pattern only against the last component (the base name) of each path; use `-path` for patterns that contain slashes. :: For example `find . -path '*/a/x.txt'`.
(-) Because `x.txt` does not exist. :: The behaviour is independent of that.
(-) Because `-name` only works in the current directory. :: It works on the whole tree.
(-) Because slashes must be doubled. :: Not the reason.

@@q multi | Patterns find understands
Select the true statements about the pattern of `-name`.
(+) It uses glob syntax (`*`, `?`, `[...]`), not regular expressions. :: Like shell wildcards.
(+) It is matched against the file name only, not the directory part. :: Base name only.
(+) A leading dot is matched by `*` (unlike in shell globbing), so hidden files are found. :: `find . -name '*'` includes dot-files.
(-) It is a regular expression, so `.*\.txt` is the right form. :: That would be `-regex`.
(-) It is case-insensitive by default. :: Use `-iname`.

@@q sort | Find tests and actions
@@buckets Test (decides if a file matches) | Action (does something)
Classify each find primary.
(Test (decides if a file matches)) `-name '*.c'` :: Selects files by name.
(Test (decides if a file matches)) `-type d` :: Selects directories.
(Test (decides if a file matches)) `-size +1M` :: Selects by size.
(Test (decides if a file matches)) `-user alumno` :: Selects by owner.
(Action (does something)) `-print` :: Writes the path to standard output.
(Action (does something)) `-delete` :: Removes the file.
(Action (does something)) `-exec ls -l {} \;` :: Runs a command for the file.

@@group Type, depth and names
@@q match | -type letters
Match each `-type` letter with the kind of file.
(=) `f` => A regular file :: Ordinary data or programs.
(=) `d` => A directory :: Folders.
(=) `l` => A symbolic link :: Links to other paths.
(=) `b` => A block device :: Disks and similar.
(=) `c` => A character device :: Terminals and similar.
(-) A hidden file :: Hidden files are found by name, not by type.

@@q single | Hidden files
How do you find the files whose names start with a dot, directly in the current directory?
(+) `find . -maxdepth 1 -name '.*' -type f` :: The pattern `.*` matches names that begin with a dot.
(-) `find . -hidden` :: There is no `-hidden` test.
(-) `find . -type h` :: No such type.
(-) `find . -name '*.'` :: That matches names ending in a dot.

@@q match | Depth options
Match each option with its effect.
(=) `-maxdepth 1` => Only the starting directory and its direct children :: No deeper levels.
(=) `-mindepth 1` => Skip the starting point itself :: Level 0 is not reported.
(=) `-maxdepth 2` => Down to grandchildren of the start :: Two levels.
(=) `-depth` => Process each directory's contents before the directory itself :: Needed for bottom-up work such as deleting.
(-) Follow every symbolic link :: That is `-L`.

@@q single | Only direct children
Which command lists only the regular files directly inside `dir` (not in sub-directories)?
(+) `find dir -maxdepth 1 -type f` :: Stops after the first level.
(-) `find dir -type f` :: Recurses through everything.
(-) `find dir -depth 1 -type f` :: `-depth` takes no number.
(-) `find dir -d 1 -type f` :: Not a valid option.

@@q single | Directories are files too
Why does `find a -size +2k` also print directory names such as `a` or `a/b`?
(+) Directories are files with their own size (often 4096 bytes), so a test on size matches them; add `-type f` to restrict to regular files. :: Always combine size tests with `-type f` when you mean files.
(-) Because `-size` counts the files *inside* the directory. :: It uses the size of the directory entry itself.
(-) Because of a bug in `find`. :: It is documented behaviour.
(-) Because `-size` ignores the type of file. :: It does look at the size, but directories have one too.

@@q single | Whole path tests
Which test matches the full path and is the right one for `*/src/*.c`?
(+) `-path '*/src/*.c'` :: Compares the pattern against the whole path.
(-) `-name '*/src/*.c'` :: `-name` sees only the base name.
(-) `-type '*/src/*.c'` :: `-type` takes a single letter.
(-) `-regextype '*/src/*.c'` :: That option selects a regex dialect.

@@group Size, time and permission tests
@@q single | Size suffixes
What does `find . -size +1M` select?
(+) Files that use more than 1 mebibyte (rounded up to whole MiB). :: `M` means 1024×1024 bytes.
(-) Files that use exactly 1 MB. :: A plus sign means "more than".
(-) Files that are at most 1 MB. :: That is `-1M`.
(-) Files modified more than a minute ago. :: Time uses `-mmin`.

@@q match | Size units
Match each suffix of `-size` with its unit.
(=) `c` => Bytes :: `-size 100c` is exactly 100 bytes.
(=) `k` => Kibibytes (1024 bytes) :: Rounded up.
(=) `M` => Mebibytes :: Rounded up.
(=) `G` => Gibibytes :: Rounded up.
(=) (no suffix) => 512-byte blocks :: The historical default, often a surprise.
(-) Megabits :: No suffix stands for bits.

@@q single | Sizes are rounded up
What does `find . -type f -size -1k` match?
(+) Only empty files (size 0), because sizes are rounded up to whole units and "less than 1" therefore means zero units. :: A 1-byte file counts as 1k.
(-) All files smaller than 1000 bytes. :: Rounding makes that false.
(-) All files of exactly 1 KiB. :: That is `-size 1k`.
(-) All files bigger than 1 KiB. :: That is `+1k`.

@@q single | Sizes exactly
Which command finds files of exactly 100 bytes?
(+) `find . -type f -size 100c` :: The `c` suffix counts bytes without rounding.
(-) `find . -type f -size 100` :: That is 100 blocks of 512 bytes.
(-) `find . -type f -size 100k` :: 100 kibibytes, rounded up.
(-) `find . -type f -size +100c -size -100c` :: Contradictory: no file matches both.

@@q fill | Files over two megabytes
Find the files under `/usr/lib` larger than 2 MiB: `find /usr/lib -type f -size {{+2M}}`
(x) 2M :: Only files whose size rounds to exactly 2 MiB.
(x) -2M :: Files *smaller* than 2 MiB.
@@note
A plus means "more than", a minus "less than", no sign "exactly".

@@q single | Days and mtime
A file was modified 36 hours ago. Which test matches it?
(+) `-mtime 1` :: Ages are counted in whole 24-hour periods with the fraction dropped: 36 hours is 1 day.
(-) `-mtime +1` :: That needs at least 2 full days.
(-) `-mtime 2` :: It is not yet two days old.
(-) `-mtime -1` :: That means less than one full day.

@@q match | Time tests
Match each test with the files it selects.
(=) `-mtime +7` => Modified more than 7 full days ago :: Old files.
(=) `-mtime -1` => Modified less than one day ago :: Today's files (last 24 hours).
(=) `-mmin -30` => Modified in the last 30 minutes :: Minutes instead of days.
(=) `-newer ref` => Modified more recently than the file `ref` :: Compares with another file's time.
(=) `-atime +30` => Last read more than 30 days ago :: Access time.
(-) Created more than 30 days ago :: `find` has no creation-time test in this form.

@@q single | Which time
What does `-mtime` look at compared with `-ctime`?
(+) `-mtime` is the last change of the file's contents; `-ctime` is the last change of its inode (permissions, owner, links, or contents). :: `ctime` is not "creation time".
(-) They are the same. :: They differ.
(-) `-ctime` is the creation time. :: Linux does not keep creation time in that field.
(-) `-mtime` is the last time it was read. :: That is `-atime`.

@@q fill | Recently modified
List regular files changed in the last hour: `find . -type f {{-mmin}} -60`
(x) -mtime :: That counts days, so `-mtime -60` means less than 60 days.
(x) -newer :: That compares against a reference file.
@@note
`-mmin` uses minutes, `-mtime` days.

@@q match | Permission tests
Match each test with its meaning.
(=) `-perm 644` => The mode is exactly 644 :: No more and no fewer bits.
(=) `-perm -644` => All of the bits of 644 are set (others may be set too) :: A minus means "at least these".
(=) `-perm /222` => Any of the write bits is set :: A slash means "any of these".
(=) `-perm -u+x` => The owner can execute :: Symbolic form.
(-) No bit of 644 is set :: No single form means that.

@@q single | Executable files
Which command finds regular files that are executable by their owner?
(+) `find . -type f -perm -u+x` :: At least the owner's execute bit is set.
(-) `find . -type f -perm u+x` :: Without a minus, find looks for exactly that mode.
(-) `find . -type f -executable -user root` :: That adds a condition about the owner.
(-) `find . -perm +x -type d` :: That selects directories.

@@q fill | Writable by anyone
Find files that are writable by **any** of owner, group or others: `find . -type f -perm {{/222 ;; /u+w,g+w,o+w}}`
(x) -222 :: That requires all three write bits at once.
(x) 222 :: Exactly mode 222, which is very rare.
@@note
`/mode` means "any of these bits"; `-mode` means "all of these bits".

@@q multi | Owners and groups
Select the tests that select files by owner or group.
(+) `-user alumno` :: Files owned by that user.
(+) `-group devs` :: Files whose group is `devs`.
(+) `-uid 1000` :: Numeric user id.
(-) `-owner alumno` :: Not a GNU find test (`-user` is).
(-) `-mine` :: No such test.

@@q single | Empty files and directories
Which option selects empty files and empty directories?
(+) `-empty` :: A zero-length file, or a directory without entries.
(-) `-size 0` :: Finds zero-size files and, in practice, not empty directories (their size is not 0).
(-) `-null` :: Not valid.
(-) `-blank` :: Not valid.

@@group Combining tests
@@q single | Implicit and
What does `find . -name '*.c' -type f` mean when no operator is given between the tests?
(+) Both tests must be true (an implicit `-a`). :: A file name ending in `.c` and a regular file.
(-) Either test may be true. :: That needs `-o`.
(-) The second test is ignored. :: Both count.
(-) The tests are evaluated in random order. :: They are evaluated left to right.

@@q single | Or needs parentheses
You want `.txt` or `.log` **regular files**. Which command is correct?
(+) `find . -type f \( -name '*.txt' -o -name '*.log' \)` :: The escaped parentheses group the alternatives so that `-type f` applies to both.
(-) `find . -type f -name '*.txt' -o -name '*.log'` :: The `-o` splits the expression: `-type f -name '*.txt'` or `-name '*.log'`; directories named `*.log` would match.
(-) `find . -type f -name '*.txt|*.log'` :: A glob does not support `|`.
(-) `find . -type f ( -name '*.txt' -o -name '*.log' )` :: Unescaped parentheses belong to the shell and cause a syntax error.

@@q single | Precedence surprise
What does `find a -name '*.txt' -o -name '*.log' -print` print?
(+) Only the `.log` files: `-print` belongs to the right-hand side, because `-a` binds tighter than `-o`. :: A `.txt` match is true but has no action, so nothing is printed for it.
(-) Both `.txt` and `.log` files. :: That needs parentheses or no explicit `-print`.
(-) Only the `.txt` files. :: Reversed.
(-) Nothing, `-o` disables `-print`. :: The right-hand side prints.

@@q single | Default print
Why does `find a -name '*.txt' -o -name '*.log'` (no explicit action) print both kinds?
(+) When no action is given, `find` adds an implicit `-print` for the **whole** expression. :: The trap appears only when you write one `-print` yourself.
(-) Because `-o` combines the lists of results. :: It is a boolean operator.
(-) Because `-name` is an action. :: It is a test.
(-) Because the default is to print only `.log` files. :: No such default.

@@q fill | Negation
Find every regular file whose name does **not** end in `.txt`: `find . -type f {{! ;; -not}} -name '*.txt'`
(x) ~ :: Not an operator in `find`.
(x) -no :: Not valid.
@@note
Use `\!` if your shell treats `!` specially (for example history expansion in an interactive session).

@@q sort | Which files does this select
@@buckets Selected | Not selected
Expression: `find . -type f \( -name '*.sh' -o -name '*.bin' \) -perm -u+x`. Decide for each file.
(Selected) `./run.sh` (executable by the owner) :: A `.sh` regular file with `u+x`.
(Selected) `./tools/app.bin` (mode 755) :: A `.bin` file the owner can execute.
(Not selected) `./notes.sh` (mode 644) :: Right name, but no execute bit.
(Not selected) `./lib.so` (mode 755) :: Executable, but the name is neither `.sh` nor `.bin`.
(Not selected) `./scripts.sh/` (a directory with mode 755) :: The name fits, but it is not a regular file.
(Not selected) `./TOOL.BIN` (mode 755) :: `-name` is case-sensitive, so `.BIN` does not match `*.bin`.

@@group Actions
@@q single | exec semantics
What does `find . -name '*.log' -exec rm {} \;` do?
(+) It runs `rm` once per file found, replacing `{}` by the file name. :: The `\;` ends the command given to `-exec`.
(-) It removes every file of the directory. :: Only the `.log` files.
(-) It prints the names without deleting. :: `rm` does delete.
(-) It runs `rm` once with all names. :: That is the `+` form.

@@q single | Semicolon versus plus
What is the difference between `-exec cmd {} \;` and `-exec cmd {} +`?
(+) With `;` the command runs once per file; with `+` many file names are appended to one command line, which is faster. :: Like `xargs`.
(-) They are identical. :: The number of invocations differs.
(-) `+` runs the command on directories only. :: It works on the matches.
(-) `;` needs root privileges. :: No.

@@q single | Escaping the semicolon
Why must the semicolon after `-exec` be written as `\;` or `';'`?
(+) An unescaped `;` would be interpreted by the shell as the end of the `find` command. :: `find` needs to receive the `;` literally.
(-) Because `find` accepts only escaped characters. :: It accepts the plain character when it arrives.
(-) Because `;` means "or" in find. :: That is `-o`.
(-) Because `;` is not allowed in file names. :: It is allowed.

@@q single | Ask before
Which action asks for confirmation before running the command for each file?
(+) `-ok` :: Like `-exec`, but prompts first.
(-) `-confirm` :: Not valid.
(-) `-ask` :: Not valid.
(-) `-interactive` :: Not valid.

@@q single | The -delete trap
Why is `find /tmp/work -name '*' -delete` dangerous?
(+) It matches everything, including `/tmp/work` itself, so the directory and all it contains are removed. :: Preview with `-print` first.
(-) `-delete` needs root. :: Not for your own files.
(-) `-delete` only removes empty files. :: It removes whatever matches (directories must be empty, which works because it deletes depth-first).
(-) It removes the parent of `/tmp/work`. :: Only the matches.

@@q single | Order of delete
In `find q -name '*.tmp' -delete -print`, what do you see for a file `q/a.tmp`?
(+) The path `q/a.tmp` is printed after it was deleted. :: Actions run left to right; `-delete` succeeds, so `-print` follows.
(-) Nothing is printed, `-delete` ends the expression. :: Both actions run.
(-) `-print` runs first, then the file disappears. :: The order is as written.
(-) An error, because two actions cannot be combined. :: They can.

@@q order | Safe clean-up
Put these steps in order to delete old log files safely.
(>) Run `find /var/tmp -name '*.log' -mtime +30 -type f` to see the candidates :: Only `-print` (the default) shows what would be deleted.
(>) Check the list: expected names, nothing unexpected :: Human review step.
(>) Re-run the same command with `-delete` at the end :: The action comes after all the tests.
(>) Run the first command again to confirm nothing is left :: Verification.

@@q single | find and xargs
Which command safely removes `.tmp` files whose names may contain spaces?
(+) `find . -name '*.tmp' -print0 | xargs -0 rm` :: Null-separated names survive spaces and newlines.
(-) `find . -name '*.tmp' | xargs rm` :: Names with spaces split into several arguments.
(-) `rm $(find . -name '*.tmp')` :: Word splitting breaks names with spaces.
(-) `find . -name '*.tmp' > rm` :: That creates a file named `rm`.

@@q single | Command substitution vs exec
What is a disadvantage of `rm $(find . -name '*.bak')` compared with `find . -name '*.bak' -delete`?
(+) The shell splits the result on whitespace (and may hit the argument-length limit), so unusual names are mishandled. :: `find` does the job internally without such limits.
(-) It is always slower for small directories. :: Speed is not the issue.
(-) It cannot delete files. :: It can.
(-) It deletes only the first file. :: It passes all names.

@@q single | printf
What does `find . -maxdepth 1 -type f -printf '%f %s\n'` print?
(+) For each regular file: its base name and its size in bytes. :: `%f` is the name, `%s` the size.
(-) The permissions of each file. :: That would be `%m`.
(-) The full path and the owner. :: `%p` and `%u`.
(-) The list of directories. :: It is restricted to files.

@@q single | Skipping a directory
Which expression lists the files of the current tree but does not descend into `./node_modules`?
(+) `find . -path ./node_modules -prune -o -type f -print` :: `-prune` stops the descent; the `-o` makes the rest apply to other paths.
(-) `find . -type f -not -name node_modules` :: That excludes a file with that *name*, but still walks into the directory.
(-) `find . -maxdepth 1 -type f` :: That does not look deeper at all.
(-) `find . -skip node_modules` :: Not a valid option.

@@group Scenarios
@@q single | Big files
Which command lists the regular files in `/var` larger than 100 MiB?
(+) `find /var -type f -size +100M` :: Type plus size.
(-) `find /var -size +100` :: That is in 512-byte blocks, and includes directories.
(-) `find /var -type f -size 100M` :: Exactly 100 MiB (rounded).
(-) `du -h /var` :: Lists the usage of every directory, not individual files.

@@q single | Recently changed scripts
Which command lists the shell scripts in your home directory modified in the last 7 days?
(+) `find ~ -type f -name '*.sh' -mtime -7` :: `-7` is "less than 7 days".
(-) `find ~ -type f -name '*.sh' -mtime +7` :: Older than a week.
(-) `find ~ -type f -name '*.sh' -mmin 7` :: Exactly 7 minutes ago.
(-) `find ~ -name '*.sh' -newer 7` :: `-newer` needs a file.

@@q single | Own writable files
Which command lists the files of your home directory that you have permission to write?
(+) `find ~ -type f -writable` :: `-writable` tests real write access of the current user.
(-) `find ~ -type f -perm 200` :: Only files with mode exactly 200.
(-) `find ~ -type f -user root` :: Files that belong to root.
(-) `find ~ -type f -perm -o+w` :: Files writable by *others*.

@@q single | Copy found files
Which command copies every `.sh` file found below the current directory into `~/backup`?
(+) `find . -name '*.sh' -exec cp {} ~/backup/ \;` :: `cp` runs once per file.
(-) `find . -name '*.sh' | cp ~/backup/` :: `cp` does not read file names from its standard input.
(-) `cp find . -name '*.sh' ~/backup/` :: That passes `find` as a file name.
(-) `find . -name '*.sh' > ~/backup/` :: Redirects the list of names into a path that is a directory.

@@q single | Count matches
Which command prints how many `.conf` files there are below `/etc`?
(+) `find /etc -name '*.conf' | wc -l` :: One path per line, counted.
(-) `find /etc -name '*.conf' -c` :: No such option.
(-) `wc -l /etc/*.conf` :: Counts lines in the files of one directory, not the files themselves.
(-) `grep -c .conf /etc` :: `/etc` is a directory, and it would look inside the files.

@@q single | Contents or names
Which command lists the files under `/etc` whose **contents** include the word `nameserver`?
(+) `grep -rl nameserver /etc` :: The question is about file *contents*.
(-) `find /etc -name nameserver` :: That looks at file names.
(-) `find /etc -type nameserver` :: Not a valid type.
(-) `locate nameserver` :: Also a name search.

@@q single | find versus locate
Why can `locate` miss a file that `find` would find?
(+) `locate` reads a prebuilt database that is refreshed periodically, so very recent files are not in it. :: `find` looks at the real file system each time.
(-) `locate` only searches the current directory. :: It searches the database of the whole system.
(-) `locate` refuses names with dots. :: No such limit.
(-) `find` and `locate` always agree. :: The database can be outdated.
