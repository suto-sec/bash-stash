Ten single-choice questions with traps: functions that change globals, a file truncated before it is read, variables set only for one command, double spaces and the difference between a builtin and its twin program.

@@q single | return and exit in functions
@@topic scripts
`s.sh` contains:
```
x=1
f() { x=2; return 5; echo never; }
f
echo "$? $x"
g() { exit 7; }
g
echo after
```
You run `bash s.sh; echo $?`. What is printed?
(-) `5 1`, `after` and `0` :: A function can change the variables of the script, and `exit 7` ends the whole script, not only the function.
(-) `5 2`, `after` and `7` :: `exit` inside a function ends the script, so `after` never appears.
(+) `5 2` and `7` :: `return 5` leaves `f` with status 5, and `x` is a global variable that `f` changed; `exit 7` in `g` ends the script with 7.
(-) `0 2` and `7` :: After `f`, `$?` holds the status given to `return`, 5.

@@q single | Sorting a file onto itself
@@topic redirection-pipes
`f` contains the lines `c`, `a` and `b`. After `sort f > f`, what does `f` contain?
(-) `a`, `b` and `c` :: The sort result is never written: the file is emptied before `sort` runs.
(-) `c`, `a`, `b`, `a`, `b` and `c` :: `>` replaces the content, it does not add to it.
(+) Nothing: the file is empty. :: The shell opens `f` for writing, truncating it, before `sort` starts, so `sort` reads an empty file.
(-) The shell refuses to run the command, because input and output are the same file. :: The shell does not check that; the data are simply lost.

@@q single | The current job
@@topic jobs-procs
You run `sleep 100 &`, which becomes job 1. Then you run `sleep 200` in the foreground and press Ctrl+Z, which makes it job 2. You type `bg` with no argument. What happens?
(-) Job 1 is resumed in the background, because it was the first job created. :: It is already running in the background.
(+) Job 2 resumes in the background: it is the current job. :: Without a job number, `bg` acts on the current job, the one that was most recently stopped.
(-) Both jobs are placed in the foreground, one after the other. :: `bg` never uses the foreground.
(-) An error message, since `bg` always needs a job number as its argument. :: The job number is optional.

@@q single | A variable set for one command only
@@topic expansion-vars
What do these lines print?
```
a=1; b=$a; a=2
a=3 echo $a ${b}0
echo $a
```
(-) `3 10` and `3` :: `$a` in the second line is expanded by the shell before `a=3` takes effect, and the prefix applies only to that command.
(-) `3 b0` and `2` :: `${b}0` is the value of `b` followed by 0; `b` was set to 1.
(+) `2 10` and `2` :: `a=3` is set only in the environment of `echo`, after `$a` has been replaced by 2; `b` kept the old value 1.
(-) `2 20` and `2` :: `b` was a copy of the old `a`, which was 1.

@@q single | Capital letters in a path
@@topic files-fs
A student types `mkdir Reports; cp data.txt reports/` and gets an error. What is wrong?
(-) `cp` cannot copy into a directory that has just been created by `mkdir`. :: A new directory can be used at once.
(+) `Reports` and `reports` differ, as Linux names are case-sensitive. :: `reports/` does not exist, so `cp` cannot copy into it.
(-) The trailing slash in `reports/` is not allowed as an argument of `cp`. :: The slash is fine when the name is a directory.
(-) `mkdir` creates directory names in lower case only, whatever is typed. :: It keeps the case that is typed.

@@q single | Two spaces
@@topic filters
What does `echo 'a  b c' | cut -d' ' -f2` print? (There are two spaces between `a` and `b`.)
(-) `b` :: Each space is a delimiter, so there is an empty field between the two spaces.
(-) `a` :: Field 1 is `a`; field 2 comes after the first space.
(+) An empty line :: The fields are `a`, an empty one, `b` and `c`; field 2 is the empty one.
(-) `b c` :: `cut` does not join fields: it selects one.

@@q single | Every two hours
@@topic logs-cron
Which `crontab` entry runs `/opt/sync.sh` once every two hours, at minute 30?
(-) `*/2 * * * * /opt/sync.sh` :: The first field is the minute: it runs every two minutes.
(-) `* */2 * * * /opt/sync.sh` :: The minute is `*`, so it runs every minute of the even hours 0, 2, 4, ... 22.
(+) `30 */2 * * * /opt/sync.sh` :: Minute 30 of every hour that is a multiple of two.
(-) `30 2 * * * /opt/sync.sh` :: It runs once a day, at 02:30.

@@q single | Builtin and program with the same name
@@topic shell-help
`/bin/echo` exists as a program and bash also has a builtin `echo`. What do `echo --version` and `/bin/echo --version` print?
(-) Both print the version of the `echo` program. :: The builtin has no `--version` option and prints it as text.
(-) Both print the text `--version`. :: The program in `/bin` accepts the option and shows its version.
(+) The first prints `--version`; the second prints the version of the `echo` program. :: Without a path, bash uses its builtin; with a path, it runs the program.
(-) The first prints the version, and the second prints the text `--version`. :: It is the other way round.

@@q single | Lines that are exactly a word
@@topic grep-regex
`w` contains `end`, `endless`, `the end`, `end of file` and `bend`. A student wants only the line that is exactly `end`. Which command does it?
(-) `grep '^end' w` :: It also matches `endless` and `end of file`, which start with `end`.
(-) `grep 'end$' w` :: It also matches `the end` and `bend`, which finish with `end`.
(-) `grep '\<end\>' w` :: Whole word, but also in `the end` and `end of file`.
(+) `grep '^end$' w` :: The line must start and finish with `end`, so nothing else can be on it.

@@q single | enable is not start
@@topic boot-systemd
`cups` is stopped and disabled. The administrator runs `systemctl enable cups` and then reboots the machine. Which statement is TRUE?
(-) `cups` is running right after `enable`. :: `enable` only registers the service for the next boots.
(-) `cups` will not run after the reboot until `systemctl start cups` is run. :: A service that is enabled is started by the boot sequence.
(+) `cups` is still stopped right after `enable`, and it is running after the reboot. :: `enable` adds it to the boot; `start` is what launches it now.
(-) `cups` is running right after `enable` and will also be after the reboot. :: Only the second part is true.
