Ten single-choice questions on the basics: one concept each, with the classic look-alike options.

@@q single | Boot sequence
@@topic boot-systemd
Which statement about the boot sequence of a PC is FALSE?
(+) The kernel starts first and is the one that initialises the firmware and loads the boot loader. :: It is the other way round: the firmware (UEFI/BIOS) runs first, then the boot loader, and the boot loader loads the kernel.
(-) The firmware initialises the hardware and finds the boot device before any boot loader code runs. :: True: the firmware is the first code to execute after power-on.
(-) The boot loader loads the kernel into memory and then hands control over to it. :: True: that is the boot loader's job (GRUB on most Linux systems).
(-) The first process started by the kernel gets PID 1 and is in charge of bringing up the services. :: True: today that process is usually systemd.

@@q single | Background job
@@topic jobs-procs
You type `sort bigfile > sorted &`. What happens?
(+) The prompt returns at once and `sort` keeps running in the background, writing into `sorted`. :: `&` only decides whether the shell waits; the `>` redirection still applies.
(-) The prompt returns only when `sort` ends, because `&` just controls where the output goes. :: `&` has nothing to do with the output: it tells the shell not to wait for the command.
(-) `sort` starts suspended and does nothing until `fg` or `bg` is typed. :: A job started with `&` runs immediately; suspended jobs are the ones stopped with `Ctrl+Z`.
(-) `&` sends the result of `sort` to the screen instead of to `sorted`. :: Output goes where `>` says: the file `sorted`.

@@q single | Counting lines
@@topic filters
`names.txt` has 3 lines. Which command prints only the number `3`, without the file name?
(+) `wc -l < names.txt` :: With the input redirected, `wc` does not know the file name, so it prints just the count.
(-) `wc -l names.txt` :: It prints the count followed by the file name: `3 names.txt`.
(-) `wc -w names.txt` :: `-w` counts words, and the file name is still printed.
(-) `wc -c names.txt` :: `-c` counts bytes, and the file name is still printed.

@@q single | Relative paths
@@topic files-fs
Your current directory is `/home/ana/docs`. Which statement is TRUE?
(+) `../notes` is the same place as `/home/ana/notes`. :: `..` is the parent directory, so `../notes` is `/home/ana/notes`.
(-) `./notes` is the same place as `/home/ana/notes`. :: `.` is the current directory: `./notes` is `/home/ana/docs/notes`.
(-) `~/notes` is the same place as `/home/ana/docs/notes`. :: `~` is the home directory, so `~/notes` is `/home/ana/notes` for ana, not a path under `docs`.
(-) `/notes` is the same place as `/home/ana/notes`. :: A path starting with `/` is absolute and starts at the root: `/notes`.

@@q single | Single and double quotes
@@topic expansion-vars
After `name=Ana`, what does `echo 'Hi $name' "Hi $name"` print?
(+) `Hi $name Hi Ana` :: Single quotes block the expansion of `$name`; double quotes allow it.
(-) `Hi Ana Hi Ana` :: Single quotes keep `$name` as literal text.
(-) `Hi $name Hi $name` :: Double quotes still expand variables.
(-) `Hi Ana Hi $name` :: The quotes are swapped in this option: single quotes are the ones that stop the expansion.

@@q single | Running a script without execute permission
@@topic scripts
`hello.sh` is in the current directory with permissions `rw-r--r--`, and `.` is not in the `PATH`. Which command runs it without changing its permissions?
(+) `bash hello.sh` :: `bash` reads the file as data, so the file only needs to be readable.
(-) `./hello.sh` :: The shell tries to execute the file itself: "Permission denied", since it has no `x`.
(-) `hello.sh` :: Without a path the shell only looks in the `PATH`, which does not include the current directory: "command not found".
(-) `/bin/hello.sh` :: That file does not exist in `/bin`: "No such file or directory".

@@q single | The superuser
@@topic users-sessions
Which statement about `root` is TRUE?
(+) It is the administrator account, identified by UID 0. :: The kernel looks at the UID, which is 0 for root.
(-) It is the first account created at installation and has no special privileges. :: It is the administrator and it does have special privileges.
(-) Any user that belongs to the group `root` is a superuser. :: Privileges follow the UID 0, not the membership of a group named `root`.
(-) Its home directory is `/home/root`. :: It is `/root`, outside `/home`.

@@q single | Hidden files
@@topic files-fs
Which command lists the current directory in long format including the hidden files?
(+) `ls -la` :: `-a` shows the entries whose names start with a dot and `-l` gives the long format.
(-) `ls -l` :: Long format, but hidden files are not shown without `-a`.
(-) `ls -lR` :: `-R` is recursive, not "all"; hidden files stay hidden.
(-) `ls -ld` :: `-d` lists the directory entry itself instead of its contents.

@@q single | Reading a mode string
@@topic permissions
`ls -l` shows `-rwxr-x--- 1 ana dev 120 Mar 3 10:00 run.sh`. Which statement is FALSE?
(+) Users who are neither ana nor members of `dev` can read the file. :: False: the last three characters (others) are `---`, so they cannot read, write or execute it.
(-) ana can read, write and execute it. :: True: the owner has `rwx`.
(-) Members of `dev` can read and execute it but not modify it. :: True: the group has `r-x`.
(-) It is a regular file. :: True: the first character is `-` (a directory would show `d`).

@@q single | Several commands on a line
@@topic shell-help
What does `echo A; echo; echo B` print?
(+) Three lines: `A`, an empty line and `B` :: `;` separates commands and `echo` with no arguments prints just a newline.
(-) Two lines: `A` and `B` :: The second `echo` is not skipped: it prints an empty line.
(-) One line: `A B` :: Each `echo` ends its output with a newline.
(-) An error, because of the empty `echo` :: `echo` without arguments is valid.
