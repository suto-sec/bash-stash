@@q single | Showing the process tree
@@topic jobs-procs
Which pair of commands shows the processes with their parent and child relations drawn as a tree?
(-) `pstree` and `ps aux` :: `ps aux` is a flat list; the tree needs the `f` option of `ps`.
(-) `ps -e` and `top` :: Both give a list, one static and the other refreshed, without the hierarchy.
(+) `pstree` and `ps axf` :: `pstree` draws the tree and the `f` option of `ps` adds the same ASCII tree.
(-) `jobs -l` and `ps -l` :: `jobs` lists the jobs of the shell, and `ps -l` only gives a long format of a flat list.

@@q single | Star in a regular expression
@@topic grep-regex
`notes` has three lines: `apple`, `banana` and `cherry`. In the shell, `ls a*` would list only the names that start with `a`. What does `grep 'a*' notes` print?
(-) Only `apple`, the line that starts with `a`. :: That is how the shell glob `a*` works; in a regular expression `*` repeats the previous character.
(-) `apple` and `banana`, the lines that contain an `a`. :: `a*` also matches zero `a`s, so lines without an `a` match too.
(+) The three lines. :: `a*` means "zero or more `a`", and zero `a`s matches in every line, so every line is selected.
(-) Nothing, because `*` needs a character before it and `a*` is not valid. :: It is valid: the star repeats the `a` before it.

@@q single | Three kinds of quotes
@@topic expansion-vars
What does `x=hello; echo "$x 'world'" '"$x"' "\"$x\""` print?
(-) `hello world "hello" "hello"` :: The single quotes inside double quotes are kept as text, and the pair in the second word is literal too.
(-) `hello 'world' $x "$x"` :: Inside single quotes nothing is expanded, so the second word keeps the double quotes and `$x`.
(+) `hello 'world' "$x" "hello"` :: Word 1: the single quotes are text inside the double ones. Word 2: single quotes keep `"$x"` literal. Word 3: `\"` is a literal quote and `$x` expands.
(-) `hello 'world' "hello" "$x"` :: The expansion happens in word 3 (double quotes) and not in word 2 (single quotes).

@@q single | Who is working and on what
@@topic users-sessions
Which command lists the users who are logged in, what each one is running right now, and the load average of the machine?
(-) `who` :: It shows user, terminal and login time, but neither the running command nor the load.
(+) `w` :: Its header has the load average and each line has a WHAT column with the command of the user.
(-) `last` :: It shows past logins and logouts, not what is running now.
(-) `id` :: It prints the identity of the current user only.

@@q single | A hard link and rm
@@topic files-fs
```
echo hi > f
ln f g
rm f
ls -l g
cat g
```
What do the last two commands show?
(-) `ls -l g` shows a link count of 2, and `cat g` prints `hi`. :: `rm f` removed a name, so the count went from 2 to 1.
(-) `ls -l g` shows a link count of 0, and `cat g` fails. :: The data stay while at least one name points to the inode.
(+) `ls -l g` shows a link count of 1, and `cat g` prints `hi`. :: The inode is the same; it lost one directory entry and keeps the other.
(-) `ls -l g` shows a link count of 1, and `cat g` fails with "No such file or directory". :: `g` is a full name for the inode, not a pointer to `f`.

@@q single | tee
@@topic redirection-pipes
Which statement about `tee` is FALSE?
(-) `echo hi | tee t1` prints `hi` on the screen and also writes it to the file `t1`. :: True: it copies stdin to stdout and to the files.
(-) `ls | tee a b` writes the listing into both `a` and `b`. :: True: `tee` accepts several files.
(-) `echo new | tee t2` replaces the old content of the file `t2`, if it already existed. :: True: without options it truncates the file.
(+) In `ls | tee l.txt | wc -l`, `wc` gets nothing, as `tee` keeps the data. :: False: `tee` passes everything to stdout too, so `wc` counts the lines and `l.txt` has the listing.

@@q single | Moving around in info
@@topic shell-help
You are reading a node of a manual with `info`. Which key takes you to its parent node, one level up?
(-) `p` :: It goes to the previous node of the same level.
(-) `l` :: It returns to the last page you read.
(+) `u` :: It moves up one level in the hierarchy of nodes.
(-) `t` :: It goes to the top page of the manual, not just one level up.

@@q single | Executable for the owner only
@@topic permissions
`deploy.sh` has mode `rw-r--r--` and a correct shebang. Which command lets only its owner run `./deploy.sh`, without touching the other bits?
(-) `chmod +x deploy.sh` :: Without a letter before `+x` the execute bit goes to the owner, the group and the others (with the usual umask 022).
(-) `chmod o+x deploy.sh` :: That gives execute to the others, not to the owner; the owner could not run it.
(+) `chmod u+x deploy.sh` :: It adds only the owner's execute bit: the mode becomes `rwxr--r--`.
(-) `chmod a-x deploy.sh` :: That removes execute for everyone; nobody had it, so nothing changes.

@@q single | Once per file
@@topic find
The directory holds `a.log`, `sub/b.log` and `c.txt`. What does `find . -name '*.log' -exec echo file: {} \;` print?
(-) `file: ./a.log ./sub/b.log` on one line :: That is what the `+` terminator does; with `\;` the command runs once for each file.
(-) `file: {}` twice :: `{}` is replaced by the name of each file found.
(+) `file: ./a.log` and `file: ./sub/b.log` on separate lines :: The command is run once per match and `{}` stands for the path.
(-) An error, because `-exec` cannot be used with `echo`. :: Any command can follow `-exec`; the error appears only if the closing `\;` is missing.

@@q single | Brackets in a test
@@topic scripts
Which statement about `if` and `[ ]` is FALSE?
(-) `if` must be closed with `fi`. :: True: that ends the structure.
(-) `elif` lets a second condition be tested without nesting another `if`. :: True: it is "else if".
(-) In `[ $x -gt 3 ]` the spaces after `[` and before `]` are required. :: True: `[` is a command and `]` its last argument.
(+) `[$x -gt 3]` works the same as `[ $x -gt 3 ]`. :: False: without the space the shell looks for a command called `[5` and fails with "command not found".
