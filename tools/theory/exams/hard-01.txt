@@exam hard-01 | Hard exam 1
@@tier hard
@@about
Ten single-choice questions with traps: quoting, ownership checks, links that dangle, exit statuses and scripts that run with missing arguments.

@@q single | Quotes and backslash together
@@topic expansion-vars
After `v=5`, what does `echo "\$v=$v" '$v=\$v' \$v=$v` print?
(-) `$v=5 $v=$v $v=5` :: Inside single quotes the backslash is not special, so `\$v` stays as typed: the second word is `$v=\$v`.
(+) `$v=5 $v=\$v $v=5` :: Word 1: the backslash escapes the first `$` inside double quotes, the second one expands. Word 2: single quotes keep everything literally, backslash included. Word 3: `\$` is a literal `$` and `$v` expands.
(-) `5=5 $v=\$v 5=5` :: The escaped `\$v` is never expanded: it prints a literal `$v`.
(-) `$v=5 $v=\$v $v=$v` :: The last word is not quoted at all, so its second `$v` is expanded to 5.

@@q single | Reading who
@@topic users-sessions
`who` prints these four lines for the same user:
```
ana  tty2   10:01
ana  :0     10:02
ana  pts/0  10:15 (:0)
ana  pts/1  10:40 (10.0.0.7)
```
Which statement is TRUE?
(-) `:0` is a text-mode virtual console, while `tty2` is the graphical session of the user. :: Swapped: `ttyN` is a text virtual console and `:0` is the graphical interface.
(-) `pts/0` and `pts/1` are text virtual consoles of the machine, reached with Ctrl+Alt+F1 to F6. :: Those are the `ttyN` ones; `pts/N` are text terminals opened inside something else.
(+) `pts/0` is a terminal window inside the graphical session `:0`; `pts/1` is a text session coming from 10.0.0.7. :: The text in parentheses says where the session came from: the display `:0`, or the remote address (for example over ssh).
(-) The four lines belong to four different machines, because each session has its own terminal name. :: They are four sessions of the same user on this machine; only the last one comes from another machine.

@@q single | Owner bits only
@@topic permissions
`tool.sh` (a correct bash script) is owned by user `ana` and group `dev`, and ana is a member of `dev`. Its mode is `---r-xr-x`. ana runs `bash tool.sh` and then `./tool.sh`. What happens?
(-) Both work, because ana is also covered by the group and "others" bits, which allow `r` and `x`. :: The shell stops at the first class that applies: ana is the owner, so only the owner bits count.
(-) `bash tool.sh` works because only `r` is needed, and `./tool.sh` fails because ana has no `x`. :: Both fail: the owner class has neither `r` nor `x`, and `bash` needs `r` to read the file.
(+) Both fail with `Permission denied`: ana is judged only by the owner bits, which are `---`. :: The class that matches the user is the only one consulted, so the more generous group and other bits do not help the owner.
(-) `bash tool.sh` fails but `./tool.sh` works, because the group bits give ana `r-x`. :: `./tool.sh` fails too: the owner bits apply to ana, not the group bits.

@@q single | Writing through a broken link
@@topic files-fs
In an empty directory:
```
echo hi > a
ln -s a b
rm a
echo new > b
```
Which statement is TRUE afterwards?
(-) `echo new > b` fails with "No such file or directory", because `b` points to a file that does not exist. :: Opening a symbolic link for writing follows it, and `>` creates the missing target.
(-) `b` is replaced by a regular file with the text `new`, and the link disappears. :: The link is kept: the redirection opens the file it points to, it does not replace the link.
(+) A new file `a` containing `new` exists, and `b` is a valid link to it again. :: The write follows the link and creates `a`; `cat b` and `cat a` both print `new`.
(-) `a` is re-created containing `hi`, since the link remembers the old content. :: A symbolic link stores only the path `a`, never the data of the file.

@@q single | Comparing byte by byte
@@topic filters
`f1` contains the lines `one` and `two`, and `f2` contains `one` and `Two` (both end with a newline). What does `cmp f1 f2` print?
(-) `f1 f2 differ: byte 4, line 2` :: The first line has 4 bytes (`one` plus the newline), so the first byte of line 2 is number 5; bytes are counted from 1.
(-) `f1 f2 differ: byte 5, line 1` :: Byte 5 is in the second line: the first line is `one` plus its newline, 4 bytes.
(-) `2c2` followed by the two lines :: That is the style of `diff`; `cmp` prints one line and stops at the first difference.
(+) `f1 f2 differ: byte 5, line 2` :: Bytes `o`,`n`,`e`,newline are 1 to 4; `t` against `T` is byte 5, on line 2.

@@q single | Who is the parent
@@topic jobs-procs
From a shell with PID 2215 you run `sleep 100 & sleep 200 & pstree -p`, and in the tree the shell appears as `sshd(2210)───bash(2215)`. Which statement is TRUE?
(-) `pstree` is the parent of both `sleep` processes, because it is the one that shows them. :: `pstree` only reads the process table; it does not create the other processes.
(+) Both `sleep` processes and `pstree` itself are children of the shell, bash(2215). :: Each command launched from the prompt, in the background or not, is a child of the shell; `pstree` shows itself as one of them.
(-) The two `sleep` processes are children of PID 1, since background processes are detached from the shell. :: A background job is still a child of the shell that started it; only an orphan is adopted by PID 1.
(-) `bash(2215)` is a direct child of PID 1, because the tree always starts at PID 1. :: The tree starts at PID 1, but here the shell hangs below `sshd(2210)`, which is its parent.

@@q single | Count 0, status 1
@@topic shell-help
`g` is a file with two lines, `x` and `y`. What do `grep -c zzz g; echo $?` print?
(-) `0` and then `0`, because the count is 0 and nothing went wrong. :: `$?` is the exit status of `grep`, not its output; `grep` exits with 1 when no line is selected.
(+) `0` and then `1` :: `-c` prints the number of matching lines (0), and the exit status is 1 because no line matched.
(-) `1` and then `1` :: The count is the number of matching lines, 0.
(-) `0` and then `2`, since 2 is the number of lines of the file. :: The exit status is not a line count: 0 means a match, 1 no match and 2 an error.

@@q single | Names and inodes
@@topic files-fs
In an empty directory you run `touch a`, `mv a b`, `cp b c`, `ln b d` and `ln -s b e`, and then `ls -i b c d e`. Which statement is TRUE?
(-) `b` and `c` show the same inode number, because `c` is a copy with the same content. :: A copy is a new file: it gets its own inode.
(-) `b` and `e` show the same inode number, because a symbolic link is another name of the same file. :: A symbolic link is a file of its own that holds a path, so it has its own inode.
(-) `b` has a new inode number because `mv` changed its name from `a`. :: Within one filesystem `mv` only changes the directory entry; the inode stays.
(+) `b` and `d` show the same inode number, while `c` and `e` each have their own. :: A hard link is another directory entry for the same inode.

@@q single | systemctl comments
@@topic boot-systemd
Which of these lines has a comment that does NOT describe what the command does?
(-) `systemctl get-default   # prints the target the system reaches at boot` :: True: it shows the default target.
(-) `systemctl isolate rescue.target   # stops the units of the current target and starts those of single-user mode` :: True: it changes the level, like the old runlevel 1.
(+) `systemctl enable cups   # starts the service now and also at every boot` :: `enable` only registers the service for the next boots; `systemctl start cups` is what starts it now.
(-) `systemctl disable cups   # removes the service from the boot, without stopping a running instance` :: True: it only changes what starts at boot.

@@q single | Script without an argument
@@topic scripts
`t.sh` contains:
```
n=$1
if [ $n -lt 0 ]; then echo neg
elif [ $n -eq 0 ]; then echo zero
else echo pos
fi
```
You run `bash t.sh` with no arguments. What happens?
(-) It prints `zero`, because an empty value counts as 0. :: `$n` is empty, so each test is `[ -eq 0 ]`: a syntax error, not a comparison with 0.
(-) It stops at the first test and prints only an error, because a failing test ends the script. :: A failed `[` just returns a non-zero status; the script goes on with the next branch.
(+) It prints two `unary operator expected` errors on stderr and then `pos` on stdout. :: Both tests are malformed, so both return non-zero and the `else` branch runs.
(-) It prints `neg`, because the first test `[ -lt 0 ]` is true for an empty value. :: The unquoted empty `$n` vanishes, leaving `[ -lt 0 ]`, which is an error and not "true".
@@note
Quoting the variable (`[ "$n" -lt 0 ]`) would still fail with "integer expression expected", so check `$#` first.
