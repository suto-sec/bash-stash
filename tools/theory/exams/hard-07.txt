@@exam hard-07 | Hard exam 7
@@tier hard
@@about
Ten single-choice questions with traps: what a child inherits and what it cannot give back, `shift` and comments, tildes in quotes, the order of redirections in a cron line and a directory that can be read but not entered.

@@q single | What a child gives back
@@topic expansion-vars
What do these lines print?
```
A=1; export B=2
bash -c 'echo $A $B; B=3; export C=4'
echo $A $B $C
```
(-) `1 2` and `1 3 4` :: A child process cannot change the variables of its parent.
(-) `2` and `1 3 4` :: Neither the new value of `B` nor the variable `C` travel back to the parent.
(+) `2` and `1 2` :: The child sees only the exported `B`; its changes are lost when it ends, and `C` never exists in the parent.
(-) `1 2` and `1 2` :: `A` was not exported, so the child does not see it.

@@q single | shift and a comment
@@topic scripts
`s.sh` contains:
```
echo $# $1
shift 2
echo $# $1 x#y # end
```
What does `bash s.sh a b c d` print?
(-) `4 a` and `2 c x#y # end` :: The text after a `#` that starts a word is a comment, so ` # end` is not printed.
(-) `4 a` and `3 b x#y` :: `shift 2` removes two arguments, not one.
(+) `4 a` and `2 c x#y` :: `shift 2` drops `a` and `b`; `x#y` is one word because the `#` does not start it, and `# end` is a comment.
(-) `4 a` and `2 c x` :: A `#` inside a word is just a character.

@@q single | A tilde in quotes
@@topic files-fs
A student types `cd "~/docs"`, with `docs` existing in the home directory, and gets `No such file or directory`. What is wrong?
(-) `cd` cannot take a path that starts with a tilde, whether it is quoted or not. :: `cd ~/docs` without quotes works.
(-) The directory `docs` must always be given as `./docs` and not by its home path. :: The problem is not the name but the quotes.
(+) Quotes stop the `~` expansion, so `cd` looks for a directory named `~`. :: Without the quotes, or with `"$HOME/docs"`, it works.
(-) Double quotes make `cd` look in `/` instead of in the current working directory. :: Quotes do not change where relative paths start.

@@q single | The order in a cron line
@@topic logs-cron
Which `crontab` line runs `/opt/cleanup.sh` every day at 05:45 and appends both what it prints and its errors to `/var/log/cleanup.out`?
(-) `45 5 * * * /opt/cleanup.sh > /var/log/cleanup.out` :: `>` replaces the log each time, and the errors are not sent to the file.
(-) `5 45 * * * /opt/cleanup.sh >> /var/log/cleanup.out 2>&1` :: The first field is the minute and the second the hour; `45` is not a valid hour.
(-) `45 5 * * * /opt/cleanup.sh 2>&1 >> /var/log/cleanup.out` :: The order matters: `2>&1` first points the errors to where stdout was, which is not the file yet.
(+) `45 5 * * * /opt/cleanup.sh >> /var/log/cleanup.out 2>&1` :: Minute 45, hour 5; the output is appended and then the errors follow it into the same file.

@@q single | The dot at the front of the PATH
@@topic shell-help
`PATH` is `.:/usr/bin:/bin`. The current directory contains an executable script called `ls` that prints `fake`. What does typing `ls` run?
(-) The real `/usr/bin/ls`, because commands are always searched in `/usr/bin` first. :: The directories are searched in the order of the `PATH`.
(+) The script in the current directory, which prints `fake`. :: The first directory of the `PATH` is the current one, so the local file wins; this is why `.` is dangerous there.
(-) An error, because two commands have the same name. :: The shell takes the first match and does not complain.
(-) The script only runs if it is written as `./ls`. :: That is needed only when `.` is not in the `PATH`.

@@q single | Zero or more vowels
@@topic grep-regex
`w` contains the lines `bt`, `bat`, `boot`, `bit5` and `bxt`. What does `grep -c '^b[aeiou]*t$' w` print?
(-) `5` :: Only lines made of `b`, vowels and a final `t` match.
(-) `4` :: That is the count without the `$`, which also lets `bit5` in.
(+) `3` :: `bt` (no vowels), `bat` and `boot` match; `bit5` has a trailing `5` and `bxt` has a non-vowel.
(-) `2` :: `bt` also matches, because `*` allows zero vowels.

@@q single | Reading and writing the same file
@@topic redirection-pipes
What does the last command print?
```
echo 1 > f
echo 2 >> f
echo 3 > g
cat f g > f
cat f
```
(-) `1`, `2` and `3` :: The shell truncates `f` before `cat` runs.
(-) `3`, `1` and `2` :: `cat` reads `f` after it has been emptied, so its old lines are gone.
(-) `1`, `2`, `3`, `1`, `2` and `3` :: `>` does not append, and the original content is lost.
(+) `3` :: `> f` empties the file first, so `cat` finds `f` empty and copies only `g`.

@@q single | Comments on shutdown lines
@@topic boot-systemd
Which of these `shutdown` lines carries a comment that is WRONG about what the command does?
(-) `shutdown -h +3   # halts the system after waiting three minutes` :: True: `-h` halts and `+3` is the delay in minutes.
(-) `shutdown -r 15:20   # reboots the machine when the clock says 15:20` :: True: a clock time is also accepted.
(-) `shutdown -c   # cancels a shutdown that was scheduled earlier on` :: True.
(+) `shutdown -h now   # sends SIGKILL to all processes, with no SIGTERM first` :: The processes first receive SIGTERM; SIGKILL goes only to those still alive after about 5 seconds.

@@q single | Line number five
@@topic filters
`n` contains the numbers 1 to 8, one per line. Which command prints only the fifth line?
(-) `tail -n 5 n | head -n 1` :: The last five lines start at 4, so this prints 4.
(-) `head -n 1 n | tail -n 5` :: The first line alone has nothing to give to `tail -n 5`; this prints 1.
(-) `tail -n+5 n` :: It prints from line 5 to the end: 5, 6, 7 and 8.
(+) `head -n 5 n | tail -n 1` :: `head` keeps lines 1 to 5 and `tail` keeps the last of them.

@@q single | A directory you can read but not enter
@@topic permissions
`dd` is a directory of `ana` with mode `r--r--r--` and contains the file `x`. `ana` runs `ls dd`, `ls -l dd` and `cd dd`. Which statement is TRUE?
(-) All three work, because ana owns the directory and can read it. :: Reading is not enough to cross it.
(-) `ls dd` fails with `Permission denied`, because without `x` nothing in the directory is accessible. :: Listing the names needs only `r`.
(+) `ls dd` shows `x`, `ls -l dd` complains that it cannot access `dd/x`, and `cd dd` fails. :: `r` allows the names; the details of each entry and entering need `x`.
(-) `ls dd` and `ls -l dd` both work, and only `cd dd` fails. :: `-l` has to read the attributes of the entries, which requires `x` on the directory.
