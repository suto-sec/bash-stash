@@q single | One tree for all the disks
@@topic files-fs
How does Linux present several disks and partitions to the user?
(+) They are all mounted on directories of one single tree that starts at `/`. :: There are no drive letters: `/home` or `/mnt/usb` may be different partitions, but they look like ordinary directories.
(-) Each disk or partition gets its own letter, such as `C:` or `D:`, with its own root. :: That is the Windows model; in Linux there is only one root, `/`.
(-) Each disk has its own tree, and `cd` switches between them. :: `cd` only moves inside the one tree.
(-) Only the first disk is visible; the others must be accessed through special device files. :: Once mounted, a partition is used through its mount point like any directory.

@@q single | Counting distinct users
@@topic filters
Each line of `log` is a user name and a number, such as `ana 1`. Which statement about `cut -d' ' -f1 log | sort -u | wc -l` is FALSE?
(-) `cut -d' ' -f1` keeps only the first field of every line, the user name. :: True: `-d' '` sets the space as separator and `-f1` selects the first field.
(-) `sort -u` sorts the names and drops the repeated ones. :: True: `-u` keeps one copy of each.
(-) The pipeline prints a single number. :: True: that is what `wc -l` prints.
(+) The number printed is the number of lines of `log`, repeated users included. :: False: duplicates are removed by `sort -u` before `wc -l` counts, so it prints the number of different users.

@@q single | Looping until
@@topic scripts
Which loop repeats its body as long as its condition is FALSE and stops when it becomes true?
(+) `until` :: `until cond; do ...; done` runs the body until the condition succeeds.
(-) `while` :: It repeats as long as the condition is true.
(-) `for` :: It repeats once for each word of a list.
(-) `case` :: It is not a loop: it chooses one branch by comparing a word with patterns.

@@q single | Permissions of a link
@@topic permissions
`link` is a symbolic link to the regular file `file`. Which command shows the permissions of the link itself, not of `file`?
(+) `ls -l link` :: It shows `lrwxrwxrwx`: the first letter `l` says it is a symbolic link, and the link's own permissions are always `rwx` for everybody.
(-) `ls -lL link` :: `-L` follows the link, so it shows the permissions of `file`, such as `-rw-r--r--`.
(-) `stat -L link` :: `-L` makes `stat` follow the link and describe the file it points to.
(-) `cat link` :: It prints the content of `file`; it shows no permissions at all.

@@q single | Dot in grep and in ls
@@topic grep-regex
The directory has the files `a.txt`, `axtxt` and `b.txt`. What does `ls | grep a.txt` print?
(+) `a.txt` and `axtxt` :: In a regular expression the dot matches any character, so `a.txt` matches `axtxt` as well.
(-) Only `a.txt` :: That would happen if the dot were an ordinary character, as it is in a shell glob.
(-) `a.txt`, `axtxt` and `b.txt` :: `b.txt` has no `a` in front of `txt`, so it does not match.
(-) Nothing, because `grep` needs the option `-E` to use a dot as a wildcard. :: The dot is part of the basic regular expressions that `grep` uses by default.

@@q single | The order of expansions
@@topic expansion-vars
In which order does bash apply these three steps to a typed command line?
(+) Alias expansion, then variable expansion, then wildcard expansion. :: Aliases are replaced first; then `$VAR` is expanded; the wildcards are expanded last, on the words that are left.
(-) Wildcard expansion, then variable expansion, then alias expansion. :: This is the reverse of the real order.
(-) Variable expansion, then alias expansion, then wildcard expansion. :: Aliases are looked at before the variables are expanded.
(-) Wildcard expansion, then alias expansion, then variable expansion. :: The wildcards are the last step of the three, not the first.

@@q single | Limiting the depth of find
@@topic find
Which command lists only the `.txt` files that are directly inside `docs`, without entering its subdirectories?
(+) `find docs -maxdepth 1 -name '*.txt'` :: `-maxdepth 1` limits the search to the directory itself and its direct entries.
(-) `find docs -mindepth 1 -name '*.txt'` :: `-mindepth 1` only skips the starting point; it still goes into every subdirectory.
(-) `find docs -maxdepth 0 -name '*.txt'` :: Depth 0 is only `docs` itself, and its name does not end in `.txt`: nothing is printed.
(-) `find docs -depth 1 -name '*.txt'` :: `-depth` takes no number; `find` complains "paths must precede expression".

@@q single | A subshell and cd
@@topic jobs-procs
You are in `/home/ana`. What does `(cd /tmp; pwd); pwd` print?
(+) `/tmp` and then `/home/ana` :: The parentheses run the commands in a subshell, so its `cd` does not change the directory of the original shell.
(-) `/tmp` twice :: That would happen with `{ cd /tmp; pwd; }; pwd`, which runs in the same shell.
(-) `/home/ana` twice :: The first `pwd` runs after the `cd`, inside the subshell, so it prints `/tmp`.
(-) `/tmp` and then an error, because `cd` cannot be used in parentheses. :: `cd` works in a subshell; its effect just ends with the subshell.

@@q single | The most frequent words
@@topic redirection-pipes
`words` has one word per line. Which statement about `sort words | uniq -c | sort -nr | head -3` is TRUE?
(+) It prints the three most frequent words, each preceded by its count. :: `uniq -c` counts equal adjacent lines (so the input is sorted first), `sort -nr` puts the biggest counts first and `head -3` keeps three lines.
(-) It prints the first three words of the file in alphabetical order. :: The counts and the second `sort` change the order and the content of the lines.
(-) It prints three different words, without counts. :: `uniq -c` adds the count at the start of every line.
(-) It fails, because `sort` cannot appear twice in the same pipeline. :: A command can be used as many times as needed.

@@q single | Who is logged in
@@topic users-sessions
Which statement about the session commands is FALSE?
(-) `whoami` prints the name of the user running the shell. :: True.
(-) `id` shows the UID, the GID and the groups of the user. :: True.
(-) `who` lists the users that are logged in at the moment. :: True: with their terminals and login times.
(+) `last` shows what each user is running right now. :: False: `last` shows the history of past logins (from `/var/log/wtmp`). The current activity of each user is shown by `w`.
