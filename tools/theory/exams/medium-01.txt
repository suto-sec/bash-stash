@@exam medium-01 | Medium exam 1
@@tier medium
@@about
Ten single-choice questions that combine two facts or ask you to trace two or three steps: modes, short pipelines, search order, argument counting and moving files.

@@q single | Reading a numeric mode
@@topic permissions
`tool.sh` belongs to user `ana` and group `dev`, and its mode was set with `chmod 645 tool.sh`. Which statement is FALSE?
(-) ana can read and modify the file, but cannot run it as `./tool.sh`. :: True: the owner digit 6 is 4+2, that is `rw-`, with no execute bit.
(-) A user who is not ana and is not in `dev` can read the file and run it as `./tool.sh`. :: True: the last digit 5 is 4+1, that is `r-x`, for everybody else.
(+) A member of `dev` (other than ana) can run it as `./tool.sh`, since "others" have execute. :: False: a user is judged by one class only; a group member falls under the group digit 4 (`r--`), so he can read the file but gets "Permission denied" when running it. The "others" digit does not add to it.
(-) A member of `dev` (other than ana) can read the file but cannot modify it. :: True: the group digit 4 is `r--`.

@@q single | Delete, then squeeze
@@topic filters
What does `echo 'a1,b22,,c333' | tr -d '0-9' | tr -s ','` print?
(-) `a,b,,c` :: That is the output of the first `tr` alone: the digits are deleted, but the double comma is still there until the second `tr` squeezes it.
(+) `a,b,c` :: The first `tr -d` deletes every digit, giving `a,b,,c`; then `tr -s ','` squeezes the repeated comma into one.
(-) `abc` :: Squeezing (`-s`) collapses repeats into one character; it does not delete the commas (that would be `-d ','`).
(-) `a1,b22,c333` :: That is what you would get from the squeeze alone; here the digits are deleted first.

@@q single | Picking fields by number
@@topic users-sessions
The line `lucia:x:1004:1004:Lucia R:/home/lucia:/bin/zsh` follows the `/etc/passwd` layout. What does `echo '<that line>' | cut -d: -f7,3` print?
(+) `1004:/bin/zsh` :: Field 3 is the UID and field 7 is the login shell; `cut` prints the selected fields in the order they appear in the line, whatever the order in the list.
(-) `/bin/zsh:1004` :: `cut` never reorders fields: `-f7,3` is the same as `-f3,7`.
(-) `x:/bin/zsh` :: That would be `-f2,7`; field 2 is the password placeholder, not the UID.
(-!) None of the above. :: The output is `1004:/bin/zsh`, which is one of the options above.

@@q single | Applying a changed GRUB setting
@@topic boot-systemd
On a Debian-based system you edited `GRUB_TIMEOUT` in `/etc/default/grub`. Which command makes GRUB use the new value at the next boot?
(-) `sudo grub-install /dev/sda` :: That writes the boot loader itself to the disk; it is not the step that regenerates the menu configuration.
(-) `sudo cp /etc/default/grub /boot/grub/grub.cfg` :: `grub.cfg` is generated, not copied: `/etc/default/grub` is only the input of the generator and has a different format.
(-) `sudo update-initramfs -u` :: That rebuilds the initial RAM disk used by the kernel; it does not touch the GRUB configuration.
(+) `sudo update-grub` :: It regenerates `/boot/grub/grub.cfg` from `/etc/default/grub` and the scripts in `/etc/grub.d/`.

@@q single | Every match along the PATH
@@topic expansion-vars
Two directories, `/opt/a` and `/opt/b`, each contain an executable called `run`, and `PATH=/opt/b:/opt/a:/usr/bin:/bin`. Which command prints the full path of both of them, in the order the shell would find them?
(-) `which run` :: It stops at the first match and prints only `/opt/b/run`.
(+) `which -a run` :: `-a` lists all the matches along the `PATH`, here `/opt/b/run` and then `/opt/a/run`.
(-) `echo $PATH | grep run` :: It only prints the `PATH` line if the text `run` appears in it, which it does not; it never looks inside the directories.
(-) `ls $PATH/run` :: `$PATH` expands to the whole colon-separated string, so `ls` looks for one file with a very odd name and fails with "No such file or directory".

@@q single | Searching the manual pages
@@topic shell-help
Which statement about looking up manual pages is FALSE?
(-) `whatis cp` prints the one-line description of each manual page named `cp`. :: True: it is a lookup by name.
(-) `apropos copy` can list `cp` even though `copy` is not its name. :: True: it searches the descriptions as well, and `cp` is described as "copy files and directories".
(+) `whatis copy` also lists `cp`, because its description contains the word `copy`. :: False: `whatis` matches names only, and no page is called `copy`, so it answers `copy: nothing appropriate.`; the keyword search is `apropos copy` or `man -k copy`.
(-) `man -k copy` performs the same search as `apropos copy`. :: True: `-k` turns `man` into a keyword search.

@@q single | What a PID tells you
@@topic jobs-procs
Which statement about process identifiers is TRUE?
(+) PIDs are handed out sequentially up to a maximum and then numbering starts again; PID 1 is the initial process that starts the services. :: The number grows with each new process; the classic limit is 32767. PID 1 (nowadays usually systemd) is launched by the kernel at the end of its start-up.
(-) A child process always gets the PID of its parent plus one, so `sleep 9 &` started from a shell with PID 500 is always PID 501. :: Other processes may be created in between, and PIDs are not tied to the parent's number.
(-) A PID belongs to a program, not to a running instance: `ls` always gets the same PID every time it runs. :: Every execution is a new process with a new PID.
(-) PID 1 is the login shell of the first user, created when that user authenticates. :: PID 1 exists from boot, before any user logs in; a login shell has an ordinary PID.

@@q single | Counting the arguments
@@topic scripts
A script `t.sh` contains this function and these three calls:

```
count() { echo $#; }
count "$*"; count "$@"; count $*
```

You run `./t.sh "a b" c`. What does it print, one number per line?
(-) `2`, `2`, `3` :: `"$*"` is a single word joining all the arguments, so the first call receives 1 argument, not 2.
(-) `1`, `3`, `3` :: `"$@"` keeps the original boundaries: `a b` and `c` are 2 arguments.
(-) `1`, `2`, `2` :: Unquoted `$*` is split on blanks into `a`, `b` and `c`: 3 arguments.
(+) `1`, `2`, `3` :: `"$*"` is one word (`a b c`), `"$@"` keeps the two original arguments, and unquoted `$*` splits into three words.

@@q single | Moving into a directory
@@topic files-fs
`docs` and `archive` are existing directories, and `notes` is a file, all in the current directory. You run:

```
mv notes docs/todo
mv docs archive
```

Where is the file now?
(+) `archive/docs/todo` :: The first `mv` moves and renames the file in one step; the second one moves the directory `docs` into the existing directory `archive`.
(-) `archive/todo` :: `mv` does not merge: since `archive` is an existing directory, `docs` goes inside it as a whole.
(-) `archive/docs/notes` :: The first command already renamed the file while moving it into `docs`: its name is `todo`.
(-) `docs/todo` :: The second command moved `docs` away: it no longer exists in the current directory.

@@q single | Removing something that is not there
@@topic files-fs
There is no file or directory called `ghost` in the current directory. Which statement is TRUE?
(-) `rm -r ghost` and `rm -rf ghost` both print the same error, because `-f` only skips the confirmation questions. :: `-f` also ignores nonexistent files, so `rm -rf` stays silent.
(-) `rm -ri ghost` asks "remove directory 'ghost'?" and then reports that it does not exist. :: There is nothing to ask about: it reports the error straight away, as `rm -r` does.
(-) `rm -r ghost` prints nothing and succeeds, because `-r` makes `rm` skip names that do not exist. :: `-r` is about directories; a missing name is an error: "No such file or directory".
(+) `rm -r ghost` prints "No such file or directory" and exits with status 1, while `rm -rf ghost` prints nothing and exits with status 0. :: `-f` ignores nonexistent files and never prompts, which is why scripts use it.
@@note
`-f` does not make `rm` able to remove a directory without `-r`: `rm -f dir` still says "Is a directory". Use it with care: `-f` also hides mistakes.
