@@exam hard-07 | Examen difícil 7
@@about
Diez preguntas de respuesta única con trampas: lo que hereda un hijo y lo que no puede devolver, `shift` y comentarios, tildes entre comillas, el orden de las redirecciones en una línea de cron y un directorio que se puede leer pero no atravesar.

@@q single | Lo que un hijo no devuelve
¿Qué imprimen estas líneas?
```
A=1; export B=2
bash -c 'echo $A $B; B=3; export C=4'
echo $A $B $C
```
(-) `1 2` y `1 3 4` :: Un proceso hijo no puede cambiar las variables de su padre.
(-) `2` y `1 3 4` :: Ni el nuevo valor de `B` ni la variable `C` viajan de vuelta al padre.
(+) `2` y `1 2` :: El hijo ve solo la `B` exportada; sus cambios se pierden al terminar, y `C` nunca existe en el padre.
(-) `1 2` y `1 2` :: `A` no se exportó, así que el hijo no la ve.

@@q single | shift y un comentario
`s.sh` contiene:
```
echo $# $1
shift 2
echo $# $1 x#y # end
```
¿Qué imprime `bash s.sh a b c d`?
(-) `4 a` y `2 c x#y # end` :: El texto tras un `#` que empieza una palabra es un comentario, así que ` # end` no se imprime.
(-) `4 a` y `3 b x#y` :: `shift 2` quita dos argumentos, no uno.
(+) `4 a` y `2 c x#y` :: `shift 2` descarta `a` y `b`; `x#y` es una palabra porque el `#` no la empieza, y `# end` es un comentario.
(-) `4 a` y `2 c x` :: Un `#` dentro de una palabra es solo un carácter.

@@q single | Una tilde entre comillas
Un estudiante escribe `cd "~/docs"`, con `docs` existiendo en el directorio home, y obtiene `No such file or directory`. ¿Qué está mal?
(-) `cd` no puede recibir una ruta que empiece por tilde, vaya entrecomillada o no. :: `cd ~/docs` sin comillas funciona.
(-) El directorio `docs` debe darse siempre como `./docs` y no por su ruta del home. :: El problema no es el nombre sino las comillas.
(+) Las comillas impiden la expansión de `~`, así que `cd` busca un directorio llamado `~`. :: Sin las comillas, o con `"$HOME/docs"`, funciona.
(-) Las comillas dobles hacen que `cd` busque en `/` en lugar de en el directorio de trabajo actual. :: Las comillas no cambian desde dónde empiezan las rutas relativas.

@@q single | El orden en una línea de cron
¿Qué línea de `crontab` ejecuta `/opt/cleanup.sh` cada día a las 05:45 y añade tanto lo que imprime como sus errores a `/var/log/cleanup.out`?
(-) `45 5 * * * /opt/cleanup.sh > /var/log/cleanup.out` :: `>` reemplaza el log cada vez, y los errores no se envían al fichero.
(-) `5 45 * * * /opt/cleanup.sh >> /var/log/cleanup.out 2>&1` :: El primer campo es el minuto y el segundo la hora; `45` no es una hora válida.
(-) `45 5 * * * /opt/cleanup.sh 2>&1 >> /var/log/cleanup.out` :: El orden importa: `2>&1` primero apunta los errores a donde estaba stdout, que todavía no es el fichero.
(+) `45 5 * * * /opt/cleanup.sh >> /var/log/cleanup.out 2>&1` :: Minuto 45, hora 5; la salida se añade y luego los errores la siguen al mismo fichero.

@@q single | El punto al principio del PATH
`PATH` vale `.:/usr/bin:/bin`. El directorio actual contiene un script ejecutable llamado `ls` que imprime `fake`. ¿Qué ejecuta escribir `ls`?
(-) El `/usr/bin/ls` real, porque los mandatos siempre se buscan primero en `/usr/bin`. :: Los directorios se recorren en el orden del `PATH`.
(+) El script del directorio actual, que imprime `fake`. :: El primer directorio del `PATH` es el actual, así que gana el fichero local; por eso `.` es peligroso ahí.
(-) Un error, porque dos mandatos tienen el mismo nombre. :: La shell toma la primera coincidencia y no se queja.
(-) El script solo se ejecuta si se escribe como `./ls`. :: Eso hace falta solo cuando `.` no está en el `PATH`.

@@q single | Cero o más vocales
`w` contiene las líneas `bt`, `bat`, `boot`, `bit5` y `bxt`. ¿Qué imprime `grep -c '^b[aeiou]*t$' w`?
(-) `5` :: Solo coinciden las líneas formadas por `b`, vocales y una `t` final.
(-) `4` :: Esa es la cuenta sin el `$`, que deja entrar también a `bit5`.
(+) `3` :: `bt` (sin vocales), `bat` y `boot` coinciden; `bit5` tiene un `5` al final y `bxt` tiene una no vocal.
(-) `2` :: `bt` también coincide, porque `*` permite cero vocales.

@@q single | Leer y escribir el mismo fichero
¿Qué imprime el último mandato?
```
echo 1 > f
echo 2 >> f
echo 3 > g
cat f g > f
cat f
```
(-) `1`, `2` y `3` :: La shell trunca `f` antes de que `cat` se ejecute.
(-) `3`, `1` y `2` :: `cat` lee `f` después de que se haya vaciado, así que sus líneas antiguas han desaparecido.
(-) `1`, `2`, `3`, `1`, `2` y `3` :: `>` no añade, y el contenido original se pierde.
(+) `3` :: `> f` vacía el fichero primero, así que `cat` encuentra `f` vacío y copia solo `g`.

@@q single | Comentarios en líneas de shutdown
¿Cuál de estas líneas de `shutdown` lleva un comentario que es INCORRECTO sobre lo que hace el mandato?
(-) `shutdown -h +3   # halts the system after waiting three minutes` :: Verdadero: `-h` detiene y `+3` es el retardo en minutos.
(-) `shutdown -r 15:20   # reboots the machine when the clock says 15:20` :: Verdadero: también se acepta una hora del reloj.
(-) `shutdown -c   # cancels a shutdown that was scheduled earlier on` :: Verdadero.
(+) `shutdown -h now   # sends SIGKILL to all processes, with no SIGTERM first` :: Los procesos reciben primero SIGTERM; SIGKILL va solo a los que siguen vivos tras unos 5 segundos.

@@q single | La línea cinco
`n` contiene los números del 1 al 8, uno por línea. ¿Qué mandato imprime solo la quinta línea?
(-) `tail -n 5 n | head -n 1` :: Las cinco últimas líneas empiezan en 4, así que imprime 4.
(-) `head -n 1 n | tail -n 5` :: La primera línea sola no da nada a `tail -n 5`; imprime 1.
(-) `tail -n+5 n` :: Imprime desde la línea 5 hasta el final: 5, 6, 7 y 8.
(+) `head -n 5 n | tail -n 1` :: `head` conserva las líneas 1 a 5 y `tail` se queda con la última de ellas.

@@q single | Un directorio que se puede leer pero no atravesar
`dd` es un directorio de `ana` con modo `r--r--r--` y contiene el fichero `x`. `ana` ejecuta `ls dd`, `ls -l dd` y `cd dd`. ¿Qué afirmación es VERDADERA?
(-) Los tres funcionan, porque ana es la dueña del directorio y puede leerlo. :: Leer no basta para atravesarlo.
(-) `ls dd` falla con `Permission denied`, porque sin `x` nada del directorio es accesible. :: Listar los nombres solo necesita `r`.
(+) `ls dd` muestra `x`, `ls -l dd` se queja de que no puede acceder a `dd/x`, y `cd dd` falla. :: `r` permite los nombres; los detalles de cada entrada y entrar necesitan `x`.
(-) `ls dd` y `ls -l dd` funcionan los dos, y solo falla `cd dd`. :: `-l` tiene que leer los atributos de las entradas, lo que requiere `x` en el directorio.
