@@exam easy-06 | Examen fácil 6
@@about
Diez preguntas de respuesta única sobre lo básico: un concepto en cada una, con las típicas opciones parecidas.

@@q single | Sustituir caracteres
¿Qué imprime `echo a-b-c | tr - _`?
(-) `abc` :: Ese sería el resultado de borrar los guiones con `tr -d -`.
(-) `a_b-c` :: `tr` sustituye todas las apariciones, no solo la primera.
(+) `a_b_c` :: `tr` sustituye cada carácter del primer conjunto por el que ocupa la misma posición en el segundo.
(-) `a-b-c` :: El texto cambia: los guiones pasan a ser guiones bajos.

@@q single | Instalar el gestor de arranque
¿Qué mandato instala GRUB en el primer disco de la máquina?
(-) `update-grub /dev/sda` :: `update-grub` regenera el fichero de menú `grub.cfg`; no instala el gestor en un disco.
(+) `grub-install /dev/sda` :: Escribe el gestor de arranque en el disco; se hace una vez, no en cada arranque.
(-) `systemctl start grub` :: GRUB no es un servicio: se ejecuta antes que el kernel, así que `systemd` todavía no existe.
(-) `cp /boot/grub/grub.cfg /dev/sda` :: `grub.cfg` es la configuración que lee el gestor, no el gestor en sí.

@@q single | PID 1
¿Qué proceso tiene el PID 1 en un sistema Linux?
(-) El proceso inactivo del kernel, que se ejecuta cuando nada más puede hacerlo. :: El proceso inactivo tiene el PID 0.
(-) El gestor de arranque, ya que es el primer programa que se ejecuta cuando se enciende la máquina. :: El gestor de arranque termina su trabajo antes de que arranque el kernel: no es un proceso del sistema en marcha.
(+) El primer proceso del sistema en marcha, lanzado por el kernel (normalmente systemd). :: Es el primer proceso del sistema en funcionamiento y el antecesor de todos los demás.
(-) La shell de login del primer usuario que se conecta a la máquina. :: Una shell de login es un proceso corriente que recibe el siguiente PID disponible.

@@q single | Crear un enlace duro
`orig.txt` existe y `copy.txt` no. ¿Qué mandato hace de `copy.txt` un enlace duro a `orig.txt`?
(-) `ln -s orig.txt copy.txt` :: Con `-s` es un enlace simbólico, no un enlace duro.
(-) `ln copy.txt orig.txt` :: El fichero existente va primero: este busca un fichero llamado `copy.txt` y falla.
(-) `cp orig.txt copy.txt` :: Crea un segundo fichero independiente con su propio i-nodo.
(+) `ln orig.txt copy.txt` :: Sin opciones `ln` hace un enlace duro: el nombre nuevo es otra entrada para el mismo i-nodo.

@@q single | El orden de las redirecciones
¿Qué afirmación sobre `ls /nope /etc/hostname > out 2>&1` es VERDADERA?
(-) El mensaje de error aparece en pantalla y el listado va a `out`. :: Eso es lo que hace `2>&1 > out`, porque el orden de las redirecciones importa.
(-) Tanto el mensaje de error como el listado aparecen en pantalla, y `out` queda vacío. :: Ambas salidas se redirigen al fichero.
(+) No aparece nada en pantalla: el mensaje de error y el listado van a `out`. :: `> out` apunta stdout al fichero y después `2>&1` hace que stderr vaya adonde va ahora stdout.
(-) El mensaje de error va a un fichero llamado `1`. :: Con `&` antes del número, `2>&1` duplica un descriptor y no nombra un fichero.

@@q single | El log de autenticación
¿Qué muestra `grep sudo /var/log/auth.log | tail -n 5`?
(-) Los cinco usuarios que más han usado `sudo`. :: No se cuenta nada por usuario; las líneas se muestran tal cual.
(-) Las cinco últimas líneas de `auth.log`, mencionen o no `sudo`. :: `grep` se ejecuta primero, así que `tail` solo ve las líneas que contienen `sudo`.
(+) Las cinco líneas más recientes de `auth.log` que mencionan `sudo`. :: `auth.log` registra los mandatos ejecutados con `sudo`; `grep` conserva esas líneas y `tail` las cinco últimas.
(-) Las cinco líneas más antiguas de `auth.log` que mencionan `sudo`. :: `tail` toma líneas del final de su entrada, no del principio.

@@q single | Buscar en el manual
¿Qué mandato hace la misma búsqueda que `apropos network`?
(-) `whatis network` :: `whatis` busca solo el nombre de la página.
(-) `man network` :: Abre la página llamada `network`, si existe; no busca en las descripciones.
(+) `man -k network` :: `-k` hace que `man` busque la palabra clave en las descripciones de todas las páginas.
(-) `info network` :: Abre la página info de una herramienta llamada `network`; no es una búsqueda por palabra clave.

@@q single | Las variables son cadenas
¿Qué afirmación es FALSA?
(-) `echo $((7*3))` imprime `21`, el producto de los números. :: Verdadero: `$(( ))` evalúa la aritmética.
(-) `expr 5 + 3` imprime `8`, con espacios alrededor del más. :: Verdadero: los espacios alrededor de `+` son necesarios.
(+) Tras `n=4` y `n=$n+1`, `echo $n` imprime `5`. :: Falso: las variables son cadenas, así que `n` pasa a ser el texto `4+1`.
(-) `echo "2*8" | bc` imprime `16`, tal como lo calcula `bc`. :: Verdadero: `bc` es una calculadora que lee expresiones de stdin.

@@q single | Anclas en un patrón
`w` contiene las líneas `cat`, `cart`, `scatter`, `cut` y `cat5`. ¿Qué afirmación sobre `grep '^c.t$' w` es VERDADERA?
(-) Imprime `cat`, `cart` y `cut`. :: `.` coincide con exactamente un carácter, y `cart` tiene dos letras entre `c` y `t`.
(-) Imprime `cat`, `scatter`, `cut` y `cat5`. :: `^` y `$` obligan a que la línea empiece por `c` y acabe en `t`.
(+) Imprime `cat` y `cut`. :: La línea completa debe ser `c`, un carácter y `t`.
(-) No imprime nada, porque `^` y `$` no se pueden usar juntos. :: Sí se puede: juntos obligan a que el patrón cubra toda la línea.

@@q single | Estado de salida
¿Qué afirmación sobre `$?` es FALSA?
(-) Cuando un mandato termina, `$?` contiene su estado de salida. :: Verdadero.
(-) Un valor de 0 significa que el último mandato terminó correctamente. :: Verdadero: cualquier otro valor indica un error.
(+) `$?` es el PID de la shell que ejecuta el script. :: Falso: eso es `$$`; `$?` es solo el estado de salida del último mandato.
(-) Tras `ls /nope`, `echo $?` imprime un valor distinto de 0. :: Verdadero: `ls` falla porque `/nope` no existe.
