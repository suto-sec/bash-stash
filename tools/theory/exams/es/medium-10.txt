@@exam medium-10 | Examen medio 10
@@about
Diez preguntas de respuesta única que combinan dos datos o piden seguir unos pasos: campos y caracteres con cut, type y whereis, flujos estándar, rutas absolutas y relativas, permisos de grupo, suspender un trabajo, el entorno de root, asignaciones, xargs con espacios y exit dentro de funciones.

@@q single | Campos y caracteres
La línea es `root:x:0`. ¿Qué imprimen `cut -d: -f2` y `cut -c2` para ella, en ese orden?
(+) `x` y `o` :: `-f2` toma el segundo campo usando `:` como separador; `-c2` toma el segundo carácter de la línea.
(-) `x` y `x` :: El segundo carácter de `root:x:0` es `o`; la `x` es el sexto.
(-) `o` y `x` :: Las opciones están intercambiadas: `-f` selecciona campos y `-c` selecciona caracteres.
(-) `root:x` y `ro` :: `-f2` y `-c2` seleccionan un solo campo y un solo carácter, no un rango.

@@q single | Encontrar mandatos
¿Qué afirmación sobre `type`, `which` y `whereis` es FALSA?
(-) `type cd` informa de que `cd` es un mandato interno de la shell. :: Cierto: imprime `cd is a shell builtin`.
(-) `which ls` imprime la ruta del programa que se ejecutaría al escribir `ls`. :: Cierto: por ejemplo `/usr/bin/ls`.
(-) `type` también informa de alias y funciones, que los otros no conocen. :: Cierto: pregunta a la propia shell cómo interpretaría la palabra.
(+) `whereis ls` solo busca en el `PATH` e imprime únicamente el ejecutable. :: Falso: `whereis` también busca las páginas de manual y los fuentes, y los imprime junto con el binario.

@@q single | Qué captura >
¿Qué afirmación sobre `ls /nonexistent /etc/hostname > out.txt` es FALSA?
(-) `/etc/hostname` se escribe en `out.txt`. :: Cierto: la salida estándar va al fichero.
(-) El mensaje de error sobre `/nonexistent` aparece en la pantalla. :: Cierto: `>` redirige solo el flujo 1.
(-) `out.txt` se crea aunque el mandato no imprima nada por stdout. :: Cierto: la shell crea (o trunca) el fichero antes de ejecutar el mandato.
(+) El mensaje de error sobre `/nonexistent` también se escribe en `out.txt`. :: Falso: la salida de error es otro flujo; haría falta `2>&1` o `2> fichero`.

@@q single | cd con una barra inicial
Estás en `/home/ana` y existen tanto `/home/ana/docs` como `/docs`. Compara `cd docs` y `cd /docs`.
(+) `cd docs` va a `/home/ana/docs`; `cd /docs` va a `/docs`. :: Una ruta sin `/` inicial parte del directorio actual; una con ella parte de la raíz.
(-) Los dos van a `/home/ana/docs`, porque `cd` siempre empieza en el directorio personal. :: Solo `cd` sin argumento va al directorio personal.
(-) `cd docs` va a `/docs` y `cd /docs` va a `/home/ana/docs`. :: Es al revés.
(-) Los dos van a `/docs`, porque la barra inicial es opcional. :: Sin la barra la ruta es relativa al directorio actual.

@@q single | Lo que puede hacer el grupo
`prog` pertenece al usuario `ana` y al grupo `devs`, con modo `-rwxr-x---`. `bob` es miembro de `devs`. ¿Qué puede hacer `bob` con `prog`?
(+) Leerlo y ejecutarlo, pero no modificarlo. :: `bob` no es el propietario, así que se le aplican los bits del grupo `r-x`.
(-) Leerlo, modificarlo y ejecutarlo, porque pertenece al grupo. :: El grupo no tiene permiso de escritura: sus bits son `r-x`.
(-) Nada, porque solo el propietario puede usar el fichero. :: Los bits del grupo dan permiso de lectura y ejecución a los miembros de `devs`.
(-) Solo ejecutarlo, porque leer es un permiso del propietario. :: El grupo también tiene `r`.

@@q single | Pausar un trabajo largo
Un `sort` largo se está ejecutando en primer plano. Necesitas el prompt un momento, pero no debes perder el trabajo del `sort`. ¿Qué secuencia lo consigue?
(+) `Ctrl+Z`, escribir tus mandatos y después `fg` :: `Ctrl+Z` suspende el trabajo sin terminarlo, y `fg` lo recupera.
(-) `Ctrl+C`, escribir tus mandatos y después `fg` :: `Ctrl+C` termina el `sort`, así que no queda nada que recuperar.
(-) `Ctrl+D`, escribir tus mandatos y después `fg` :: `Ctrl+D` envía fin de fichero a la entrada; no devuelve el prompt.
(-) `Ctrl+Z` y después `kill %1` para liberar el terminal. :: `kill %1` termina el trabajo y se pierde su trabajo.

@@q single | El entorno de root
Con la sesión de `root` iniciada normalmente, ejecutas `whoami; id -u; echo $HOME`. ¿Qué se imprime?
(+) `root`, `0` y `/root` :: root es la cuenta de administrador: UID 0, y su directorio personal es `/root`, fuera de `/home`.
(-) `root`, `0` y `/home/root` :: El directorio personal de root no está bajo `/home`.
(-) `root`, `1` y `/root` :: El UID 1 pertenece a `daemon`; root tiene UID 0.
(-) `admin`, `0` y `/root` :: La cuenta se llama `root`, no `admin`.

@@q single | Asignar una variable
¿Qué mandato hace que `echo "${file}_old"` imprima `report.txt_old`?
(+) `file=report.txt` :: Una asignación no lleva espacios alrededor de `=`, y `${file}` va seguido del texto `_old`.
(-) `file = report.txt` :: Con espacios es el mandato `file` con dos argumentos (`=` y `report.txt`).
(-) `$file=report.txt` :: Un `$` a la izquierda expande la variable: la shell intenta ejecutar un mandato llamado `=report.txt`.
(-) `file report.txt` :: Ejecuta el mandato `file`, que describe el tipo de `report.txt`; no se asigna ninguna variable.

@@q single | xargs y nombres con espacios
Existen `my notes.txt` (dos líneas) y `c.txt` (vacío). ¿Qué hace `find . -name '*.txt' | xargs wc -l`?
(+) Da errores para `./my` y `notes.txt`, porque `xargs` parte el nombre en el espacio. :: Por defecto `xargs` divide su entrada por espacios en blanco; `-print0` con `xargs -0` evita el problema.
(-) Imprime correctamente el número de líneas de los dos ficheros. :: El nombre con espacio se parte en dos palabras.
(-) Imprime solo la cuenta de los ficheros sin espacios y salta el otro en silencio. :: `wc` recibe las dos mitades y protesta por cada una.
(-) Falla antes de ejecutar nada, porque `find` no puede imprimir nombres con espacios. :: `find` los imprime con normalidad; el problema aparece en `xargs`.

@@q single | exit dentro de una función
Un script ejecuta `f() { exit 3; }`, después `f` y después `echo after`. ¿Qué ocurre?
(+) El script termina con estado 3 al llamar a `f`, y `after` no se imprime nunca. :: `exit` termina la shell que lo ejecuta, incluso dentro de una función; `return` es lo que sale solo de la función.
(-) Se imprime `after` y el estado del script es 3. :: `echo` nunca se alcanza.
(-) Se imprime `after` y el estado del script es 0. :: El script ya ha terminado.
(-) El script imprime un error, porque `exit` no se puede usar dentro de una función. :: Se puede usar; simplemente termina todo el script.
