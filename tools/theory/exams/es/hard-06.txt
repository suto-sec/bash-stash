@@exam hard-06 | Examen difícil 6
@@about
Diez preguntas de respuesta única con trampas: funciones que cambian variables globales, un fichero truncado antes de leerlo, variables definidas solo para un mandato, dobles espacios y la diferencia entre un mandato interno y su programa gemelo.

@@q single | return y exit en funciones
`s.sh` contiene:
```
x=1
f() { x=2; return 5; echo never; }
f
echo "$? $x"
g() { exit 7; }
g
echo after
```
Ejecutas `bash s.sh; echo $?`. ¿Qué se imprime?
(-) `5 1`, `after` y `0` :: Una función puede cambiar las variables del script, y `exit 7` termina todo el script, no solo la función.
(-) `5 2`, `after` y `7` :: `exit` dentro de una función termina el script, así que `after` nunca aparece.
(+) `5 2` y `7` :: `return 5` sale de `f` con estado 5, y `x` es una variable global que `f` cambió; `exit 7` en `g` termina el script con 7.
(-) `0 2` y `7` :: Después de `f`, `$?` contiene el estado dado a `return`, 5.

@@q single | Ordenar un fichero sobre sí mismo
`f` contiene las líneas `c`, `a` y `b`. Tras `sort f > f`, ¿qué contiene `f`?
(-) `a`, `b` y `c` :: El resultado de `sort` nunca se escribe: el fichero se vacía antes de que `sort` se ejecute.
(-) `c`, `a`, `b`, `a`, `b` y `c` :: `>` reemplaza el contenido, no añade.
(+) Nada: el fichero está vacío. :: La shell abre `f` para escribir, truncándolo, antes de que arranque `sort`, así que `sort` lee un fichero vacío.
(-) La shell se niega a ejecutar el mandato, porque entrada y salida son el mismo fichero. :: La shell no comprueba eso; los datos simplemente se pierden.

@@q single | El trabajo actual
Ejecutas `sleep 100 &`, que pasa a ser el trabajo 1. Después ejecutas `sleep 200` en primer plano y pulsas Ctrl+Z, lo que lo convierte en el trabajo 2. Escribes `bg` sin argumento. ¿Qué ocurre?
(-) Se reanuda el trabajo 1 en segundo plano, porque fue el primer trabajo creado. :: Ya se está ejecutando en segundo plano.
(+) El trabajo 2 se reanuda en segundo plano: es el trabajo actual. :: Sin número de trabajo, `bg` actúa sobre el trabajo actual, el que se detuvo más recientemente.
(-) Los dos trabajos pasan a primer plano, uno tras otro. :: `bg` nunca usa el primer plano.
(-) Un mensaje de error, ya que `bg` siempre necesita un número de trabajo como argumento. :: El número de trabajo es opcional.

@@q single | Una variable definida solo para un mandato
¿Qué imprimen estas líneas?
```
a=1; b=$a; a=2
a=3 echo $a ${b}0
echo $a
```
(-) `3 10` y `3` :: `$a` de la segunda línea lo expande la shell antes de que `a=3` surta efecto, y el prefijo solo se aplica a ese mandato.
(-) `3 b0` y `2` :: `${b}0` es el valor de `b` seguido de 0; `b` valía 1.
(+) `2 10` y `2` :: `a=3` se define solo en el entorno de `echo`, después de que `$a` se haya sustituido por 2; `b` conservó el valor antiguo 1.
(-) `2 20` y `2` :: `b` era una copia del antiguo `a`, que valía 1.

@@q single | Mayúsculas en una ruta
Un estudiante escribe `mkdir Reports; cp data.txt reports/` y obtiene un error. ¿Qué está mal?
(-) `cp` no puede copiar en un directorio que acaba de crear `mkdir`. :: Un directorio nuevo se puede usar enseguida.
(+) `Reports` y `reports` difieren, pues los nombres en Linux distinguen mayúsculas. :: `reports/` no existe, así que `cp` no puede copiar en él.
(-) La barra final de `reports/` no se permite como argumento de `cp`. :: La barra es válida cuando el nombre es un directorio.
(-) `mkdir` crea nombres de directorio solo en minúsculas, se escriba lo que se escriba. :: Conserva las mayúsculas que se escriben.

@@q single | Dos espacios
¿Qué imprime `echo 'a  b c' | cut -d' ' -f2`? (Hay dos espacios entre `a` y `b`.)
(-) `b` :: Cada espacio es un delimitador, así que hay un campo vacío entre los dos espacios.
(-) `a` :: El campo 1 es `a`; el campo 2 viene después del primer espacio.
(+) Una línea vacía :: Los campos son `a`, uno vacío, `b` y `c`; el campo 2 es el vacío.
(-) `b c` :: `cut` no une campos: selecciona uno.

@@q single | Cada dos horas
¿Qué entrada de `crontab` ejecuta `/opt/sync.sh` una vez cada dos horas, en el minuto 30?
(-) `*/2 * * * * /opt/sync.sh` :: El primer campo es el minuto: se ejecuta cada dos minutos.
(-) `* */2 * * * /opt/sync.sh` :: El minuto es `*`, así que se ejecuta cada minuto de las horas pares 0, 2, 4, ... 22.
(+) `30 */2 * * * /opt/sync.sh` :: Minuto 30 de cada hora que sea múltiplo de dos.
(-) `30 2 * * * /opt/sync.sh` :: Se ejecuta una vez al día, a las 02:30.

@@q single | Mandato interno y programa con el mismo nombre
`/bin/echo` existe como programa y bash también tiene un `echo` interno. ¿Qué imprimen `echo --version` y `/bin/echo --version`?
(-) Ambos imprimen la versión del programa `echo`. :: El mandato interno no tiene opción `--version` y la imprime como texto.
(-) Ambos imprimen el texto `--version`. :: El programa de `/bin` acepta la opción y muestra su versión.
(+) El primero imprime `--version`; el segundo imprime la versión del programa `echo`. :: Sin ruta, bash usa su mandato interno; con ruta, ejecuta el programa.
(-) El primero imprime la versión, y el segundo imprime el texto `--version`. :: Es al revés.

@@q single | Líneas que son exactamente una palabra
`w` contiene `end`, `endless`, `the end`, `end of file` y `bend`. Un estudiante quiere solo la línea que es exactamente `end`. ¿Qué mandato lo consigue?
(-) `grep '^end' w` :: También coincide con `endless` y `end of file`, que empiezan por `end`.
(-) `grep 'end$' w` :: También coincide con `the end` y `bend`, que acaban en `end`.
(-) `grep '\<end\>' w` :: Palabra completa, pero también en `the end` y `end of file`.
(+) `grep '^end$' w` :: La línea debe empezar y acabar con `end`, así que no puede haber nada más en ella.

@@q single | enable no es start
`cups` está parado y deshabilitado. El administrador ejecuta `systemctl enable cups` y después reinicia la máquina. ¿Qué afirmación es VERDADERA?
(-) `cups` se está ejecutando justo después de `enable`. :: `enable` solo lo registra para los próximos arranques.
(-) `cups` no se ejecutará tras el reinicio hasta que se ejecute `systemctl start cups`. :: Un servicio habilitado lo arranca la secuencia de arranque.
(+) `cups` sigue parado justo después de `enable`, y se está ejecutando tras el reinicio. :: `enable` lo añade al arranque; `start` es lo que lo lanza ahora.
(-) `cups` se está ejecutando justo después de `enable` y también lo estará tras el reinicio. :: Solo la segunda parte es cierta.
