@@exam medium-01 | Examen medio 1
@@about
Diez preguntas de respuesta única que combinan dos datos o piden seguir dos o tres pasos: modos, tuberías cortas, orden de búsqueda, recuento de argumentos y mover ficheros.

@@q single | Leer un modo numérico
`tool.sh` pertenece al usuario `ana` y al grupo `dev`, y su modo se fijó con `chmod 645 tool.sh`. ¿Qué afirmación es FALSA?
(-) ana puede leer y modificar el fichero, pero no puede ejecutarlo como `./tool.sh`. :: Cierto: el dígito del dueño, 6, es 4+2, es decir `rw-`, sin bit de ejecución.
(-) Un usuario que no es ana ni está en `dev` puede leer el fichero y ejecutarlo como `./tool.sh`. :: Cierto: el último dígito, 5, es 4+1, es decir `r-x`, para todos los demás.
(+) Un miembro de `dev` (distinto de ana) puede ejecutarlo como `./tool.sh`, ya que «otros» tienen ejecución. :: Falso: a un usuario se le aplica una sola clase; un miembro del grupo cae bajo el dígito de grupo 4 (`r--`), así que puede leer el fichero pero obtiene «Permission denied» al ejecutarlo. El dígito de «otros» no se suma.
(-) Un miembro de `dev` (distinto de ana) puede leer el fichero pero no modificarlo. :: Cierto: el dígito de grupo 4 es `r--`.

@@q single | Borrar y luego comprimir
¿Qué imprime `echo 'a1,b22,,c333' | tr -d '0-9' | tr -s ','`?
(-) `a,b,,c` :: Es la salida del primer `tr` por sí solo: los dígitos se borran, pero la doble coma sigue ahí hasta que el segundo `tr` la comprime.
(+) `a,b,c` :: El primer `tr -d` borra todos los dígitos y deja `a,b,,c`; después `tr -s ','` comprime la coma repetida en una sola.
(-) `abc` :: Comprimir (`-s`) reduce las repeticiones a un solo carácter; no elimina las comas (eso sería `-d ','`).
(-) `a1,b22,c333` :: Eso saldría solo con la compresión; aquí los dígitos se borran primero.

@@q single | Elegir campos por número
La línea `lucia:x:1004:1004:Lucia R:/home/lucia:/bin/zsh` sigue el formato de `/etc/passwd`. ¿Qué imprime `echo '<esa línea>' | cut -d: -f7,3`?
(+) `1004:/bin/zsh` :: El campo 3 es el UID y el 7 es la shell de entrada; `cut` imprime los campos elegidos en el orden en que aparecen en la línea, sea cual sea el orden de la lista.
(-) `/bin/zsh:1004` :: `cut` nunca reordena campos: `-f7,3` equivale a `-f3,7`.
(-) `x:/bin/zsh` :: Eso sería `-f2,7`; el campo 2 es el marcador de contraseña, no el UID.
(-!) Ninguna de las anteriores. :: La salida es `1004:/bin/zsh`, que es una de las opciones anteriores.

@@q single | Aplicar un cambio de GRUB
En un sistema basado en Debian has editado `GRUB_TIMEOUT` en `/etc/default/grub`. ¿Qué mandato hace que GRUB use el nuevo valor en el próximo arranque?
(-) `sudo grub-install /dev/sda` :: Escribe el propio gestor de arranque en el disco; no es el paso que regenera la configuración del menú.
(-) `sudo cp /etc/default/grub /boot/grub/grub.cfg` :: `grub.cfg` se genera, no se copia: `/etc/default/grub` es solo la entrada del generador y tiene otro formato.
(-) `sudo update-initramfs -u` :: Reconstruye el disco RAM inicial que usa el núcleo; no toca la configuración de GRUB.
(+) `sudo update-grub` :: Regenera `/boot/grub/grub.cfg` a partir de `/etc/default/grub` y de los scripts de `/etc/grub.d/`.

@@q single | Todas las coincidencias en el PATH
Dos directorios, `/opt/a` y `/opt/b`, contienen cada uno un ejecutable llamado `run`, y `PATH=/opt/b:/opt/a:/usr/bin:/bin`. ¿Qué mandato imprime la ruta completa de ambos, en el orden en que la shell los encontraría?
(-) `which run` :: Se detiene en la primera coincidencia e imprime solo `/opt/b/run`.
(+) `which -a run` :: `-a` lista todas las coincidencias a lo largo del `PATH`, aquí `/opt/b/run` y después `/opt/a/run`.
(-) `echo $PATH | grep run` :: Solo imprime la línea del `PATH` si contiene el texto `run`, que no es el caso; nunca mira dentro de los directorios.
(-) `ls $PATH/run` :: `$PATH` se expande a toda la cadena separada por dos puntos, así que `ls` busca un único fichero con un nombre rarísimo y falla con «No such file or directory».

@@q single | Buscar en las páginas del manual
¿Qué afirmación sobre la búsqueda de páginas del manual es FALSA?
(-) `whatis cp` imprime la descripción de una línea de cada página del manual llamada `cp`. :: Cierto: es una búsqueda por nombre.
(-) `apropos copy` puede listar `cp` aunque `copy` no sea su nombre. :: Cierto: busca también en las descripciones, y `cp` se describe como «copy files and directories».
(+) `whatis copy` lista también `cp`, porque su descripción contiene la palabra `copy`. :: Falso: `whatis` solo compara nombres, y ninguna página se llama `copy`, así que responde `copy: nothing appropriate.`; la búsqueda por palabra clave es `apropos copy` o `man -k copy`.
(-) `man -k copy` realiza la misma búsqueda que `apropos copy`. :: Cierto: `-k` convierte `man` en una búsqueda por palabra clave.

@@q single | Qué indica un PID
¿Qué afirmación sobre los identificadores de proceso es CIERTA?
(+) Los PID se reparten secuencialmente hasta un máximo y luego la numeración vuelve a empezar; el PID 1 es el proceso inicial que arranca los servicios. :: El número crece con cada proceso nuevo; el límite clásico es 32767. El PID 1 (hoy normalmente systemd) lo lanza el núcleo al final de su arranque.
(-) Un proceso hijo siempre recibe el PID de su padre más uno, así que `sleep 9 &` lanzado desde una shell con PID 500 es siempre el PID 501. :: Pueden crearse otros procesos entre medias, y los PID no dependen del número del padre.
(-) Un PID pertenece a un programa, no a una ejecución: `ls` recibe siempre el mismo PID cada vez que se ejecuta. :: Cada ejecución es un proceso nuevo con un PID nuevo.
(-) El PID 1 es la shell de login del primer usuario, creada cuando ese usuario se autentica. :: El PID 1 existe desde el arranque, antes de que nadie inicie sesión; una shell de login tiene un PID corriente.

@@q single | Contar los argumentos
Un script `t.sh` contiene esta función y estas tres llamadas:

```
count() { echo $#; }
count "$*"; count "$@"; count $*
```

Lo ejecutas con `./t.sh "a b" c`. ¿Qué imprime, un número por línea?
(-) `2`, `2`, `3` :: `"$*"` es una sola palabra que une todos los argumentos, así que la primera llamada recibe 1 argumento, no 2.
(-) `1`, `3`, `3` :: `"$@"` conserva las fronteras originales: `a b` y `c` son 2 argumentos.
(-) `1`, `2`, `2` :: `$*` sin comillas se divide por blancos en `a`, `b` y `c`: 3 argumentos.
(+) `1`, `2`, `3` :: `"$*"` es una palabra (`a b c`), `"$@"` conserva los dos argumentos originales y `$*` sin comillas se divide en tres palabras.

@@q single | Mover dentro de un directorio
`docs` y `archive` son directorios existentes, y `notes` es un fichero, todos en el directorio actual. Ejecutas:

```
mv notes docs/todo
mv docs archive
```

¿Dónde está ahora el fichero?
(+) `archive/docs/todo` :: El primer `mv` mueve y renombra el fichero en un solo paso; el segundo mueve el directorio `docs` dentro del directorio existente `archive`.
(-) `archive/todo` :: `mv` no fusiona: como `archive` es un directorio existente, `docs` entra en él entero.
(-) `archive/docs/notes` :: El primer mandato ya renombró el fichero al moverlo a `docs`: su nombre es `todo`.
(-) `docs/todo` :: El segundo mandato se llevó `docs`: ya no existe en el directorio actual.

@@q single | Borrar algo que no existe
No hay ningún fichero ni directorio llamado `ghost` en el directorio actual. ¿Qué afirmación es CIERTA?
(-) `rm -r ghost` y `rm -rf ghost` imprimen el mismo error, porque `-f` solo evita las preguntas de confirmación. :: `-f` también ignora los ficheros inexistentes, así que `rm -rf` no dice nada.
(-) `rm -ri ghost` pregunta «remove directory 'ghost'?» y luego avisa de que no existe. :: No hay nada sobre lo que preguntar: informa del error de inmediato, igual que `rm -r`.
(-) `rm -r ghost` no imprime nada y termina bien, porque `-r` hace que `rm` omita los nombres que no existen. :: `-r` se refiere a directorios; un nombre inexistente es un error: «No such file or directory».
(+) `rm -r ghost` da «No such file or directory» y estado 1; `rm -rf ghost` no imprime nada y da estado 0. :: `-f` ignora los ficheros inexistentes y nunca pregunta, por eso se usa en scripts.
@@note
`-f` no permite a `rm` borrar un directorio sin `-r`: `rm -f dir` sigue diciendo «Is a directory». Úsalo con cuidado: `-f` también esconde errores.
