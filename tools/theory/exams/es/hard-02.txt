@@exam hard-02 | Examen difícil 2
@@about
Diez preguntas de respuesta única con trampas: el PID equivocado, un nombre pasado como texto, nombres de fichero con espacios, líneas continuadas, puntos de montaje ocupados y ajustes que sobreviven a un mandato.

@@q single | Matar el proceso equivocado
Un script debía lanzar `sleep 300` en segundo plano y después detenerlo:
```
sleep 300 &
kill $$
echo done
```
¿Qué ocurre cuando se ejecuta el script?
(-) `sleep` termina y el script imprime `done`. :: `kill $$` no nombra el proceso `sleep`.
(-) No se mata nada, porque `kill` no puede enviar señales a un proceso lanzado con `&`. :: `kill` puede enviar señales a cualquier proceso del usuario, en segundo plano o no.
(+) El script se mata a sí mismo, así que `done` nunca se imprime, y `sleep` sigue ejecutándose. :: `$$` es el PID de la shell que ejecuta el script; el PID del último mandato en segundo plano está en `$!`.
(-) `kill` espera a que `sleep` termine y luego termina el script. :: `kill` solo envía una señal y vuelve de inmediato.

@@q single | Un nombre no es un fichero
`notes.txt` tiene tres líneas. ¿Qué imprime `echo notes.txt | wc -l`?
(-) `3` :: `wc` cuenta las líneas de lo que llega por stdin, que es el texto producido por `echo`, no el contenido del fichero.
(+) `1` :: `echo` produce una línea con el texto `notes.txt`; `wc` nunca abre el fichero.
(-) `3 notes.txt` :: `wc` imprime un nombre de fichero solo cuando se le da como argumento.
(-) `0` :: `echo` termina su salida con un salto de línea, así que hay una línea.

@@q single | Nombres de fichero con espacios
El directorio contiene `a b.txt` y `c.txt`. ¿Qué ocurre al ejecutar `ls *.txt | xargs rm`?
(-) Se eliminan los dos ficheros. :: `xargs` divide la entrada en los blancos, así que `a b.txt` se convierte en dos nombres distintos.
(-) No se elimina nada, porque `rm` no puede leer nombres de fichero de una tubería. :: `xargs` convierte los nombres en argumentos, así que `rm` sí se ejecuta.
(+) Se elimina `c.txt`, `rm` se queja de `a` y `b.txt`, y `a b.txt` permanece. :: El nombre `a b.txt` se divide en `a` y `b.txt`, y ninguno existe.
(-) Se elimina `a b.txt`, porque `xargs` mantiene juntos los nombres con espacios. :: Por defecto también divide en blancos; para eso hace falta `-0` con `find -print0`.

@@q single | Una línea continuada
```
cd /tmp; cd /nope 2> /dev/null; \
pwd; echo $?
```
Estas dos líneas físicas se escriben en una shell que empieza en `/home/ana`. ¿Qué se imprime?
(-) `/home/ana` y `1` :: El primer `cd` tuvo éxito: el directorio actual es `/tmp`.
(-) `/tmp` y `1` :: `$?` es el estado del último mandato, `pwd`, no el del `cd` fallido.
(+) `/tmp` y `0` :: El `cd /nope` fallido deja el directorio como estaba, `;` continúa, y `$?` es el estado de `pwd`.
(-) Solo un error, porque la barra invertida anula el `;` que tiene delante. :: La barra invertida solo une las dos líneas.

@@q single | Saltos de línea en echo
¿Qué imprimen estos tres mandatos, en este orden?
```
echo -e 'x\ny' | wc -l
echo 'x\ny' | wc -l
echo -n 'x\ny' | wc -l
```
(-) `2`, `2` y `1` :: Sin `-e` el `\n` son dos caracteres normales, así que hay una línea.
(-) `1`, `1` y `1` :: Con `-e` el `\n` se convierte en un salto de línea real, así que hay dos líneas.
(-) `2`, `1` y `1` :: El tercer mandato, con `-n` y sin `-e`, no imprime ningún salto de línea.
(+) `2`, `1` y `0` :: El primero tiene dos saltos; el segundo tiene uno (el final de `echo`); el tercero ninguno, pues `-n` lo suprime y `\n` queda como texto.

@@q single | Un punto de montaje ocupado
Un pendrive está montado en `/media/usb`. En un terminal ejecutas `cd /media/usb` y después `umount /media/usb`. ¿Qué ocurre?
(-) El pendrive se desmonta y la shell pasa a `/`. :: `umount` no cambia el directorio de la shell.
(-) El pendrive se desmonta, y el directorio muestra lo que había bajo el punto de montaje. :: No mientras un proceso siga teniendo el sistema de ficheros montado como directorio de trabajo.
(+) `umount` se niega con un error como "target is busy". :: El directorio de trabajo de la shell está dentro del sistema de ficheros montado, lo que lo mantiene en uso.
(-) El contenido del pendrive se borra y después se desmonta. :: `umount` nunca borra datos.

@@q single | El argumento vacío
`c.sh` contiene:
```
case "$1" in
  "") echo empty ;;
  *.txt) echo text ;;
  [0-9]*) echo num ;;
  *) echo other ;;
esac
```
¿Qué imprimen `bash c.sh 5.txt`, `bash c.sh 7z`, `bash c.sh -x` y `bash c.sh` (sin argumento), en orden?
(-) `num`, `num`, `other`, `other` :: `5.txt` coincide antes con `*.txt`: gana el primer patrón que coincide.
(-) `text`, `num`, `other`, `other` :: Sin argumento, `"$1"` es una cadena vacía, que coincide con el primer patrón.
(+) `text`, `num`, `other`, `empty` :: Los patrones se prueban en orden; y `"$1"` sin argumento es la cadena vacía, que coincide con `""`.
(-) `text`, `other`, `other`, `empty` :: `7z` empieza por un dígito, así que `[0-9]*` coincide.

@@q single | Aislar un target
El target por defecto de una máquina es `graphical.target`. Un administrador ejecuta `systemctl isolate rescue.target` y luego `systemctl get-default`. ¿Qué imprime el segundo mandato?
(-) `rescue.target` :: `isolate` cambia el estado del sistema en marcha, no el valor por defecto configurado.
(-) `runlevel1.target` :: El valor por defecto tampoco cambia al alias del nivel de ejecución.
(+) `graphical.target` :: El target por defecto es el que alcanza la máquina en el próximo arranque; `isolate` no lo modifica.
(-) `poweroff.target` :: Ese es el nivel 0; nada de lo hecho lo pidió.

@@q single | También importa la ruta
`ana` es la dueña del directorio `d` con modo `rw-r--r--` y del fichero `d/f` con modo `rw-r--r--`. Crea el enlace simbólico `s` hacia `d/f`. ¿Qué afirmación es VERDADERA?
(-) `cat s` funciona, porque `f` es legible y el enlace tiene `rwxrwxrwx`. :: La ruta hasta el fichero pasa por `d`, que no tiene permiso de ejecución.
(+) `cat s` falla con `Permission denied`, aunque `ls d` sigue listando el nombre `f`. :: Llegar a `d/f` necesita `x` en `d`; el bit `r` solo permite listar los nombres.
(-) `cat s` falla, porque un enlace simbólico nunca da acceso a un fichero dentro de un directorio. :: Un enlace funciona con normalidad cuando se puede atravesar toda la ruta.
(-) `ls d` también falla, porque un directorio sin `x` no se puede listar. :: Listar los nombres necesita `r`, que `d` tiene.

@@q single | Quién soy
`ana` entra en `pts/0` y ejecuta `su - bob`. En esa nueva shell ejecuta `whoami`, `id` y `who`. ¿Qué afirmación es VERDADERA?
(-) `who` muestra una línea nueva para `bob`, porque cada `su` abre una sesión nueva. :: `su` no registra una sesión de login; `who` lista las creadas por logins.
(-) `whoami` sigue imprimiendo `ana`, porque el nombre del login no cambia hasta que cierra sesión. :: `whoami` imprime el usuario efectivo, que ahora es `bob`.
(+) `whoami` e `id` indican `bob`, mientras que `who` sigue listando la sesión de `ana`. :: `su` cambia el usuario de la shell; `who` lee el registro del login, que hizo `ana`.
(-) `id` muestra el UID de `ana` y los grupos de `bob`. :: `su -` cambia la identidad por completo.
