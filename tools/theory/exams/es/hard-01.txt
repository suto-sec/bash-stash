@@exam hard-01 | Examen difícil 1
@@about
Diez preguntas de respuesta única con trampas: comillas, comprobación de propietario, enlaces rotos, códigos de salida y scripts que se ejecutan sin argumentos.

@@q single | Comillas y barra invertida juntas
Tras `v=5`, ¿qué imprime `echo "\$v=$v" '$v=\$v' \$v=$v`?
(-) `$v=5 $v=$v $v=5` :: Dentro de comillas simples la barra invertida no es especial, así que `\$v` se queda tal cual: la segunda palabra es `$v=\$v`.
(+) `$v=5 $v=\$v $v=5` :: Palabra 1: la barra escapa el primer `$` entre comillas dobles y el segundo se expande. Palabra 2: las comillas simples lo dejan todo literal, barra incluida. Palabra 3: `\$` es un `$` literal y `$v` se expande.
(-) `5=5 $v=\$v 5=5` :: El `\$v` escapado nunca se expande: imprime un `$v` literal.
(-) `$v=5 $v=\$v $v=$v` :: La última palabra no lleva comillas, así que su segundo `$v` se expande a 5.

@@q single | Leer la salida de who
`who` imprime estas cuatro líneas para el mismo usuario:
```
ana  tty2   10:01
ana  :0     10:02
ana  pts/0  10:15 (:0)
ana  pts/1  10:40 (10.0.0.7)
```
¿Qué afirmación es VERDADERA?
(-) `:0` es una consola virtual en modo texto, mientras que `tty2` es la sesión gráfica del usuario. :: Al revés: `ttyN` es una consola virtual de texto y `:0` es la interfaz gráfica.
(-) `pts/0` y `pts/1` son consolas virtuales de texto de la máquina, a las que se llega con Ctrl+Alt+F1 a F6. :: Esas son las `ttyN`; las `pts/N` son terminales de texto abiertos dentro de otra cosa.
(+) `pts/0` es una ventana de terminal dentro de la sesión gráfica `:0`; `pts/1` es una sesión de texto que viene de 10.0.0.7. :: El texto entre paréntesis indica de dónde viene la sesión: la pantalla `:0` o la dirección remota (por ejemplo por ssh).
(-) Las cuatro líneas pertenecen a cuatro máquinas distintas, porque cada sesión tiene su propio nombre de terminal. :: Son cuatro sesiones del mismo usuario en esta máquina; solo la última viene de otra máquina.

@@q single | Solo cuentan los bits del dueño
`tool.sh` (un script de bash correcto) pertenece al usuario `ana` y al grupo `dev`, y ana es miembro de `dev`. Su modo es `---r-xr-x`. ana ejecuta `bash tool.sh` y después `./tool.sh`. ¿Qué ocurre?
(-) Ambos funcionan, porque ana también está cubierta por los bits de grupo y de otros, que permiten `r` y `x`. :: La shell se detiene en la primera clase que aplica: ana es la dueña, así que solo cuentan los bits del dueño.
(-) `bash tool.sh` funciona porque solo hace falta `r`, y `./tool.sh` falla porque ana no tiene `x`. :: Fallan los dos: la clase del dueño no tiene ni `r` ni `x`, y `bash` necesita `r` para leer el fichero.
(+) Fallan los dos con `Permission denied`: a ana solo se le aplican los bits del dueño, que son `---`. :: Solo se consulta la clase que corresponde al usuario, así que los bits más generosos del grupo y de otros no ayudan al dueño.
(-) `bash tool.sh` falla pero `./tool.sh` funciona, porque los bits de grupo dan a ana `r-x`. :: `./tool.sh` también falla: a ana se le aplican los bits del dueño, no los del grupo.

@@q single | Escribir a través de un enlace roto
En un directorio vacío:
```
echo hi > a
ln -s a b
rm a
echo new > b
```
¿Qué afirmación es VERDADERA después?
(-) `echo new > b` falla con "No such file or directory", porque `b` apunta a un fichero que no existe. :: Abrir un enlace simbólico para escribir lo sigue, y `>` crea el destino que falta.
(-) `b` se sustituye por un fichero regular con el texto `new`, y el enlace desaparece. :: El enlace se conserva: la redirección abre el fichero al que apunta, no sustituye el enlace.
(+) Existe un fichero nuevo `a` con `new`, y `b` vuelve a ser un enlace válido hacia él. :: La escritura sigue el enlace y crea `a`; `cat b` y `cat a` imprimen `new`.
(-) `a` se vuelve a crear con `hi`, porque el enlace recuerda el contenido anterior. :: Un enlace simbólico solo guarda la ruta `a`, nunca los datos del fichero.

@@q single | Comparar byte a byte
`f1` contiene las líneas `one` y `two`, y `f2` contiene `one` y `Two` (ambos acaban en salto de línea). ¿Qué imprime `cmp f1 f2`?
(-) `f1 f2 differ: byte 4, line 2` :: La primera línea tiene 4 bytes (`one` más el salto), así que el primer byte de la línea 2 es el número 5; los bytes se cuentan desde 1.
(-) `f1 f2 differ: byte 5, line 1` :: El byte 5 está en la segunda línea: la primera es `one` más su salto, 4 bytes.
(-) `2c2` seguido de las dos líneas :: Ese es el estilo de `diff`; `cmp` imprime una sola línea y se detiene en la primera diferencia.
(+) `f1 f2 differ: byte 5, line 2` :: Los bytes `o`,`n`,`e`, salto son del 1 al 4; `t` frente a `T` es el byte 5, en la línea 2.

@@q single | Quién es el padre
Desde una shell con PID 2215 ejecutas `sleep 100 & sleep 200 & pstree -p`, y en el árbol la shell aparece como `sshd(2210)───bash(2215)`. ¿Qué afirmación es VERDADERA?
(-) `pstree` es el padre de los dos procesos `sleep`, porque es quien los muestra. :: `pstree` solo lee la tabla de procesos; no crea los demás procesos.
(+) Los dos procesos `sleep` y el propio `pstree` son hijos de la shell, bash(2215). :: Cada mandato lanzado desde el prompt, en segundo plano o no, es hijo de la shell; `pstree` se muestra a sí mismo como uno de ellos.
(-) Los dos procesos `sleep` son hijos del PID 1, porque los procesos en segundo plano se separan de la shell. :: Un trabajo en segundo plano sigue siendo hijo de la shell que lo lanzó; solo un huérfano es adoptado por el PID 1.
(-) `bash(2215)` es hijo directo del PID 1, porque el árbol siempre empieza en el PID 1. :: El árbol empieza en el PID 1, pero aquí la shell cuelga de `sshd(2210)`, que es su padre.

@@q single | Cuenta 0, estado 1
`g` es un fichero con dos líneas, `x` e `y`. ¿Qué imprimen `grep -c zzz g; echo $?`?
(-) `0` y luego `0`, porque la cuenta es 0 y no ha ido nada mal. :: `$?` es el estado de salida de `grep`, no su salida; `grep` sale con 1 cuando no se selecciona ninguna línea.
(+) `0` y luego `1` :: `-c` imprime el número de líneas que coinciden (0), y el estado de salida es 1 porque ninguna línea coincidió.
(-) `1` y luego `1` :: La cuenta es el número de líneas que coinciden, 0.
(-) `0` y luego `2`, ya que 2 es el número de líneas del fichero. :: El estado de salida no es un número de líneas: 0 significa coincidencia, 1 ninguna y 2 un error.

@@q single | Nombres e i-nodos
En un directorio vacío ejecutas `touch a`, `mv a b`, `cp b c`, `ln b d` y `ln -s b e`, y después `ls -i b c d e`. ¿Qué afirmación es VERDADERA?
(-) `b` y `c` muestran el mismo número de i-nodo, porque `c` es una copia con el mismo contenido. :: Una copia es un fichero nuevo: recibe su propio i-nodo.
(-) `b` y `e` muestran el mismo número de i-nodo, porque un enlace simbólico es otro nombre del mismo fichero. :: Un enlace simbólico es un fichero propio que guarda una ruta, así que tiene su propio i-nodo.
(-) `b` tiene un número de i-nodo nuevo porque `mv` le cambió el nombre desde `a`. :: Dentro de un mismo sistema de ficheros `mv` solo cambia la entrada de directorio; el i-nodo sigue igual.
(+) `b` y `d` muestran el mismo número de i-nodo, mientras que `c` y `e` tienen cada uno el suyo. :: Un enlace duro es otra entrada de directorio para el mismo i-nodo.

@@q single | Comentarios de systemctl
¿Cuál de estas líneas tiene un comentario que NO describe lo que hace el mandato?
(-) `systemctl get-default   # prints the target the system reaches at boot` :: Verdadero: muestra el target por defecto.
(-) `systemctl isolate rescue.target   # stops the units of the current target and starts those of single-user mode` :: Verdadero: cambia de nivel, como el antiguo runlevel 1.
(+) `systemctl enable cups   # starts the service now and also at every boot` :: `enable` solo registra el servicio para los próximos arranques; `systemctl start cups` es lo que lo arranca ahora.
(-) `systemctl disable cups   # removes the service from the boot, without stopping a running instance` :: Verdadero: solo cambia lo que arranca al iniciar el sistema.

@@q single | Script sin argumento
`t.sh` contiene:
```
n=$1
if [ $n -lt 0 ]; then echo neg
elif [ $n -eq 0 ]; then echo zero
else echo pos
fi
```
Ejecutas `bash t.sh` sin argumentos. ¿Qué ocurre?
(-) Imprime `zero`, porque un valor vacío cuenta como 0. :: `$n` está vacío, así que cada prueba es `[ -eq 0 ]`: un error de sintaxis, no una comparación con 0.
(-) Se detiene en la primera prueba e imprime solo un error, porque una prueba que falla termina el script. :: Un `[` que falla solo devuelve un estado distinto de 0; el script sigue con la rama siguiente.
(+) Imprime dos errores `unary operator expected` por stderr y después `pos` por stdout. :: Las dos pruebas están mal formadas, así que ambas devuelven un valor distinto de 0 y se ejecuta la rama `else`.
(-) Imprime `neg`, porque la primera prueba `[ -lt 0 ]` es verdadera para un valor vacío. :: El `$n` vacío sin comillas desaparece y queda `[ -lt 0 ]`, que es un error y no "verdadero".
@@note
Poner la variable entre comillas (`[ "$n" -lt 0 ]`) seguiría fallando con "integer expression expected", así que comprueba antes `$#`.
