@@exam medium-06 | Examen medio 6
@@about
Diez preguntas de respuesta única que combinan dos datos o piden seguir dos o tres pasos: escapes, `xargs`, patrones anclados, puntos de montaje, señales, `case` y comprobación de argumentos.

@@q single | Escapes en echo
En bash, ¿qué imprimen `echo 'a\tb'` y `echo -e 'a\tb'`?
(-) Ambos imprimen `a`, un tabulador y `b`, porque `\t` siempre es un tabulador. :: Sin `-e`, `echo` imprime la barra invertida y la `t` tal cual.
(-) Ambos imprimen `a\tb`, porque las comillas simples bloquean todos los escapes. :: No son las comillas lo que importa: `-e` hace que `echo` interprete `\t`.
(+) El primero imprime `a\tb`; el segundo imprime `a`, un tabulador y `b`. :: `-e` activa la interpretación de escapes con barra invertida como `\t` y `\n`.
(-) El primero imprime `a`, un tabulador y `b`; el segundo imprime `a\tb`. :: Es al revés.

@@q single | Argumentos que no son stdin
Quieres borrar todos los ficheros cuyo nombre acaba en `~` bajo el directorio actual. ¿Qué mandato lo hace enviando a `rm` la lista de nombres que imprime `find`?
(-) `find . -name '*~' | rm` :: `rm` recibe los nombres como argumentos y no lee stdin: se queja de "missing operand".
(-) `find . -name '*~' > rm` :: Escribe la lista en un fichero llamado `rm`; no se borra nada.
(+) `find . -name '*~' | xargs rm` :: `xargs` lee los nombres de stdin y ejecuta `rm` con ellos como argumentos.
(-) `rm | find . -name '*~'` :: La tubería va en sentido contrario: `rm` tendría que producir los nombres.

@@q single | Patrones sobre una lista de palabras
`w` contiene las palabras `cart`, `cat`, `coat`, `cot` y `ct`, una por línea. ¿Qué mandato imprime exactamente `cat` y `cot`?
(-) `grep '^c.*t$' w` :: `.*` es cualquier número de caracteres, así que coincide con las cinco palabras.
(-) `grep '^co*t$' w` :: `o*` repite solo la `o`: coincide con `cot` y `ct`.
(+) `grep '^c.t$' w` :: Exactamente un carácter cualquiera entre `c` y `t`, en una línea que empieza y acaba ahí.
(-) `grep '^c.?t$' w` :: En una expresión regular básica `?` es un carácter normal, así que no coincide nada.

@@q single | Escribir bajo un punto de montaje
`/data` contiene el fichero `old.log`. Montas en `/data` un disco que contiene `new1` y `new2`, ejecutas `echo x > /data/new3`, y por último `umount /data`. ¿Qué muestra `ls /data`?
(-) `old.log`, `new1`, `new2` y `new3` :: Mientras el disco está montado, `old.log` queda oculto; y tras `umount` los ficheros del disco desaparecen del árbol.
(-) `new1`, `new2` y `new3` :: Esos ficheros pertenecen al disco, que ya no está montado.
(+) Solo `old.log` :: Al desmontar reaparece el contenido original; `new3` se escribió en el disco, no en el directorio de debajo.
(-) Nada, porque `umount` vacía el directorio. :: `umount` no elimina nada; solo vuelve a mostrar lo que había bajo el punto de montaje.

@@q single | Editar la línea de mandatos
¿Qué afirmación sobre la edición y el historial en bash es FALSA?
(-) `Tab` completa el nombre de un mandato o de un fichero. :: Verdadero.
(-) `Ctrl+A` mueve el cursor al principio de la línea y `Ctrl+E` al final. :: Verdadero.
(-) La flecha arriba recupera el mandato anterior del historial. :: Verdadero.
(+) `Ctrl+R` y unos pocos caracteres encuentra el mandato más antiguo que los contiene. :: Falso: encuentra el más reciente, y pulsar `Ctrl+R` otra vez pasa al siguiente más reciente.

@@q single | Qué hace el kernel
¿Qué afirmación sobre lo que ocurre después de que el gestor de arranque cede el control es FALSA?
(-) El kernel inicializa la gestión de memoria y el vector de interrupciones de la CPU. :: Verdadero: son tareas tempranas del kernel.
(-) El initrd es un disco RAM temporal con los controladores y herramientas necesarios para encontrar el sistema de ficheros raíz real. :: Verdadero: se usa hasta que se puede montar el sistema de ficheros raíz.
(-) El kernel busca por último el proceso inicial y lo arranca con el PID 1. :: Verdadero: es el proceso que levanta los servicios.
(+) El proceso inactivo, con PID 0, es el que arranca los servicios. :: Falso: el PID 0 es el proceso inactivo del kernel; los servicios los arranca el PID 1.

@@q single | Comprobar los argumentos
`need3.sh` contiene:
```
if [ $# -ne 3 ]; then echo "usage: $0 src dst mode" >&2; exit 1; fi
echo ok
```
Ejecutas `bash need3.sh onlyone 2> err.txt; echo "status=$?"; wc -l < err.txt`. ¿Qué se imprime en pantalla?
(-) `usage: need3.sh src dst mode`, luego `status=1` y `0` :: El mensaje de uso se escribió en stderr, así que fue a `err.txt` y no a la pantalla.
(-) `ok`, luego `status=0` y `0` :: Un argumento no son tres: la prueba falla y el script termina antes de `echo ok`.
(+) `status=1` y luego `1` :: El mensaje fue a `err.txt` (una línea), y el script terminó con estado 1.
(-) `status=0` y luego `1` :: `exit 1` fija el estado del script a 1.

@@q single | Ver los bytes
¿Qué mandato imprime el contenido del fichero `data` como valores hexadecimales, uno por byte?
(-) `od -c data` :: `-c` muestra los bytes como caracteres, con escapes como `\n`.
(+) `od -t x1 data` :: `-t x1` selecciona hexadecimal con un byte por valor.
(-) `cmp -l data other` :: Lista los bytes que difieren entre dos ficheros; no vuelca uno solo.
(-) `diff data other` :: Compara dos ficheros de texto línea a línea.

@@q single | Un case con patrones
`s.sh` contiene:
```
case $1 in
  a*) echo A ;;
  b|c) echo BC ;;
  *) echo other ;;
esac
```
¿Qué imprimen `bash s.sh abc`, `bash s.sh c` y `bash s.sh bc`, en este orden?
(-) `A`, `BC`, `BC` :: `b|c` significa exactamente `b` o exactamente `c`; `bc` no es ninguna de las dos, así que cae en `*`.
(-) `A`, `other`, `other` :: `c` es una de las alternativas de `b|c`.
(+) `A`, `BC`, `other` :: `abc` coincide con `a*`, `c` con `b|c`, y `bc` solo con `*`.
(-) `other`, `BC`, `other` :: `abc` empieza por `a`, así que coincide el primer patrón.

@@q single | Un proceso que ignora TERM
Se ha escrito un script para que ignore SIGTERM y siga ejecutándose. Le haces `kill 4321`, esperas un segundo, y luego `kill -9 4321`. ¿Qué ocurre?
(-) El primer `kill` lo termina, y el segundo informa de que el proceso no existe. :: SIGTERM se puede capturar o ignorar, y aquí se ignora.
(-) Ambas señales se ignoran, porque un proceso puede ignorar cualquier señal. :: SIGKILL (9) no se puede capturar ni ignorar.
(+) Sigue ejecutándose tras el primer `kill`, y el segundo lo termina. :: `kill` envía SIGTERM (15) por defecto; `-9` envía SIGKILL, que el proceso no puede rechazar.
(-) El primer `kill` lo detiene temporalmente, y el segundo lo hace continuar. :: Ninguna de las dos señales lo suspende; la primera no tiene efecto visible.
