@@exam easy-15 | Examen fácil 15
@@about
Diez preguntas de respuesta única sobre lo básico: números de trabajo, targets de systemd, añadir a un fichero, env y printenv, opciones de grep, crontab, wc, shift, ls -d y qué es una shell.

@@q single | Recuperar un trabajo
`jobs` muestra dos trabajos detenidos, `[1]` y `[2]`. ¿Qué mandato trae el trabajo número 2 al primer plano?
(+) `fg %2` :: `%2` nombra el trabajo número 2 y `fg` lo vuelve a poner en primer plano.
(-) `bg %2` :: Reanuda el trabajo 2, pero en segundo plano.
(-) `jobs %2` :: Solo lista el trabajo; no cambia su estado.
(-) `kill %2` :: Envía `SIGTERM` al trabajo 2, que termina.

@@q single | El target por defecto
¿Qué imprime `systemctl get-default`?
(+) El nombre del target al que llega el sistema por defecto en el arranque, como `graphical.target` o `multi-user.target`. :: Un target agrupa unidades, como hacían los antiguos niveles de ejecución.
(-) El número del nivel de ejecución por defecto, de 0 a 6. :: `systemd` usa targets con nombre; los números sobreviven solo como alias.
(-) El núcleo que GRUB carga por defecto. :: Eso es un ajuste de GRUB, no de systemd.
(-) La lista de unidades que fallaron en el último arranque. :: Las unidades fallidas se listan con `systemctl --failed`.

@@q single | Añadir a un fichero que no existe
`log.txt` no existe. ¿Qué hace `echo hi >> log.txt`?
(+) Crea `log.txt` con la línea `hi`. :: `>>` añade al final y crea el fichero si falta.
(-) Falla con «No such file or directory». :: Las redirecciones crean el fichero; no necesitan que exista.
(-) No hace nada, porque no hay contenido al que añadir. :: Siempre hay algo a lo que añadir: primero se crea un fichero vacío.
(-) Crea `log.txt` vacío e imprime `hi` en la pantalla. :: La salida de `echo` va al fichero, no a la pantalla.

@@q single | Variables que ven los hijos
Tras `x=1; export y=2`, ¿qué afirmación sobre `printenv` es FALSA?
(-) `printenv y` imprime `2`. :: Cierto: `y` está exportada, así que está en el entorno.
(-) `env` lista las variables exportadas, entre ellas `y`. :: Cierto: `env` imprime el entorno de la shell.
(-) Un programa lanzado desde esta shell puede leer `y`. :: Cierto: las variables exportadas las heredan los procesos hijos.
(+) `printenv x` imprime `1`, porque `printenv` muestra todas las variables de la shell. :: Falso: `x` no se exportó, así que no forma parte del entorno y `printenv x` no imprime nada.

@@q single | Las opciones de grep
¿Qué afirmación sobre las opciones de `grep` es FALSA?
(-) `grep -i` ignora la diferencia entre mayúsculas y minúsculas. :: Cierto.
(-) `grep -v` imprime las líneas que no coinciden. :: Cierto: invierte la selección.
(-) `grep -n` pone el número de línea delante de cada línea que imprime. :: Cierto.
(+) `grep -c` imprime las líneas que coinciden y, al final, cuántas fueron. :: Falso: `-c` imprime solo el número de líneas que coinciden, no las líneas.

@@q single | Listar el crontab
¿Qué hace `crontab -l`?
(+) Lista las tareas programadas en el crontab del usuario actual. :: `-e` lo edita y `-r` lo elimina.
(-) Abre el crontab del usuario actual en un editor. :: Eso es `crontab -e`.
(-) Borra todas las tareas del usuario actual. :: Eso es `crontab -r`.
(-) Lista las tareas de todos los usuarios del sistema. :: Cada usuario tiene su propio crontab; `-l` muestra solo el tuyo.

@@q single | Contar con wc
¿Qué afirmación sobre `wc` es CIERTA?
(+) `wc -m` cuenta caracteres y `wc -c` cuenta bytes. :: Para la línea `é` la salida de `wc -c` es 3 (dos bytes más el salto de línea) y la de `wc -m` es 2.
(-) `wc -l` cuenta las palabras y `wc -w` cuenta las líneas. :: `-l` cuenta líneas; las palabras se cuentan con `-w`.
(-) `wc -w` cuenta las líneas. :: `-w` cuenta palabras.
(-) `wc` sin opciones imprime solo el número de líneas. :: Imprime líneas, palabras y bytes, en ese orden.

@@q single | El mandato shift
¿Qué hace `shift` en un script?
(+) Descarta `$1` y desplaza el resto: `$2` pasa a ser `$1`. :: Sirve para procesar los argumentos uno a uno en un bucle.
(-) Mueve el cursor a la siguiente línea del script. :: `shift` no trata del texto del script.
(-) Desplaza el contenido de una variable un carácter a la izquierda, perdiendo el primero. :: Trabaja con los parámetros posicionales, no con cadenas.
(-) Añade el primer argumento al final de la lista. :: El primer argumento se descarta, no se rota.

@@q single | Listar un directorio en sí
`dd` es un directorio con un fichero dentro. ¿Qué imprime `ls -ld dd`?
(+) Una línea en formato largo que describe el propio directorio `dd`. :: `-d` lista el directorio en lugar de su contenido.
(-) El listado largo de los ficheros que hay dentro de `dd`. :: Eso es `ls -l dd`.
(-) El número de inodo de `dd`. :: Eso es `ls -i`.
(-) Los ficheros de `dd` y de todos sus subdirectorios. :: Eso es `ls -R dd`.

@@q single | Qué es una shell
¿Qué es la shell en un sistema operativo como Linux? Elige la afirmación CIERTA.
(+) Es un programa que lee las líneas que escribes, las interpreta y ejecuta los mandatos. :: Es un programa normal que se ejecuta sobre el núcleo; bash es una de varias shells.
(-) Es la parte del núcleo que gestiona los ficheros. :: La shell es un programa corriente del espacio de usuario, no parte del núcleo.
(-) Es el único programa que puede arrancar otros programas. :: Cualquier programa puede arrancar otros programas; la shell lo hace por el usuario.
(-) Es el programa que el firmware arranca primero al encender el ordenador. :: El firmware arranca un gestor de arranque, que carga el núcleo; la shell viene mucho después.
