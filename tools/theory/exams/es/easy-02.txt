@@exam easy-02 | Examen fácil 2
@@about
Diez preguntas de respuesta única sobre lo básico: un concepto en cada una, con las típicas opciones parecidas.

@@q single | Dueño con solo permiso de escritura
Eres el dueño de `data.txt`, un fichero regular con modo `--w-------`. ¿Qué hace `cat data.txt`?
(-) Muestra el contenido, porque el dueño de un fichero siempre puede leerlo. :: Ser el dueño no da ningún permiso por sí mismo: mandan los bits, y falta `r`.
(+) Falla con `Permission denied`: leer necesita `r` y el fichero solo tiene `w`. :: `cat` debe leer el fichero; `w` por sí solo no lo permite (añadir con `>>` sí funcionaría).
(-) No muestra nada y termina con éxito, porque un fichero de solo escritura no muestra nada. :: `cat` informa de un error y devuelve un estado distinto de cero; no tiene éxito en silencio.
(-) Muestra el contenido, porque `cat` solo necesita `x` o `w` sobre el fichero para abrirlo. :: Leer necesita `r`; `x` sirve para ejecutar el fichero y `w` para modificarlo.

@@q single | Interno o externo
¿Qué afirmación sobre mandatos internos y externos es FALSA?
(+) Para ejecutar un mandato interno como `jobs`, la shell busca en el `PATH` un fichero ejecutable llamado `jobs`. :: Falso: un mandato interno está implementado dentro de la shell, así que no se busca ni se lanza ningún fichero.
(-) `ls` y `cp` son mandatos externos: cada uno es un fichero de programa que la shell encuentra a través del `PATH`. :: Cierto: son programas en disco, por ejemplo `/usr/bin/ls`.
(-) `type cd` responde que `cd` es un mandato interno de la shell. :: Cierto: `type` dice cómo interpretaría la shell un nombre.
(-) `whereis ls` muestra la ruta del ejecutable de `ls` y de sus páginas de manual. :: Cierto: imprime entradas como `/usr/bin/ls` y `/usr/share/man/man1/ls.1.gz`.

@@q single | Añadir un usuario a un grupo
En un sistema tipo Debian ya existen el usuario `marta` y el grupo `lab`. ¿Qué mandato hace que `marta` sea miembro de `lab`?
(-) `addgroup lab marta` :: `addgroup` crea grupos; con dos argumentos se niega a actuar («unspecified operation»).
(-) `deluser marta lab` :: Hace lo contrario: quita a `marta` del grupo `lab`.
(+) `adduser marta lab` :: `adduser usuario grupo` añade un usuario existente a un grupo existente.
(-) `adduser lab marta` :: Los argumentos están en el orden equivocado: busca un usuario llamado `lab`, que no existe.

@@q single | Alias
¿Qué afirmación sobre los alias en bash es CIERTA?
(-) `unalias ll` borra del disco el programa llamado `ll`. :: Solo elimina el alias de la shell actual; no se toca ningún fichero.
(-) Un alias escrito en el prompt se guarda automáticamente y está disponible en todos los terminales que se abran después. :: Para conservarlo hay que escribirlo en un fichero de arranque como `~/.bashrc`.
(-) `alias` sin argumentos borra todos los alias de la sesión. :: Sin argumentos lista los alias que están definidos.
(+) Tras `alias ll='ls -l'`, escribir `ll /tmp` ejecuta `ls -l /tmp`. :: La shell sustituye la primera palabra por el texto del alias y conserva el resto de la línea.

@@q single | Campos con cut
Se ejecuta `echo 'tea,milk,rice,salt' | cut -d, -f2,4`. ¿Qué afirmación es FALSA?
(+) La salida es `milk salt`: `cut` une los campos con un espacio. :: Falso: `cut` conserva el delimitador de la entrada, así que la salida es `milk,salt`.
(-) `cut -d, -f3` sobre la misma línea imprime `rice`. :: Cierto: `-f3` selecciona el tercer campo.
(-) `cut -d, -f2-3` sobre la misma línea imprime `milk,rice`, los campos segundo y tercero. :: Cierto: un rango selecciona campos consecutivos y mantiene el delimitador entre ellos.
(-) `cut -c5-8` sobre la misma línea imprime `milk`, los caracteres 5 a 8 de la línea. :: Cierto: `-c` selecciona caracteres por posición; los caracteres 5 a 8 son `milk`.

@@q single | UEFI y la BIOS clásica
¿Qué afirmación sobre UEFI y la BIOS clásica es CIERTA?
(-) UEFI es el firmware más antiguo, y la BIOS lo sustituyó añadiendo Secure Boot. :: Es al revés: UEFI es el sucesor de la BIOS.
(+) UEFI sustituye a la BIOS y puede trabajar con discos GPT y ofrecer Secure Boot. :: Secure Boot permite al firmware rechazar software de arranque que no esté firmado.
(-) UEFI solo arranca desde discos MBR, mientras que los discos GPT solo los usa la BIOS clásica. :: Al revés: GPT es la tabla de particiones que acompaña a UEFI, y MBR a la BIOS.
(-) Secure Boot cifra el disco, de modo que sus ficheros no pueden leerse sin la contraseña del propietario. :: Secure Boot comprueba las firmas del software de arranque; no cifra nada.

@@q single | Flujos por defecto
¿Qué línea describe correctamente adónde van por defecto los tres flujos estándar de un mandato ejecutado en un terminal?
(-) stdin (0) se lee del fichero indicado en el primer argumento, stdout (1) va a la pantalla y stderr (2) va a la pantalla. :: Sin `<`, stdin es el teclado; un fichero como argumento es algo que abre el propio mandato.
(-) stdin (0) es el teclado, stdout (1) va a la pantalla y stderr (2) se descarta salvo que se redirija. :: Los errores no se descartan: stderr también va a la pantalla por defecto.
(-) stdin (1) es el teclado, stdout (0) va a la pantalla y stderr (2) va a la pantalla. :: Los números están cambiados: 0 es stdin y 1 es stdout.
(+) stdin (0) es el teclado, y tanto stdout (1) como stderr (2) van a la pantalla. :: Ambas salidas van al terminal salvo que se redirijan, por eso `2>` sirve para separar los errores.

@@q single | rmdir tras mkdir -p
En un directorio vacío ejecutas `mkdir -p a/b` y después `rmdir a`. ¿Qué ocurre?
(-) Se eliminan `a` y `b`, porque `b` está vacío y `rmdir` elimina un directorio junto con sus subdirectorios vacíos. :: `rmdir` solo elimina el directorio indicado, y solo si ese está vacío.
(-) `rmdir` pide confirmación y elimina `a` con `b` dentro si respondes `y`. :: `rmdir` nunca pregunta; borrar un directorio con contenido necesita `rm -r`.
(+) `rmdir` falla con «Directory not empty», porque `a` todavía contiene `b`. :: `-p` de `mkdir` creó ambos niveles; `rmdir` solo elimina directorios vacíos y `a` contiene `b`.
(-) Solo se elimina `a`, y `b` se queda en el directorio actual. :: No se mueve nada; el mandato falla y ambos directorios permanecen.

@@q single | Copiar con -u
`src/notes.txt` es más antiguo que `dest/notes.txt`. ¿Qué hace `cp -u src/notes.txt dest/`?
(-) Sobrescribe `dest/notes.txt` con el fichero antiguo, porque `-u` significa «incondicional» (unconditional). :: `-u` significa «update» (actualizar): copia solo si el origen es más reciente o el destino no existe.
(-) Pregunta `overwrite 'dest/notes.txt'?` y espera `y` o `n`. :: Eso es `-i` (interactivo).
(-) Conserva ambas versiones: la antigua se guarda como `notes.txt~` y se copia el origen. :: Las copias de seguridad necesitan `-b`; `-u` no crea ninguna.
(+) No hace nada: el destino es más reciente, así que se deja intacto. :: `-u` omite la copia cuando el destino es al menos tan reciente como el origen.

@@q single | Entorno tras ejecutar un script
`setup.sh` contiene la única línea `export MODE=test` y tiene permiso de ejecución. ¿Qué afirmación es CIERTA?
(-) Tras `./setup.sh`, `echo $MODE` imprime `test`, porque la variable fue exportada. :: `./setup.sh` se ejecuta en una shell hija; `export` pasa la variable solo a los hijos de esa shell, nunca de vuelta al padre.
(+) Tras `. setup.sh`, `echo $MODE` imprime `test` en tu shell actual. :: `.` (igual que `source`) ejecuta las líneas en la shell actual, así que la variable permanece.
(-) Tras `bash setup.sh`, `echo $MODE` imprime `test`, porque `bash` ejecuta el script con el entorno actual. :: Lanza una shell nueva: la variable desaparece cuando esta termina.
(-) Tras `. setup.sh`, `echo $MODE` no imprime nada, porque `.` ejecuta el script en una shell hija. :: `.` no crea ningún hijo; eso lo hacen `./` y `bash`.
