@@exam medium-04 | Examen medio 4
@@about
Diez preguntas de respuesta única que combinan dos datos o piden seguir dos o tres pasos: lo que root puede y no puede hacer, límites de profundidad, pruebas de cadenas y ficheros, palabras completas y sustituciones.

@@q single | Root y los permisos
`f` tiene el modo `---------` y `s.sh` es un script correcto con modo `rw-r--r--`; ambos pertenecen a ana. Root ejecuta `cat f` y después `./s.sh`. ¿Qué ocurre?
(-) Ambos fallan con `Permission denied`, porque root también está sujeto a los bits de permisos. :: Root puede leer y escribir cualquier fichero sean cuales sean sus bits.
(-) Ambos funcionan, porque root tiene todos los permisos sobre todos los ficheros. :: Root puede leer cualquier fichero, pero para ejecutar un fichero tiene que haber al menos un bit `x`.
(+) `cat f` imprime el contenido, pero `./s.sh` falla con `Permission denied`. :: Root no necesita permiso de lectura, pero sí un bit `x` en alguna parte para ejecutar un fichero.
(-) `cat f` falla, pero `./s.sh` funciona, porque tiene permiso de lectura. :: Al revés: root ignora los bits de lectura y escritura, pero no la falta del bit de ejecución.

@@q single | Limitar la profundidad
`d` contiene `a.txt`, `s/b.txt` y `s/t/c.txt`. ¿Qué imprime `find d -maxdepth 2 -name '*.txt'`?
(-) Solo `d/a.txt` :: `d/a.txt` está a profundidad 1, pero `d/s/b.txt`, a profundidad 2, también está dentro del límite.
(+) `d/a.txt` y `d/s/b.txt` :: `d` es la profundidad 0, sus entradas la 1 y las entradas de `d/s` la 2; `c.txt` está a profundidad 3.
(-) `d/a.txt`, `d/s/b.txt` y `d/s/t/c.txt` :: `c.txt` está a profundidad 3, más allá de `-maxdepth 2`.
(-) Nada, porque el patrón `*.txt` no coincide con los nombres que llevan una barra. :: `-name` se compara con el último componente de cada ruta, así que el patrón coincide.

@@q single | El fichero vacío
`empty.txt` es un fichero regular de 0 bytes. ¿Qué afirmación sobre las cuatro pruebas `[ -e empty.txt ]`, `[ -f empty.txt ]`, `[ -s empty.txt ]` y `[ -d empty.txt ]` es VERDADERA?
(-) Solo `-e` tiene éxito, porque el fichero no tiene ningún contenido. :: `-f` también tiene éxito: es un fichero regular.
(-) `-e`, `-f` y `-s` tienen éxito, y solo falla `-d`. :: `-s` necesita que el fichero exista y tenga contenido; este está vacío.
(+) `-e` y `-f` tienen éxito, mientras que `-s` y `-d` fallan. :: Existe y es un fichero regular, pero no está vacío (`-s`) ni es un directorio (`-d`).
(-) Solo falla `-d`, ya que el fichero existe y es regular. :: `-s` también falla, puesto que el fichero no tiene datos.

@@q single | La redirección que se come un argumento
¿Qué diferencia hay entre `ls | wc -l` y `ls > wc -l`?
(-) Ambos cuentan las entradas del directorio, y el segundo guarda el resultado en un fichero. :: El segundo mandato no ejecuta `wc`.
(+) El primero cuenta las líneas que imprime `ls`; el segundo ejecuta `ls -l` y escribe en un fichero llamado `wc`. :: Tras `> wc` la palabra `-l` es un argumento normal de `ls`.
(-) El primero es correcto y el segundo es un error de sintaxis, ya que `wc` no es un fichero. :: Es sintaxis válida; simplemente hace otra cosa.
(-) El primero manda la salida de `ls` a `wc`; el segundo manda la salida de `wc` a `ls`. :: Ninguno de los dos manda salida a `ls`.

@@q single | Forzar un cambio de contraseña
¿Qué mandato hace que el usuario `ana` tenga que elegir una contraseña nueva la próxima vez que entre?
(-) `passwd -l ana` :: `-l` bloquea la cuenta, así que no podría entrar con contraseña.
(-) `passwd -u ana` :: `-u` desbloquea una cuenta que estaba bloqueada; no caduca la contraseña.
(+) `passwd -e ana` :: `-e` hace caducar la contraseña: debe cambiarse en el siguiente login.
(-) `deluser ana` :: Elimina al usuario en lugar de pedir una contraseña nueva.

@@q single | Ordenar dentro de top
`top` muestra los procesos ordenados por uso de CPU. ¿Qué tecla los ordena por uso de memoria?
(+) `M` (Shift+M) :: Cambia la columna de ordenación al uso de memoria.
(-) `h` :: Abre la pantalla de ayuda con la lista de opciones.
(-) `q` :: Sale de `top`.
(-) `k` :: Pide el PID de un proceso para enviarle una señal; no cambia el orden.

@@q single | Una palabra completa
`w` contiene las líneas `cat`, `concat`, `catalog` y `the cat sat`. ¿Qué mandato imprime solo las líneas que contienen `cat` como palabra completa?
(-) `grep cat w` :: Coincide con `cat` en cualquier parte, así que imprime las cuatro líneas.
(-) `grep '\<cat' w` :: Ancla solo el principio de la palabra, así que `catalog` también coincide.
(-) `grep '^cat$' w` :: Coincide solo con una línea que sea exactamente `cat`, y no ve `the cat sat`.
(+) `grep -w cat w` :: `-w` exige que la coincidencia sea una palabra completa, dando `cat` y `the cat sat`.

@@q single | Escribir a través de un enlace a un directorio
```
mkdir d; echo 1 > d/f
ln -s d link
echo 2 >> link/f
cat d/f
rm link
ls d
```
¿Qué imprime esto?
(-) `1`, `2` y luego nada para `ls`, porque `rm link` eliminó el directorio. :: `rm` sobre un enlace simbólico elimina solo el enlace.
(-) `1` y `f`, porque `link/f` es un fichero distinto. :: `link/f` es `d/f`, alcanzado a través del enlace, así que la línea `2` se añade a él.
(+) `1`, `2` y `f` :: La adición pasa por el enlace hasta `d/f`; quitar el enlace deja `d` y su fichero intactos.
(-) `2` y `f`, porque `>>` reemplaza el contenido. :: `>>` añade, así que `1` se conserva.

@@q single | Sustitución de mandatos
¿Qué afirmación sobre la sustitución de mandatos es FALSA?
(-) `n=$(ls | wc -l)` guarda en `n` el número de entradas. :: Verdadero: la salida del mandato sustituye a `$( )`.
(-) `echo "Hi $(whoami)"` se expande incluso entre comillas dobles. :: Verdadero: las comillas dobles permiten las sustituciones.
(-) Las comillas invertidas, como en `` `date` ``, hacen lo mismo que `$(date)`. :: Verdadero: es la sintaxis antigua de lo mismo.
(+) `echo '$(date)'` imprime la fecha actual. :: Falso: las comillas simples impiden la sustitución, así que imprime el texto `$(date)`.

@@q single | tee, paste y split
¿Qué afirmación sobre `tee`, `paste` y `split` es FALSA?
(-) `ls | tee list.txt` muestra el listado en pantalla y además lo guarda en `list.txt`. :: Verdadero: `tee` escribe su entrada en el fichero y en stdout.
(-) `split -l 2 f` corta `f` en trozos de dos líneas cada uno, llamados `xaa`, `xab`, etc. :: Verdadero.
(-) `paste a b` une la línea 1 de `a` con la línea 1 de `b`, separadas por un tabulador, luego las líneas 2, etc. :: Verdadero: pega los ficheros lado a lado.
(+) `paste a b` imprime todo `a` y luego todo `b`. :: Falso: eso es lo que hace `cat a b`.
