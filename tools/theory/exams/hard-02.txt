@@tier hard
@@about
Ten single-choice questions with traps: the wrong PID, a name passed as text, file names with spaces, line continuations, busy mount points and settings that outlive a command.

@@q single | Killing the wrong process
@@topic jobs-procs
A script was meant to start `sleep 300` in the background and then stop it:
```
sleep 300 &
kill $$
echo done
```
What happens when the script runs?
(-) `sleep` is terminated and the script prints `done`. :: `kill $$` does not name the `sleep` process.
(-) Nothing is killed, because `kill` cannot signal a process started with `&`. :: `kill` can signal any process the user owns, in the background or not.
(+) The script kills itself, so `done` is never printed, and `sleep` keeps running. :: `$$` is the PID of the shell running the script; the PID of the last background command is in `$!`.
(-) `kill` waits for `sleep` to finish and then ends the script. :: `kill` only sends a signal and returns at once.

@@q single | A name is not a file
@@topic filters
`notes.txt` has three lines. What does `echo notes.txt | wc -l` print?
(-) `3` :: `wc` counts the lines of what arrives on stdin, which is the text produced by `echo`, not the contents of the file.
(+) `1` :: `echo` outputs one line containing the text `notes.txt`; `wc` never opens the file.
(-) `3 notes.txt` :: `wc` prints a file name only when it is given as an argument.
(-) `0` :: `echo` ends its output with a newline, so there is one line.

@@q single | File names with spaces
@@topic redirection-pipes
The directory holds `a b.txt` and `c.txt`. What happens when you run `ls *.txt | xargs rm`?
(-) Both files are removed. :: `xargs` splits the input at blanks, so `a b.txt` becomes two separate names.
(-) Nothing is removed, because `rm` cannot read file names from a pipe. :: `xargs` turns the names into arguments, so `rm` does run.
(+) `c.txt` is removed, `rm` complains about `a` and `b.txt`, and `a b.txt` stays. :: The name `a b.txt` is split into `a` and `b.txt`, neither of which exists.
(-) `a b.txt` is removed, because `xargs` keeps names with spaces together. :: By default it splits on blanks too; `-0` with `find -print0` is needed for that.

@@q single | A line continued
@@topic shell-help
```
cd /tmp; cd /nope 2> /dev/null; \
pwd; echo $?
```
These two physical lines are typed in a shell that starts in `/home/ana`. What is printed?
(-) `/home/ana` and `1` :: The first `cd` succeeded: the current directory is `/tmp`.
(-) `/tmp` and `1` :: `$?` is the status of the last command, `pwd`, not that of the failed `cd`.
(+) `/tmp` and `0` :: The failed `cd /nope` leaves the directory as it was, `;` goes on, and `$?` is the status of `pwd`.
(-) Only an error, because the backslash cancels the `;` before it. :: The backslash only joins the two lines.

@@q single | Newlines in echo
@@topic expansion-vars
What do these three commands print, in this order?
```
echo -e 'x\ny' | wc -l
echo 'x\ny' | wc -l
echo -n 'x\ny' | wc -l
```
(-) `2`, `2` and `1` :: Without `-e` the `\n` is two ordinary characters, so there is one line.
(-) `1`, `1` and `1` :: With `-e` the `\n` becomes a real newline, so there are two lines.
(-) `2`, `1` and `1` :: The third command, with `-n` and no `-e`, prints no newline at all.
(+) `2`, `1` and `0` :: The first has two newlines; the second has one (the final newline of `echo`); the third has none, since `-n` suppresses it and `\n` stays as text.

@@q single | A busy mount point
@@topic files-fs
A pendrive is mounted on `/media/usb`. In a terminal you run `cd /media/usb` and then `umount /media/usb`. What happens?
(-) The pendrive is unmounted and the shell is moved to `/`. :: The shell's directory is not changed by `umount`.
(-) The pendrive is unmounted, and the directory shows what was under the mount point. :: Not while a process still has the mounted filesystem as its working directory.
(+) `umount` refuses with an error such as "target is busy". :: The shell's working directory is inside the mounted filesystem, which keeps it in use.
(-) The content of the pendrive is deleted, and then it is unmounted. :: `umount` never deletes data.

@@q single | The empty argument
@@topic scripts
`c.sh` contains:
```
case "$1" in
  "") echo empty ;;
  *.txt) echo text ;;
  [0-9]*) echo num ;;
  *) echo other ;;
esac
```
What do `bash c.sh 5.txt`, `bash c.sh 7z`, `bash c.sh -x` and `bash c.sh` (no argument) print, in order?
(-) `num`, `num`, `other`, `other` :: `5.txt` is matched earlier by `*.txt`: the first matching pattern wins.
(-) `text`, `num`, `other`, `other` :: With no argument, `"$1"` is an empty string, which matches the first pattern.
(+) `text`, `num`, `other`, `empty` :: Patterns are tried in order; and `"$1"` with no argument is the empty string, which matches `""`.
(-) `text`, `other`, `other`, `empty` :: `7z` starts with a digit, so `[0-9]*` matches it.

@@q single | Isolating a target
@@topic boot-systemd
The default target of a machine is `graphical.target`. An administrator runs `systemctl isolate rescue.target` and then `systemctl get-default`. What does the second command print?
(-) `rescue.target` :: `isolate` changes the state of the running system, not the configured default.
(-) `runlevel1.target` :: The default is not changed to the runlevel alias either.
(+) `graphical.target` :: The default target is what the machine reaches at the next boot; `isolate` does not modify it.
(-) `poweroff.target` :: That is level 0; nothing here asked for it.

@@q single | The path matters too
@@topic permissions
`ana` owns the directory `d` with mode `rw-r--r--` and the file `d/f` with mode `rw-r--r--`. She creates the symbolic link `s` to `d/f`. Which statement is TRUE?
(-) `cat s` works, because `f` is readable and the link has `rwxrwxrwx`. :: The path to the file goes through `d`, which has no execute permission.
(+) `cat s` fails with `Permission denied`, although `ls d` still lists the name `f`. :: Reaching `d/f` needs `x` on `d`; the `r` bit only allows listing the names.
(-) `cat s` fails, because a symbolic link never gives access to a file inside a directory. :: A link works normally when the whole path can be traversed.
(-) `ls d` fails too, because a directory without `x` cannot be listed. :: Listing the names needs `r`, which `d` has.

@@q single | Who am I
@@topic users-sessions
`ana` logs in on `pts/0` and runs `su - bob`. In that new shell she runs `whoami`, `id` and `who`. Which statement is TRUE?
(-) `who` shows a new line for `bob`, because every `su` opens a new session. :: `su` does not register a login session; `who` lists the ones created by logins.
(-) `whoami` still prints `ana`, because the name of the login does not change until she logs out. :: `whoami` prints the effective user, which is now `bob`.
(+) `whoami` and `id` report `bob`, while `who` still lists the session of `ana`. :: `su` changes the user of the shell; `who` reads the record of the login, which was made by `ana`.
(-) `id` shows the UID of `ana` and the groups of `bob`. :: `su -` switches the identity completely.
