Ten single-choice questions that combine two facts or ask you to trace a few steps: letter case in names, pipeline statuses, aliases, read, directory permissions, systemd defaults, exit codes, startup files, wc and background PIDs.

@@q single | Case and file names
@@topic files-fs
Which statement about upper and lower case in Linux is FALSE?
(-) `README` and `readme` can exist side by side in the same directory. :: True: they are different names.
(-) If only `Documents` exists, `cd documents` fails. :: True: names are case sensitive.
(-) `Echo hi` fails with "command not found", while `echo hi` works. :: True: command names are case sensitive too.
(+) If `Notes.txt` exists, `touch notes.txt` only updates the time of that file. :: False: `notes.txt` is another name, so `touch` creates a second, empty file.

@@q single | Status of a group
@@topic redirection-pipes
You type `(cd /tmp; false); echo $?`. What is printed?
(+) `1` :: The status of a parenthesised group is the status of its last command, and `false` returns 1.
(-) `0` :: `cd /tmp` succeeded, but it is not the last command of the group.
(-) `/tmp` :: `echo $?` prints a status number; nothing in the line prints the directory.
(-) `127` :: 127 means "command not found", and both `cd` and `false` exist.

@@q single | Redefining an alias
@@topic expansion-vars
In an interactive shell you type `alias ll='ls -l'`, then `alias ll='ls -la'`, then `alias ll`. What does the last command print?
(+) `alias ll='ls -la'` :: Defining an alias again replaces the previous definition, and `alias name` shows the current one.
(-) `alias ll='ls -l'` :: The second definition replaced the first one.
(-) Both definitions, one after the other. :: An alias has only one value at a time.
(-) `ls -la` :: `alias ll` prints the definition in the form `alias name='...'`, it does not run it.

@@q single | Two ways of reading
@@topic scripts
Compare `read -p "Name: " n` and `read -t 5 n`. Which statement is correct?
(+) The first shows a prompt; the second waits at most 5 seconds and then fails. :: `-p` gives a prompt text and `-t` a timeout in seconds; on a timeout `read` returns a non-zero status.
(-) The first waits 5 seconds and the second shows a prompt. :: The options are the other way round.
(-) Both wait for ever, since the options only change how the variable is stored. :: `-t` is exactly what limits the waiting time.
(-) The second reads from a file called `5` into `n`. :: `-t` takes the timeout as its argument; `read` still reads standard input.

@@q single | Listing needs read
@@topic permissions
Which statement about the permissions of a directory is FALSE?
(-) To create a file in it you need write and execute permission on it. :: True: creating adds a name to the directory.
(-) To rename a file in it you need write and execute permission on it. :: True: renaming changes a name stored in the directory.
(-) With only read permission you can list the names, but you cannot get the details of the files. :: True: `ls` shows the names, while `ls -l` answers "Permission denied" for each entry.
(+) With only execute permission you can list its names with `ls`. :: False: listing needs read permission. With only `x` you can pass through the directory to a file whose name you already know.

@@q single | A text-only default
@@topic boot-systemd
You want the next boots of a systemd machine to start in text mode, without the graphical desktop. Which command does that?
(+) `sudo systemctl set-default multi-user.target` :: It changes the default target for the following boots.
(-) `sudo systemctl isolate multi-user.target` :: It switches the running system to that target now, but the default for the next boot does not change.
(-) `sudo systemctl enable graphical.target` :: It is the graphical target that gives the desktop.
(-) `sudo systemctl get-default multi-user.target` :: `get-default` only prints the current default and takes no argument.

@@q single | A command that does not exist
@@topic shell-help
You type `foo`, which is not a builtin, an alias or a program in the `PATH`. What does `echo $?` print right after?
(+) `127` :: The shell uses 127 for "command not found" (126 is for a file that exists but cannot be executed).
(-) `0` :: Status 0 means success, and the command did not run.
(-) `1` :: 1 is the generic failure status of many commands, not the one the shell reports for a missing command.
(-) `2` :: 2 is used by many commands for incorrect usage; it is not the status of a missing command.

@@q single | Login files
@@topic users-sessions
Which statement compares `~/.profile` and `~/.bashrc` correctly?
(+) `~/.profile` is for login shells; `~/.bashrc` is for interactive shells that are not login shells. :: Many `.profile` files include `~/.bashrc`, so that both kinds of shell get the same aliases.
(-) `~/.bashrc` is read only at login and `~/.profile` by every new terminal window you open. :: It is the other way round.
(-) Both are read only by `root`. :: Every user has them in the home directory.
(-) `~/.profile` configures the kernel and `~/.bashrc` configures the boot loader. :: Both are shell startup files.

@@q single | Counting entries
@@topic filters
The directory `e` contains two files, `a` and `b`. Which command prints just the number of entries of `e`, `2`?
(+) `ls e | wc -l` :: `ls` prints one name per line when its output is a pipe, and `wc -l` counts the lines.
(-) `ls -l e | wc -l` :: The long listing starts with a line `total ...`, so it prints `3`.
(-) `wc -l e` :: `wc` would try to read `e` as a file, and it is a directory.
(-) `ls e wc -l` :: Without the pipe `ls` receives `wc` and `-l` as more arguments.

@@q single | The PID of a background job
@@topic jobs-procs
Which line starts `sleep 30` in the background and then prints its PID?
(+) `sleep 30 & echo $!` :: `$!` is the PID of the last background job.
(-) `sleep 30 ; echo $!` :: `;` runs `sleep` in the foreground: the `echo` waits 30 seconds, and `$!` is empty because nothing was run in the background.
(-) `sleep 30 & echo $$` :: `$$` is the PID of the shell itself, not of the background job.
(-) `sleep 30 && echo $!` :: The `echo` runs after `sleep` ends, and `$!` is empty if no background job was started.
