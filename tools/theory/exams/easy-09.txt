@@q single | An if with several branches
@@topic scripts
Which `if` is written correctly in bash?
(+) `if [ "$n" -gt 0 ]; then echo pos; elif [ "$n" -lt 0 ]; then echo neg; else echo zero; fi` :: Each test is followed by `;` (or a newline) before `then`, the extra branch is `elif`, and everything ends with `fi`.
(-) `if [ "$n" -gt 0 ] then echo pos; else if [ "$n" -lt 0 ] then echo neg; fi` :: There is no `;` before `then`, so the shell reports a syntax error near `else`.
(-) `if [ "$n" -gt 0 ]; then echo pos; elsif [ "$n" -lt 0 ]; then echo neg; fi` :: `elsif` does not exist in bash; the keyword is `elif`.
(-) `if ["$n" -gt 0]; then echo pos; elif ["$n" -lt 0]; then echo neg; fi` :: `[` is a command and needs spaces around it: `["5"` is read as an unknown command called `[5`.

@@q single | Members of a group
@@topic users-sessions
Which statement about `/etc/group` is FALSE?
(-) Each line has four fields separated by colons: group name, password placeholder, GID and a list of members. :: True: for example `devs:x:1004:luke,sally`.
(-) The members are written separated by commas. :: True: `luke,sally,rmartin`.
(-) A user can belong to a group without being named in its member list, if that group is the user's primary group. :: True: the primary group is not taken from this list.
(+) The primary group of a user is the one that lists the user as a member in `/etc/group`. :: False: the primary group is the GID written in the user's line of `/etc/passwd`; `/etc/group` lists the supplementary members.

@@q single | Moving around in info
@@topic shell-help
Which statement about `info` is TRUE?
(+) `u` goes up one level of the node tree and `l` goes back to the last node you visited. :: `info` organises a manual as a tree of nodes; `n`, `p`, `u` move through it and `l` goes back.
(-) `n` and `p` scroll the current node one line down and up. :: They jump to the next and the previous node; scrolling is done with the space bar and backspace.
(-) `q` goes back to the previous node; to leave `info` you press `x`. :: `q` is the key that quits `info`.
(-) `Tab` goes to the next page of the node. :: `Tab` moves the cursor to the next link (menu entry or cross-reference) of the node.

@@q single | Screen and file at once
@@topic redirection-pipes
Which command shows the output of `ls` on the screen and also saves it in `list.txt`?
(+) `ls | tee list.txt` :: `tee` copies its input to its output and to the file.
(-) `ls > list.txt` :: The output goes only to the file; nothing is shown.
(-) `ls | list.txt` :: The shell tries to run `list.txt` as a command: "command not found".
(-) `ls | cat > list.txt` :: `cat` just forwards the data, and the `>` sends it to the file: nothing reaches the screen.

@@q single | chainloader in GRUB
@@topic boot-systemd
At the GRUB command line, what is the purpose of `chainloader +1`?
(+) To hand control to the boot loader of another partition or system, instead of loading a kernel. :: This is chain loading: GRUB does not load a kernel itself but starts the other boot loader.
(-) To load a Linux kernel into memory and pass it the parameters of the command line. :: That is done with `linux` (and `initrd` for the initial RAM disk).
(-) To select the partition that holds `/boot`. :: That is done with `set root=...` (or `search`).
(-) To rebuild `grub.cfg` from the files in `/etc/grub.d/`. :: That is `update-grub`, run from a normal shell, not from the GRUB prompt.

@@q single | A mount point with files
@@topic files-fs
The directory `/mnt/data` contains the file `old.txt`. You mount a partition that holds `new.txt` on `/mnt/data`. What does `ls /mnt/data` show?
(+) Only `new.txt`: `old.txt` is hidden until the partition is unmounted. :: Mounting covers the previous contents of the mount point; they are not deleted and reappear after `umount`.
(-) Both `old.txt` and `new.txt`, merged in a single listing. :: A mount does not merge directories: it replaces what you see at that path.
(-) Only `old.txt`, until you `cd` into the directory again. :: The mount takes effect at once for everybody.
(-) Nothing: the mount point is emptied when something is mounted on it. :: The files are not erased; they are just not reachable while the mount lasts.

@@q single | Printing a dollar and quotes
@@topic expansion-vars
Which command prints exactly `Cost: $5 "net"`?
(+) `echo 'Cost: $5 "net"'` :: Single quotes keep every character as it is, double quotes and `$5` included.
(-) `echo "Cost: $5 "net""` :: Inside double quotes `$5` is expanded (to nothing) and the quotes around `net` just close and reopen the string: it prints `Cost:  net`.
(-) `echo Cost: $5 "net"` :: `$5` is expanded to nothing and the quotes disappear: it prints `Cost: net`.
(-) `echo "Cost: $5 \"net\""` :: The `\"` are right, but `$5` is still expanded: it prints `Cost:  "net"`.

@@q single | What split does
@@topic filters
Which statement about `split` is FALSE?
(-) With no options it cuts the input into pieces of 1000 lines. :: True: 1000 lines is the default size.
(-) `split -b 1M big.bin` cuts the file into pieces of one mebibyte. :: True: `-b` sets the size in bytes (with suffixes such as K and M).
(-) If no prefix is given, the pieces are called `xaa`, `xab`, `xac`... :: True: the default prefix is `x`.
(+) `split` deletes the original file after cutting it. :: False: `split` only reads the file; the original is still there afterwards.

@@q single | Who can change the owner
@@topic permissions
Which statement about `chown` and `chgrp` is TRUE?
(+) Only root can give a file away; the owner can change its group, but only to a group he or she is in. :: As an ordinary user, `chown root file` fails with "Operation not permitted", and so does `chgrp` with a group you are not in.
(-) The owner of a file can give it to any other existing user of the system with `chown`. :: Allowing that would let users dodge disk quotas, so Linux restricts it to root.
(-) `chgrp` changes the permission bits of the group on a file. :: `chgrp` changes which group owns the file; the bits are changed with `chmod`.
(-) `chown` can only be used on directories. :: It works on any file.

@@q single | Sorting inside top
@@topic jobs-procs
While `top` is running you press `M` (capital). What happens?
(+) The list is sorted by memory usage. :: Inside `top`, `M` sorts by `%MEM`; `P` sorts by CPU usage.
(-) The list is sorted by CPU usage. :: That is the key `P`.
(-) A prompt asks for the PID of a process to kill. :: That is `k`.
(-) `top` quits. :: That is `q`.
