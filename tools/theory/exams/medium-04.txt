@@q single | Root and permissions
@@topic permissions
`f` has mode `---------` and `s.sh` is a correct script with mode `rw-r--r--`; both belong to ana. Root runs `cat f` and then `./s.sh`. What happens?
(-) Both fail with `Permission denied`, because root is also subject to the permission bits. :: Root can read and write any file regardless of its bits.
(-) Both work, because root has every permission on every file. :: Root can read any file, but to execute a file at least one `x` bit has to be set.
(+) `cat f` prints the content, but `./s.sh` fails with `Permission denied`. :: Root needs no read permission, yet still needs an `x` bit somewhere to run a file.
(-) `cat f` fails, but `./s.sh` works, because it has read permission. :: The opposite: root ignores the read and write bits but not the missing execute bit.

@@q single | Limiting the depth
@@topic find
`d` contains `a.txt`, `s/b.txt` and `s/t/c.txt`. What does `find d -maxdepth 2 -name '*.txt'` print?
(-) `d/a.txt` only :: `d/a.txt` is at depth 1, but `d/s/b.txt` at depth 2 is also within the limit.
(+) `d/a.txt` and `d/s/b.txt` :: `d` is depth 0, its entries depth 1 and the entries of `d/s` depth 2; `c.txt` is at depth 3.
(-) `d/a.txt`, `d/s/b.txt` and `d/s/t/c.txt` :: `c.txt` is at depth 3, beyond `-maxdepth 2`.
(-) Nothing, because the pattern `*.txt` does not match the names with a slash in them. :: `-name` is compared with the last component of each path, so the pattern matches.

@@q single | The empty file
@@topic scripts
`empty.txt` is a regular file with 0 bytes. Which statement about the four tests `[ -e empty.txt ]`, `[ -f empty.txt ]`, `[ -s empty.txt ]` and `[ -d empty.txt ]` is TRUE?
(-) Only `-e` succeeds, because the file has no content at all. :: `-f` succeeds too: it is a regular file.
(-) `-e`, `-f` and `-s` succeed, and only `-d` fails. :: `-s` needs the file to exist and have content; this one is empty.
(+) `-e` and `-f` succeed, while `-s` and `-d` fail. :: It exists and is a regular file, but it is not empty (`-s`) and not a directory (`-d`).
(-) Only `-d` fails, since the file exists and is regular. :: `-s` fails as well, since the file has no data.

@@q single | The redirection that eats an argument
@@topic redirection-pipes
What is the difference between `ls | wc -l` and `ls > wc -l`?
(-) Both of them count the entries of the directory, and the second one saves the result in a file. :: The second command does not run `wc`.
(+) The first counts the lines `ls` prints; the second runs `ls -l` and writes into a file named `wc`. :: After `> wc` the word `-l` is an ordinary argument of `ls`.
(-) The first one is correct and the second one is a syntax error, since `wc` is not a file. :: It is valid syntax; it simply does something different.
(-) The first sends the output of `ls` to `wc`; the second sends the output of `wc` to `ls`. :: Neither of them sends output to `ls`.

@@q single | Forcing a password change
@@topic users-sessions
Which command makes the user `ana` choose a new password the next time she logs in?
(-) `passwd -l ana` :: `-l` locks the account, so she could not log in with a password at all.
(-) `passwd -u ana` :: `-u` unlocks an account that was locked; it does not expire the password.
(+) `passwd -e ana` :: `-e` expires the password: it must be changed at the next login.
(-) `deluser ana` :: It removes the user instead of asking for a new password.

@@q single | Sorting inside top
@@topic jobs-procs
`top` shows the processes sorted by CPU use. Which key sorts them by memory use instead?
(+) `M` (Shift+M) :: It changes the sort column to memory use.
(-) `h` :: It opens the help screen with the list of options.
(-) `q` :: It quits `top`.
(-) `k` :: It asks for the PID of a process to send it a signal; it does not change the order.

@@q single | A whole word
@@topic grep-regex
`w` contains the lines `cat`, `concat`, `catalog` and `the cat sat`. Which command prints only the lines that contain `cat` as a whole word?
(-) `grep cat w` :: It matches `cat` anywhere, so it prints all four lines.
(-) `grep '\<cat' w` :: It anchors only the beginning of the word, so `catalog` also matches.
(-) `grep '^cat$' w` :: It matches only a line that is exactly `cat`, and misses `the cat sat`.
(+) `grep -w cat w` :: `-w` requires the match to be a whole word, giving `cat` and `the cat sat`.

@@q single | Writing through a link to a directory
@@topic files-fs
```
mkdir d; echo 1 > d/f
ln -s d link
echo 2 >> link/f
cat d/f
rm link
ls d
```
What does this print?
(-) `1`, `2` and then nothing for `ls`, because `rm link` removed the directory. :: `rm` on a symbolic link removes only the link.
(-) `1` and `f`, because `link/f` is a different file. :: `link/f` is `d/f`, reached through the link, so the line `2` is added to it.
(+) `1`, `2` and `f` :: The append goes through the link to `d/f`; removing the link leaves `d` and its file untouched.
(-) `2` and `f`, because `>>` replaces the content. :: `>>` appends, so `1` stays.

@@q single | Command substitution
@@topic expansion-vars
Which statement about command substitution is FALSE?
(-) `n=$(ls | wc -l)` stores the number of entries in `n`. :: True: the output of the command replaces `$( )`.
(-) `echo "Hi $(whoami)"` is expanded even between double quotes. :: True: double quotes allow substitutions.
(-) Backticks, as in `` `date` ``, do the same as `$(date)`. :: True: it is the older syntax for the same thing.
(+) `echo '$(date)'` prints the current date. :: False: single quotes prevent the substitution, so it prints the text `$(date)`.

@@q single | tee, paste and split
@@topic filters
Which statement about `tee`, `paste` and `split` is FALSE?
(-) `ls | tee list.txt` shows the listing on the screen and also saves it in `list.txt`. :: True: `tee` writes its input to the file and to stdout.
(-) `split -l 2 f` cuts `f` into pieces of two lines each, named `xaa`, `xab`, and so on. :: True.
(-) `paste a b` joins line 1 of `a` with line 1 of `b`, separated by a tab, then the lines 2, and so on. :: True: it pastes the files side by side.
(+) `paste a b` prints all of `a` and then all of `b`. :: False: that is what `cat a b` does.
