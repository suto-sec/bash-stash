@@q single | Owner with write permission only
@@topic permissions
You own `data.txt`, a regular file whose mode is `--w-------`. What does `cat data.txt` do?
(-) It prints the contents, because the owner of a file can always read it. :: Being the owner gives no permission by itself: the bits decide, and `r` is missing.
(+) It fails with `Permission denied`: reading needs `r` and the file only has `w`. :: `cat` must read the file; `w` alone does not allow it (appending with `>>` would work).
(-) It prints nothing and ends successfully, because a write-only file shows nothing. :: `cat` reports an error and returns a non-zero status; it does not silently succeed.
(-) It prints the contents, because `cat` only needs `x` or `w` on the file to open it. :: Reading needs `r`; `x` is for running the file and `w` for changing it.

@@q single | Builtin or external
@@topic shell-help
Which statement about builtin and external commands is FALSE?
(+) To run a builtin such as `jobs`, the shell searches `PATH` for an executable file called `jobs`. :: False: a builtin is implemented inside the shell, so no file is searched for or started.
(-) `ls` and `cp` are external commands: each is a program file that the shell finds through `PATH`. :: True: they are programs on disk, for example `/usr/bin/ls`.
(-) `type cd` answers that `cd` is a shell builtin. :: True: `type` tells how the shell would interpret a name.
(-) `whereis ls` shows the path of the executable of `ls` and of its manual pages. :: True: it prints entries such as `/usr/bin/ls` and `/usr/share/man/man1/ls.1.gz`.

@@q single | Adding a user to a group
@@topic users-sessions
On a Debian-like system the user `marta` and the group `lab` already exist. Which command makes `marta` a member of `lab`?
(-) `addgroup lab marta` :: `addgroup` creates groups; with two arguments it refuses ("unspecified operation").
(-) `deluser marta lab` :: It does the opposite: it removes `marta` from the group `lab`.
(+) `adduser marta lab` :: `adduser user group` adds an existing user to an existing group.
(-) `adduser lab marta` :: The arguments are in the wrong order: it looks for a user called `lab`, which does not exist.

@@q single | Aliases
@@topic expansion-vars
Which statement about aliases in bash is TRUE?
(-) `unalias ll` deletes the program called `ll` from the disk. :: It only removes the alias from the current shell; no file is touched.
(-) An alias typed at the prompt is saved automatically and is available in every terminal opened later. :: To keep it you have to write it in a startup file such as `~/.bashrc`.
(-) `alias` with no arguments deletes all the aliases of the session. :: With no arguments it lists the aliases that are defined.
(+) After `alias ll='ls -l'`, typing `ll /tmp` runs `ls -l /tmp`. :: The shell replaces the first word with the alias text and keeps the rest of the line.

@@q single | Fields with cut
@@topic filters
`echo 'tea,milk,rice,salt' | cut -d, -f2,4` is run. Which statement is FALSE?
(+) The output is `milk salt`: `cut` joins the fields with a space. :: False: `cut` keeps the input delimiter, so the output is `milk,salt`.
(-) `cut -d, -f3` on the same line prints `rice`. :: True: `-f3` selects the third field.
(-) `cut -d, -f2-3` on the same line prints `milk,rice`, the second and third fields. :: True: a range selects consecutive fields and keeps the delimiter between them.
(-) `cut -c5-8` on the same line prints `milk`, characters 5 to 8 of the line. :: True: `-c` selects characters by position; characters 5 to 8 are `milk`.

@@q single | UEFI and legacy BIOS
@@topic boot-systemd
Which statement about UEFI and the legacy BIOS is TRUE?
(-) UEFI is the older firmware, and the BIOS replaced it by adding Secure Boot. :: It is the other way round: UEFI is the successor of the BIOS.
(+) UEFI replaces the BIOS and can work with GPT disks and offer Secure Boot. :: Secure Boot lets the firmware refuse boot software that is not signed.
(-) UEFI only boots from MBR disks, while GPT disks are used only by the legacy BIOS. :: Swapped: GPT is the partition table that goes with UEFI, and MBR with the BIOS.
(-) Secure Boot encrypts the disk, so its files cannot be read without the owner's password. :: Secure Boot checks signatures of the boot software; it does not encrypt anything.

@@q single | Default streams
@@topic redirection-pipes
Which line describes correctly where the three standard streams of a command go by default when it is run at a terminal?
(-) stdin (0) is read from the file named in the first argument, stdout (1) goes to the screen and stderr (2) goes to the screen. :: Without `<`, stdin is the keyboard; a file argument is something the command itself opens.
(-) stdin (0) is the keyboard, stdout (1) goes to the screen and stderr (2) is discarded unless it is redirected. :: Errors are not discarded: stderr also goes to the screen by default.
(-) stdin (1) is the keyboard, stdout (0) goes to the screen and stderr (2) goes to the screen. :: The numbers are swapped: 0 is stdin and 1 is stdout.
(+) stdin (0) is the keyboard, and both stdout (1) and stderr (2) go to the screen. :: Both outputs go to the terminal unless redirected, which is why `2>` is useful to separate the errors.

@@q single | rmdir after mkdir -p
@@topic files-fs
In an empty directory you run `mkdir -p a/b` and then `rmdir a`. What happens?
(-) Both `a` and `b` are removed, because `b` is empty and `rmdir` removes a directory with its empty subdirectories. :: `rmdir` only removes the directory it is given, and only if that one is empty.
(-) `rmdir` asks for confirmation and removes `a` with `b` inside it if you answer `y`. :: `rmdir` never asks; deleting a directory with content needs `rm -r`.
(+) `rmdir` fails with "Directory not empty", because `a` still contains `b`. :: `-p` of `mkdir` created both levels; `rmdir` removes only empty directories and `a` holds `b`.
(-) Only `a` is removed, and `b` stays in the current directory. :: Nothing is moved; the command fails and both directories remain.

@@q single | Copying with -u
@@topic files-fs
`src/notes.txt` is older than `dest/notes.txt`. What does `cp -u src/notes.txt dest/` do?
(-) It overwrites `dest/notes.txt` with the old file, because `-u` means "unconditional". :: `-u` means "update": it copies only when the source is newer or the destination is missing.
(-) It asks `overwrite 'dest/notes.txt'?` and waits for `y` or `n`. :: That is `-i` (interactive).
(-) It keeps both versions: the old one is saved as `notes.txt~` and the source is copied. :: Backups need `-b`; `-u` does not create any.
(+) It does nothing: the destination is newer, so it is left untouched. :: `-u` skips the copy when the destination is at least as recent as the source.

@@q single | Environment after running a script
@@topic scripts
`setup.sh` contains the single line `export MODE=test`, and it has execute permission. Which statement is TRUE?
(-) After `./setup.sh`, `echo $MODE` prints `test`, because the variable was exported. :: `./setup.sh` runs in a child shell; `export` passes the variable only to that child's own children, never back to the parent.
(+) After `. setup.sh`, `echo $MODE` prints `test` in your current shell. :: `.` (same as `source`) runs the lines in the current shell, so the variable stays.
(-) After `bash setup.sh`, `echo $MODE` prints `test`, because `bash` runs the script with the current environment. :: It starts a new shell: the variable disappears when it ends.
(-) After `. setup.sh`, `echo $MODE` prints nothing, because `.` runs the script in a child shell. :: `.` does not create a child; that is what `./` and `bash` do.
