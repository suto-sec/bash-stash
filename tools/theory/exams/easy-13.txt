@@q single | The actions of find
@@topic find
Which statement about `find` actions is FALSE?
(-) `find . -name '*.tmp' -exec rm {} \;` runs `rm` once for each file found. :: True: `{}` is replaced by the name of each file.
(-) `find . -name '*.log' -exec ls -l {} +` passes many file names to a single `ls`. :: True: with `+` the names are grouped, as `xargs` does.
(-) `find . -name '*.tmp' -delete` removes every file that matches. :: True.
(+) `find . -name '*.tmp' -delete` asks for confirmation before removing each file. :: False: `-delete` removes at once, without asking; the action that asks is `-ok`.

@@q single | What an alias does
@@topic expansion-vars
After typing `alias hi='echo hello'` in an interactive shell, what does `hi world` print?
(+) `hello world` :: The shell replaces the word `hi` by `echo hello` and keeps the rest of the line.
(-) `hi: command not found` :: The alias is known by the shell, so `hi` is replaced before the shell looks for a command.
(-) `world` :: Only the alias name is replaced; the arguments stay in the line and `echo` prints them.
(-) `hello` :: The arguments written after the alias are not lost: they are appended to the expansion.

@@q single | One redirection for two commands
@@topic redirection-pipes
Which command writes the output of both `echo one` and `echo two` into the file `out.txt`?
(+) `{ echo one; echo two; } > out.txt` :: The braces group the commands, and the redirection applies to the output of the whole group.
(-) `echo one; echo two > out.txt` :: Only `echo two` is redirected; `one` goes to the screen.
(-) `echo one | echo two > out.txt` :: `echo` ignores its input: the file contains only `two`.
(-) `echo one && echo two > out.txt` :: The redirection still affects only the second command.

@@q single | Matching words
@@topic grep-regex
In a list of English words, which statement about `grep '^c.t$' words` is TRUE?
(+) It prints the three-letter words that start with `c` and end with `t`, such as `cat` or `cut`. :: `^` and `$` fix the start and the end of the line, and the dot stands for exactly one character.
(-) It prints the words that contain the text `c.t` with a real dot. :: To search for a literal dot it must be written `\.`.
(-) It prints every word that starts with `c` or ends with `t`. :: The pattern requires both conditions and exactly one letter between them.
(-) It prints words of any length that start with `c` and end with `t`, such as `cart`. :: The dot matches one character, so `cart` (two letters between `c` and `t`) does not match.

@@q single | Kernel messages at boot
@@topic boot-systemd
Which command shows the messages that the kernel printed while the system was starting?
(+) `dmesg` :: It prints the kernel ring buffer: hardware detection, drivers loaded, the root file system being mounted...
(-) `last` :: It lists the past logins of the users, read from `/var/log/wtmp`.
(-) `history` :: It lists the commands typed in the current shell.
(-) `uname -a` :: It prints the name and version of the kernel, not the messages it wrote.

@@q single | Names in any case
@@topic files-fs
Linux treats `Notes.TXT` and `notes.txt` as different files. Which command lists both?
(+) `find . -iname notes.txt` :: `-iname` ignores the difference between upper and lower case in the name.
(-) `find . -name notes.txt` :: `-name` is case sensitive: it finds only `notes.txt`.
(-) `find . -name 'notes.TXT'` :: It finds only the file with exactly that spelling.
(-) `find . -name notes.txt -i` :: `-i` is not an option of `find`; it fails with "unknown predicate".

@@q single | Foreground jobs
@@topic jobs-procs
Which statement defines a foreground job?
(+) The job that owns the terminal: the shell waits for it before the next prompt. :: Only one job at a time can be in the foreground; `Ctrl+C` and `Ctrl+Z` act on it.
(-) A job that runs with a higher priority than the others. :: Foreground and background say nothing about priority.
(-) A job that has no terminal and is started at boot. :: That describes a daemon.
(-) A job that keeps running after the user logs out. :: That is what `nohup` is for.

@@q single | The || operator
@@topic shell-help
In `cmd1 || cmd2`, when is `cmd2` run?
(+) Only when `cmd1` fails, that is, ends with a status different from 0. :: `||` means "or else": the second command is a fallback.
(-) Only when `cmd1` succeeds. :: That is what `&&` does.
(-) Always, after `cmd1` has finished. :: That is what `;` does.
(-) At the same time as `cmd1`, in the background. :: Running at the same time is what `&` or a pipe does.

@@q single | Deleting needs the directory
@@topic permissions
Which statement about deleting the file `docs/old.txt` is FALSE?
(-) To delete it you need write and execute permission on the directory `docs`. :: True: deleting changes the directory, which lists the names.
(-) A file with mode `r--r--r--` can be deleted if you have write permission on its directory. :: True: the permissions of the file are not consulted.
(-) If `docs` has mode `r-xr-xr-x` you cannot delete the file, even if you own it. :: True: nobody has write permission on the directory.
(+) You can delete it only if you have write permission on the file itself. :: False: the permission that matters is the one of the directory that contains the name.

@@q single | The read command
@@topic scripts
What does `read -p "Name: " n` do in a script?
(+) It prints the prompt `Name: ` and stores the typed line in the variable `n`. :: `-p` gives the prompt text and the first word after the options is the variable that receives the input.
(-) It reads the content of a file called `Name: ` into the variable `n`. :: `read` reads standard input, not a file named by `-p`.
(-) It prints `Name: ` and the value of `n`. :: It does not print the variable; it assigns it.
(-) It pipes the output of the previous command into `n`. :: `-p` has nothing to do with pipes.
