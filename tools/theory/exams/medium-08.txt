@@q single | cd inside a script
@@topic jobs-procs
`s.sh` is executable and its only line is `cd /tmp`. From `/home/ana` you run `./s.sh` and then `pwd`. What does `pwd` print?
(+) `/home/ana` :: The script runs in a child shell; `cd` changes the directory of that shell, which ends with the script.
(-) `/tmp` :: The directory of a process is not shared with its parent: the change is lost when the script ends.
(-) `/tmp`, because `cd` is an external program that changes the directory of the system. :: `cd` is a shell builtin and it only affects the shell that executes it.
(-) An error, because `cd` cannot be used inside a script. :: It can be used; it just has no effect on the parent shell.

@@q single | Counting the groups
@@topic users-sessions
For the user `alumno` the command `id -Gn` prints `alumno adm cdrom sudo audio video secops`. What does `id -Gn | wc -w` print?
(+) `7` :: `-G` lists all the groups, the primary one included, and `wc -w` counts the 7 words of the line.
(-) `6` :: The primary group `alumno` is in the list too, so it is not 6.
(-) `1` :: `wc -w` counts words, not lines: the output is one line but seven words.
(-) `8` :: There are seven names in the list, not eight.

@@q single | Switching targets
@@topic boot-systemd
Which statement about `systemd` is FALSE?
(-) A unit file describes a service, a mount point, a timer or another resource that systemd manages. :: True: they are the `.service`, `.mount`, `.timer`... files.
(-) A target groups units and plays the role that the runlevels had in SysV init. :: True: `multi-user.target` is similar to the old runlevel 3.
(-) `systemd` uses control groups (cgroups) to keep track of all the processes of a service. :: True: that is how it can stop every process of a service.
(+) `systemctl isolate multi-user.target` powers the machine off. :: False: it switches to that target, stopping the units that do not belong to it. Powering off is `systemctl poweroff`.

@@q single | Archives and compression
@@topic files-fs
Which statement about `tar` and compression is FALSE?
(-) `tar -cf docs.tar docs` creates an archive without compressing it. :: True: without `z` there is no compression.
(-) `tar -czf docs.tgz docs` creates a gzip-compressed archive. :: True.
(-) `tar -tf docs.tar` lists the content of the archive without extracting it. :: True.
(+) `gzip docs` compresses the directory `docs` into `docs.gz`. :: False: `gzip` compresses files, not directories; it answers "docs is a directory -- ignored". A directory must be packed with `tar` first.

@@q single | A long command on two lines
@@topic shell-help
You are typing a long command and want to continue it on the next physical line. What do you do at the end of the first line?
(+) Type a backslash `\` and press Enter. :: The backslash removes the newline, so the shell reads both lines as one command.
(-) Type a semicolon `;` and press Enter. :: The semicolon ends the command: the second line would run as a separate command.
(-) Type a slash `/` and press Enter. :: A slash is just part of the last word.
(-) Type an ampersand `&` and press Enter. :: `&` runs the first part in the background and then reads a new command.

@@q single | uniq on unsorted data
@@topic filters
`names` has the lines `b`, `a`, `b`, `c`, `a` (in that order). What happens with `uniq names | wc -l`?
(+) It prints `5`: `uniq` only collapses equal lines that are adjacent. :: No two equal lines are adjacent here, so nothing is removed.
(-) It prints `3`, the number of different names. :: That is what `sort names | uniq | wc -l` prints.
(-) It prints `2`, the number of names that are repeated. :: `uniq` does not count repetitions unless `-c` is used.
(-) It fails, because `uniq` needs sorted input. :: It accepts any input; it just may not remove all the duplicates.

@@q single | A useless cat
@@topic redirection-pipes
Compare `cat f | sort | uniq -c` with `sort f | uniq -c`. Which statement is correct?
(+) They print the same, but the first starts an extra process (`cat`) that adds nothing. :: `sort` can read the file by itself, so the `cat` only copies the data into the pipe.
(-) The first one counts the repeated lines and the second does not. :: Both end in `uniq -c`, so both count.
(-) The second fails, because `sort` cannot read a file given as an argument. :: `sort` reads files given as arguments, and its standard input when there are none.
(-) The output of the first is sorted and that of the second is not. :: Both pipelines sort before `uniq`.

@@q single | Counting down
@@topic scripts
Which line prints `3`, `2` and `1`, one number per line?
(+) `i=3; while [ $i -ge 1 ]; do echo $i; i=$((i-1)); done` :: The loop runs while `i` is at least 1 and decrements it each time.
(-) `i=3; until [ $i -ge 1 ]; do echo $i; i=$((i-1)); done` :: `until` stops as soon as the condition is true, and `3 -ge 1` is true at once: nothing is printed.
(-) `i=3; while [ $i -le 1 ]; do echo $i; i=$((i-1)); done` :: `3 -le 1` is false at the start, so the body never runs.
(-) `i=3; while [ $i -ge 1 ]; do echo $i; done` :: `i` never changes, so it prints `3` for ever.

@@q single | The root of the tree and root's home
@@topic files-fs
Which statement compares the directories `/` and `/root` correctly?
(+) `/` is the top of the single directory tree, and `/root` is the home directory of the user `root`. :: Every file of the system is below `/`; `/root` is just one directory in it.
(-) They are two names for the same directory. :: `/` contains `/root`, `/home`, `/etc` and everything else.
(-) `/root` is the top of the tree and `/` is the home directory of root. :: It is the other way round.
(-) `/root` is the top of the tree of each user, as `/home` is for the others. :: `/root` is the home of one user; the tree of the whole system has a single top, `/`.

@@q single | Variables and wildcards
@@topic expansion-vars
The current directory has only the files `a` and `b`. What does `name='*'; echo "$name" $name` print?
(+) `* a b` :: The quoted `"$name"` stays as the text `*`; the unquoted `$name` is expanded to `*` and then the wildcard is expanded to the file names.
(-) `* *` :: The wildcard of the unquoted variable is expanded after the variable: it becomes `a b`.
(-) `a b a b` :: The quotes stop the expansion of the wildcard in the first word.
(-) `a b *` :: The order of the two words is `"$name"` first and `$name` second.
