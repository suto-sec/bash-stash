@@collection 06_grep_regex | grep y expresiones regulares
@@about
Buscar texto con grep: sus opciones y su valor de retorno, expresiones regulares básicas y extendidas, anclas, corchetes, repeticiones, grupos, y en qué se diferencian las expresiones regulares de los comodines de la shell.

@@group Lo básico de grep
@@q single | Qué hace grep
¿Qué imprime `grep patron fichero`?
(+) Cada línea de `fichero` que contiene texto que coincide con `patron`. :: Selecciona líneas completas; no imprime solo la palabra que coincide salvo que lo pidas con `-o`.
(-) Los nombres de los ficheros que contienen el patrón, sin las líneas. :: Eso es `grep -l`, o `grep -r` con un directorio.
(-) Solo la primera coincidencia de todo el fichero, y después deja de leer. :: Se imprimen todas las líneas que coinciden (salvo que `-m` las limite).
(-) El número de coincidencias, en lugar de las líneas que contienen el patrón. :: Eso es `grep -c`.

@@q single | De dónde sale el texto
¿Qué hace `grep root` sin ningún fichero como operando?
(+) Lee la entrada estándar, así que se puede usar en medio de una tubería. :: Por ejemplo `ps aux | grep root`.
(-) Busca la palabra en todo el sistema de ficheros, empezando por `/`. :: Eso es `grep -r root /`.
(-) Falla con el error «missing file», porque no se dio ningún fichero en el que buscar. :: Como la mayoría de filtros, recurre a la entrada estándar.
(-) Busca en todos los ficheros del directorio actual, sin entrar en los subdirectorios. :: No sin `-r`.

@@q match | Opciones habituales de grep
Empareja cada opción con su efecto.
(=) `-i` => Ignorar mayúsculas y minúsculas :: Coinciden `Root`, `ROOT` y `root`.
(=) `-v` => Invertir: imprimir las líneas que NO coinciden :: Una forma de descartar cosas.
(=) `-c` => Imprimir el número de líneas que coinciden :: No las propias líneas.
(=) `-n` => Poner delante de cada línea su número de línea :: Útil para encontrar el sitio en un editor.
(=) `-l` => Imprimir solo los nombres de los ficheros con alguna coincidencia :: Un nombre por fichero.
(-) Editar las líneas que coinciden :: `grep` nunca cambia su entrada.

@@q match | Más opciones de grep
Empareja cada opción con su efecto.
(=) `-r` => Buscar en los directorios de forma recursiva :: Entra en los subdirectorios.
(=) `-o` => Imprimir solo la parte de cada línea que coincide :: Cada coincidencia en su propia línea.
(=) `-w` => Coincidir solo con palabras completas :: `cat` ya no coincide con `concatenate`.
(=) `-x` => La línea entera tiene que coincidir :: Más estricto que `-w`.
(=) `-F` => Tratar el patrón como una cadena fija, no como una expresión regular :: Los puntos y los asteriscos pierden su significado.
(-) Sustituir la coincidencia por otro texto :: Sustituir es cosa de `sed`.

@@q multi | Opciones que cambian lo que se imprime
Marca las opciones que hacen que `grep` imprima algo distinto de las líneas que coinciden.
(+) `-c` :: Imprime una cuenta.
(+) `-l` :: Imprime nombres de fichero.
(+) `-o` :: Imprime solo el texto que coincide.
(-) `-i` :: Solo cambia cómo se hace la comparación.
(-) `-E` :: Solo elige el dialecto de expresiones regulares.

@@q single | Valor de retorno de grep
¿Qué valor de retorno devuelve `grep` cuando no encuentra ninguna coincidencia en un fichero que sí se puede leer?
(+) 1 :: 0 significa al menos una coincidencia, 1 ninguna y 2 un error (por ejemplo un fichero que no existe).
(-) 0 :: Significa que alguna línea coincidió.
(-) 2 :: Es para los errores.
(-) 255 :: grep no lo usa.

@@q match | Valores de retorno de grep
Empareja cada mandato con su valor de retorno.
(=) `grep root /etc/passwd` (está) => 0 :: Se encontró una coincidencia.
(=) `grep zzzqqq /etc/passwd` => 1 :: No coincidió nada.
(=) `grep root /no/existe` => 2 :: Error: no se pudo leer el fichero.
(-) 3 :: Ninguno de estos lo produce.

@@q single | Modo silencioso
¿Qué hace `grep -q root /etc/passwd`, y por qué es útil en un `if`?
(+) No imprime nada y solo fija el valor de retorno, así que `if grep -q ...; then` puede comprobar si hay un patrón. :: Además, `-q` para en la primera coincidencia.
(-) Imprime la línea que coincide sin los colores que `grep` suele añadirle. :: `-q` no imprime nada.
(-) Entrecomilla el patrón para la shell, de modo que sus caracteres especiales quedan a salvo. :: El entrecomillado lo hace la shell.
(-) Busca más rápido porque ignora las mayúsculas y minúsculas del fichero y del patrón, lo que se ahorra algunas comparaciones. :: No afecta a las mayúsculas.

@@q single | Mayúsculas y cuenta
¿Qué mandato cuenta cuántas líneas contienen `error` escrito con cualquier combinación de mayúsculas?
(+) `grep -ic error log` :: Opciones combinadas: ignorar mayúsculas y contar.
(-) `grep -c error log | sort` :: Solo cuenta las coincidencias exactas en minúsculas.
(-) `grep -n error log` :: Imprime líneas con números, no una cuenta.
(-) `grep -v error log` :: Imprime las líneas que no tienen la palabra.

@@q single | Quitar el ruido
¿Qué mandato muestra las líneas de `config` que no son comentarios (los comentarios empiezan por `#`)?
(+) `grep -v '^#' config` :: `-v` invierte; `^#` coincide con las líneas que empiezan por almohadilla.
(-) `grep '^#' config` :: Eso muestra *solo* los comentarios.
(-) `grep -c '#' config` :: Cuenta las líneas que contienen una almohadilla.
(-) `grep -l '#' config` :: Imprime el nombre del fichero.

@@q single | Buscar en un árbol
¿Qué mandato lista los ficheros que cuelgan de `/etc` que contienen el texto `ssh`, imprimiendo solo los nombres?
(+) `grep -rl ssh /etc` :: Recursivo y solo los nombres.
(-) `grep ssh /etc` :: Sin `-r`, grep protesta porque `/etc` es un directorio.
(-) `grep -c ssh /etc` :: También da el error de directorio, e imprimiría cuentas.
(-) `ls /etc | grep ssh` :: Busca en los *nombres* de los ficheros, no en su contenido.

@@q single | grep sobre nombres frente a contenido
¿Qué diferencia hay entre `ls | grep foo` y `grep foo *`?
(+) El primero filtra los nombres de fichero que contienen `foo`; el segundo busca dentro de cada fichero del directorio. :: Nombres frente a contenido.
(-) Hacen lo mismo, porque `grep` siempre mira los nombres de los ficheros. :: Miran datos distintos.
(-) El primero busca dentro de los ficheros del directorio, mientras que el segundo solo mira sus nombres. :: Es al revés.
(-) El segundo solo funciona cuando el argumento es un directorio y falla con ficheros normales. :: Funciona sobre los ficheros que coinciden con el comodín `*`.

@@q single | Varios ficheros
Cuando `grep root /etc/passwd /etc/group` busca en dos ficheros, ¿cómo cambia la salida respecto a un solo fichero?
(+) Cada línea lleva delante el nombre del fichero del que viene. :: Usa `-h` para ocultar los nombres.
(-) La salida se ordena alfabéticamente, con las líneas de los dos ficheros mezcladas. :: El orden sigue el de los ficheros dados.
(-) Solo se busca en el primer fichero, y `grep` ignora el segundo. :: Busca en todos.
(-) Las líneas idénticas encontradas en los dos ficheros se funden en una sola línea de salida. :: Eso sería `sort -u`.

@@q single | Líneas de contexto
¿Qué añade `grep -C 2 error log` a la salida?
(+) Dos líneas de contexto antes y después de cada línea que coincide. :: `-B` es antes, `-A` después y `-C` las dos cosas.
(-) Dos líneas coincidentes más tras la primera coincidencia, y después deja de buscar. :: Eso sería `-m`.
(-) Una cuenta de dos coincidencias, impresa al final de la salida de `grep`. :: No es una cuenta.
(-) Las dos últimas líneas del fichero `log`, además de las líneas que coinciden. :: Eso es `tail`.

@@q match | Opciones de contexto
Empareja cada opción con su efecto.
(=) `-A 3` => Imprimir también 3 líneas después de cada coincidencia :: «After», después.
(=) `-B 3` => Imprimir también 3 líneas antes de cada coincidencia :: «Before», antes.
(=) `-C 3` => 3 líneas antes y después :: «Context», contexto.
(=) `-m 3` => Parar tras 3 líneas coincidentes :: «Max count», cuenta máxima.
(-) Saltarse las 3 primeras líneas :: Eso es `tail -n +4`.

@@group Expresiones regulares básicas
@@q single | Patrón frente a comodín
¿Cuál es la diferencia más importante entre una expresión regular y un comodín de la shell (glob)?
(+) Un comodín se compara con *nombres de fichero* y lo expande la shell; una expresión regular se compara con *texto* y la usan programas como `grep`. :: Además, sus símbolos significan cosas distintas.
(-) No hay diferencia: los dos usan los mismos símbolos con el mismo significado en todas partes. :: `*` significa «cualquier cosa» en un comodín pero «repite el elemento anterior» en una expresión regular.
(-) Las expresiones regulares solo funcionan dentro de scripts, mientras que los comodines funcionan en el prompt. :: Funcionan en la línea de mandatos.
(-) Los comodines son más potentes que las expresiones regulares, porque la shell es un lenguaje completo y los expande antes de que se ejecute ningún otro programa. :: Las expresiones regulares son mucho más expresivas.

@@q match | El asterisco en comodines y expresiones regulares
Empareja cada patrón con aquello con lo que coincide.
(=) comodín `*.txt` => Cualquier nombre de fichero que termine en `.txt` :: `*` representa cualquier secuencia de caracteres.
(=) expresión regular `a*` => Cero o más letras `a` :: `*` repite el elemento anterior.
(=) expresión regular `.*` => Cualquier texto, incluido el vacío :: Un punto seguido de un asterisco: cualquier carácter, repetido.
(=) comodín `?` => Exactamente un carácter de un nombre de fichero :: Un comodín de un solo carácter.
(=) expresión regular `.` => Exactamente un carácter cualquiera :: La versión en expresión regular del comodín `?`.
(-) Un asterisco literal :: Para eso hay que escaparlo: `\*`.

@@q single | El punto
En una expresión regular, ¿con qué coincide `.`?
(+) Con un carácter cualquiera. :: Usa `\.` para un punto literal.
(-) Solo con un punto literal. :: Para eso hace falta una barra invertida.
(-) Con cero o más caracteres. :: Eso es `.*`.
(-) Con el final de una línea. :: Eso es `$`.

@@q fill | Punto literal
Para que coincida el texto `c.t` pero **no** `cat`, escapa el punto: `grep 'c{{\. ;; [.]}}t' fichero`
(x) . :: Sin escapar, el punto coincide con cualquier carácter, así que `cat` también coincidiría.
@@note
Dentro de un corchete la mayoría de caracteres especiales pierden su significado, así que `[.]` es una forma igual de buena.

@@q single | Anclas
¿Con qué coinciden `^` y `$` en una expresión regular?
(+) Con el principio y el final de una línea. :: No coinciden con caracteres, sino con posiciones.
(-) Con un acento circunflejo literal y un dólar literal. :: Sin más contexto son anclas.
(-) Con el principio y el final de una palabra. :: Los límites de palabra son `\<` y `\>`.
(-) Con el principio y el final del fichero. :: `grep` trabaja línea a línea.

@@q match | Patrones anclados
Empareja cada patrón con las líneas que selecciona.
(=) `^root` => Líneas que empiezan por `root` :: El circunflejo ancla el principio.
(=) `bash$` => Líneas que terminan en `bash` :: El dólar ancla el final.
(=) `^$` => Líneas vacías :: El principio seguido inmediatamente del final.
(=) `^root$` => Líneas que son exactamente `root` :: Anclada por los dos extremos.
(-) Líneas que contienen un circunflejo :: `^` necesitaría escaparse o ir en un corchete: `[\^]`.

@@q single | Contar líneas vacías
¿Qué mandato cuenta las líneas vacías de un fichero?
(+) `grep -c '^$' fichero` :: El principio de línea seguido directamente del final de línea.
(-) `grep -c '$' fichero` :: Toda línea tiene final, así que cuenta todas las líneas.
(-) `grep -c '^' fichero` :: También coincide con todas las líneas.
(-) `grep -c ' ' fichero` :: Cuenta las líneas que contienen un espacio.

@@q sort | Qué líneas selecciona `^[A-Z]`
@@buckets Coincide | No coincide
El patrón `^[A-Z]` exige que la línea empiece por una letra mayúscula. Clasifica cada línea.
(Coincide) `Root login` :: Empieza por `R`.
(Coincide) `X` :: Basta una sola letra mayúscula.
(Coincide) `Zebra crossing` :: Empieza por `Z`.
(No coincide) `root login` :: La primera letra es minúscula.
(No coincide) ` Root` :: Hay un espacio al principio: el primer carácter no es una mayúscula.
(No coincide) `3 Roots` :: Empieza por un dígito.

@@q single | Expresión entre corchetes
¿Con qué coincide el patrón `b[ae]g`?
(+) Con `bag` y `beg` :: Exactamente un carácter del conjunto que hay entre los corchetes.
(-) Con `baeg` :: Un corchete coincide con un único carácter.
(-) Con `bg` :: Hace falta un carácter del conjunto.
(-) Con `b[ae]g` literalmente. :: Los corchetes son especiales.

@@q match | Corchetes en la práctica
Empareja cada patrón con aquello con lo que coincide.
(=) `[aeiou]` => Una vocal :: Una lista de caracteres.
(=) `[0-9]` => Un dígito :: Un rango.
(=) `[^0-9]` => Un carácter que no es un dígito :: El circunflejo dentro del corchete niega.
(=) `[A-Za-z]` => Una letra ASCII :: Dos rangos.
(=) `[[:space:]]` => Un espacio, un tabulador u otro carácter en blanco :: Una clase de caracteres POSIX.
(-) Una palabra formada por vocales :: Un corchete coincide con un solo carácter; repítelo con `*` o `+` para una palabra.

@@q single | Significados del circunflejo
¿Cuáles son los dos significados distintos del circunflejo `^` en una expresión regular?
(+) Fuera de los corchetes ancla el principio de una línea; como primer carácter dentro de unos corchetes niega el conjunto. :: `^a` frente a `[^a]`.
(-) Siempre niega el patrón que le sigue, tanto dentro como fuera de los corchetes. :: Solo dentro de un corchete.
(-) Siempre significa el principio de la línea, también cuando es el primer carácter de un corchete, donde marca igualmente el principio. :: Dentro de un corchete niega.
(-) Significa «o» entre dos alternativas, como la barra vertical en los patrones `-E`. :: Eso es `|` en las expresiones extendidas.

@@q single | El asterisco y el cero
Dadas las líneas `ac`, `abc`, `abbc`, `abbbc`, ¿con cuántas coincide `ab*c`?
(+) Con las cuatro :: `b*` significa cero o más `b`, así que incluso `ac` coincide.
(-) Con tres :: La línea `ac` tiene cero `b`, cosa que `*` permite.
(-) Con dos :: Todas las líneas encajan.
(-) Con una :: Para eso `*` tendría que ser exacto.

@@q single | Un asterisco que coincide con todo
¿Por qué `grep 'f*' fichero` imprime todas las líneas del fichero?
(+) `f*` significa cero o más `f`, y «cero `f`» coincide en cualquier posición de cualquier línea. :: Una expresión regular que puede coincidir con la cadena vacía coincide con todas las líneas.
(-) Porque `*` es un comodín que representa todos los ficheros del directorio actual. :: Eso es un comodín de la shell, no una expresión regular.
(-) Porque `grep` ignora los patrones que contienen un asterisco y lo imprime todo. :: No se ignora nada.
(-) Porque da la casualidad de que el fichero solo contiene líneas que tienen la letra `f`. :: No hace falta.

@@q single | Patrón de palabras
¿Qué patrón coincide con una línea formada por una palabra de cuatro letras que empieza por `c` y termina en `h` (como `cash`)?
(+) `^c..h$` :: Anclado: `c`, dos caracteres cualesquiera y `h`.
(-) `^c*h$` :: Cero o más `c` seguidas de `h`.
(-) `c..h` :: También coincide dentro de palabras más largas, como `catch`.
(-) `^c.h$` :: Solo hay un carácter en medio.

@@q single | Palabras completas
¿Por qué `grep -w cat` es distinto de `grep cat`?
(+) `-w` solo acepta `cat` como palabra completa, así que `concatenate` y `cats` no coinciden. :: Los caracteres de palabra a cualquiera de los lados impiden la coincidencia.
(-) `-w` coincide con palabras escritas en cualquier idioma, no solo en inglés. :: No es su propósito.
(-) `-w` escribe las palabras que coinciden en un fichero en vez de imprimirlas en pantalla. :: No.
(-) `-w` hace que la comparación no distinga mayúsculas, así que también encuentra `Cat` y `CAT`. :: Eso es `-i`.

@@q fill | Palabras de tres letras b_g
Una palabra de exactamente tres letras que empieza por `b`, termina en `g` y tiene `a` o `e` en medio: `grep -w 'b{{[ae]}}g' palabras`
(x) (a|e) :: La alternativa con paréntesis necesita `-E` (o una barra invertida) en las expresiones básicas.
(x) a|e :: Sin `-E`, `|` es un carácter normal.
@@note
Un corchete funciona en todas partes; la alternativa `a|e` necesita la sintaxis extendida.

@@q single | Corchete negado
¿Con cuáles de las palabras `bag`, `beg`, `big`, `bog` coincide `b[^ae]g`?
(+) Con `big` y `bog` :: El carácter del medio tiene que ser cualquiera salvo `a` o `e`.
(-) Con `bag` y `beg` :: Con esas coincide `b[ae]g`.
(-) Con las cuatro :: El conjunto excluye a dos de ellas.
(-) Con ninguna :: Dos de ellas encajan.

@@group Expresiones regulares extendidas y grupos
@@q single | -E
¿Qué cambia la opción `-E` (o el mandato `egrep`)?
(+) Activa las expresiones regulares extendidas, donde `+`, `?`, `|`, `{}` y `()` son operadores sin barras invertidas. :: Se leen mejor que el dialecto básico.
(-) Hace que la búsqueda no distinga mayúsculas, de modo que las mayúsculas coinciden con las minúsculas. :: Eso es `-i`.
(-) Imprime solo la parte de cada línea que coincide, en vez de la línea entera, una coincidencia por línea de salida. :: Eso es `-o`.
(-) Excluye las líneas que coinciden e imprime solo las que no contienen el patrón. :: Eso es `-v`.

@@q match | Operadores de repetición
Empareja cada operador con su significado en las expresiones regulares extendidas.
(=) `+` => Una o más veces el elemento anterior :: Al menos una.
(=) `?` => Cero o una vez el elemento anterior :: Opcional.
(=) `*` => Cero o más veces el elemento anterior :: Cualquier número, incluido ninguno.
(=) `{2,4}` => Entre dos y cuatro veces el elemento anterior :: Una repetición acotada.
(=) `{3}` => Exactamente tres veces el elemento anterior :: Una repetición exacta.
(-) Uno o más caracteres cualesquiera :: Eso sería `.+`.

@@q single | El más en básica frente a extendida
En las expresiones regulares básicas (`grep` a secas), ¿con qué coincide `a+b`?
(+) Con el texto literal `a+b`: `+` no tiene significado especial salvo que se escape (`a\+b`) o se use `-E`. :: El grep de GNU también acepta `\+`.
(-) Con una o más letras `a` seguidas de la letra `b`, como en `aab` y `ab`. :: Ese es el significado extendido.
(-) Con nada: es un patrón no válido que hace que `grep` imprima un mensaje de error. :: Es un patrón válido.
(-) Con cualquier texto, ya que el signo más representa cualquier secuencia de caracteres, así que se imprimen todas las líneas del fichero. :: No.

@@q single | Letra opcional
Dadas las líneas `ac`, `abc`, `abbc`, ¿cuáles selecciona `grep -E 'ab?c'`?
(+) `ac` y `abc` :: `b?` permite cero o una `b`.
(-) Las tres :: `abbc` tiene dos `b`.
(-) Solo `abc` :: Se permite que haya cero `b`.
(-) Ninguna :: Dos líneas encajan.

@@q single | grep a secas y la interrogación
Con las mismas líneas `ac`, `abc`, `abbc`, ¿qué imprime `grep 'ab?c'` (sintaxis básica, sin `-E`)?
(+) Nada, porque en la sintaxis básica `?` es un carácter normal y ninguna línea contiene `ab?c`. :: Usa `-E` o `ab\?c`.
(-) `ac` y `abc`, porque `?` hace opcional la letra anterior en todos los dialectos de expresiones regulares, básicas incluidas. :: Ese es el comportamiento extendido.
(-) Las tres líneas, porque `?` coincide con un carácter cualquiera en medio. :: No.
(-) Un error de patrón no válido, porque la interrogación necesita `-E`. :: El patrón es válido, solo que literal.

@@q fill | Alternativas
Imprime las líneas que contienen `cat` o `cut`: `grep -E 'cat{{|}}cut' fichero`
(x) , :: No existe un operador coma en las expresiones regulares.
(x) || :: Eso lo usa la shell entre mandatos; en una expresión regular una sola barra separa alternativas.
@@note
En la sintaxis básica, con el grep de GNU, lo mismo se escribe `cat\|cut`.

@@q single | Agrupar alternativas
¿Qué patrón coincide con una línea que sea exactamente `one` o exactamente `two`?
(+) `grep -E '^(one|two)$'` :: Los paréntesis dejan las anclas fuera de la alternativa.
(-) `grep -E '^one|two$'` :: Las anclas se unen a cada alternativa por separado: líneas que empiezan por `one` o terminan en `two`.
(-) `grep '^[one|two]$'` :: Un corchete coincide con un único carácter.
(-) `grep -E '^onetwo$'` :: Coincide con el texto `onetwo`.

@@q single | Anclas y alternativas
¿Por qué `grep -E '^root|daemon'` coincide con la línea `the daemon runs`?
(+) `^root` solo se aplica a la primera alternativa; la segunda, `daemon`, coincide en cualquier parte de la línea. :: Usa `^(root|daemon)` para anclar las dos.
(-) `-E` ignora el ancla `^`, así que el patrón coincide en cualquier posición de la línea. :: El ancla se respeta, pero solo para su alternativa.
(-) Porque `|` es un carácter literal en este patrón, así que `daemon` es solo parte de una palabra más larga que la línea tiene que contener. :: Con `-E` es el operador de alternativa.
(-) Porque da la casualidad de que la línea termina con la palabra `daemon`, que el ancla selecciona. :: Su final es irrelevante.

@@q single | Grupo repetido
¿Qué imprime `echo abcabc | grep -oE '(abc){2}'`?
(+) `abcabc` :: El grupo `abc` repetido exactamente dos veces.
(-) `abc` :: Una sola copia coincidiría con `(abc){1}`.
(-) `abcabcabc` :: La entrada solo tiene dos copias.
(-) Nada :: Hay una coincidencia.

@@q single | Referencia hacia atrás
¿Qué significa `\1` en `grep -E '(.)\1'`?
(+) Una repetición de lo que haya coincidido con el primer grupo, así que el patrón encuentra dos caracteres idénticos seguidos. :: Coincidiría con `aa` pero no con `ab`.
(-) El primer carácter de la línea, que el grupo `(.)` encuentra y luego recuerda para el resto del patrón. :: Se refiere a lo que *coincidió* con el grupo.
(-) Un dígito `1` literal, que tiene que ir detrás de un carácter cualquiera para que la línea coincida. :: Tras una barra invertida, un dígito se refiere a un grupo.
(-) El primer fichero que se le da a `grep`, del que después se imprimen las coincidencias. :: No tiene relación.

@@q fill | Forma de una dirección IP
Busca algo con forma de dirección IPv4 (cuatro grupos de dígitos separados por puntos): `grep -oE '[0-9]+(\.[0-9]+){{{3}}}'`
(x) {4} :: El primer grupo de dígitos ya está escrito; con cuatro repeticiones la dirección tendría cinco partes.
(x) * :: Aceptaría cualquier número de grupos con punto, incluido ninguno.
@@note
Un patrón así acepta números como 999.1.1.1, así que un script que valide también debería comprobar los rangos.

@@q single | ¿Extendida o básica?
¿Cuáles de estos mandatos se comportan igual?
(+) `grep -E 'a+'` y `grep 'a\+'` :: El grep de GNU admite `\+` en modo básico.
(-) `grep -E 'a+'` y `grep 'a+'` :: El segundo busca un más literal.
(-) `grep 'a|b'` y `grep -E 'a|b'` :: En la sintaxis básica, `|` es un carácter literal.
(-) `grep -E '(a)'` y `grep '(a)'` :: El segundo busca paréntesis literales.

@@group Cadenas fijas y caracteres especiales
@@q single | Búsqueda literal
Quieres encontrar las líneas que contienen exactamente el texto `1.2.3`, puntos incluidos. ¿Qué mandato es el mejor?
(+) `grep -F '1.2.3' fichero` :: `-F` toma el patrón de forma literal.
(-) `grep '1.2.3' fichero` :: Los puntos coinciden con cualquier carácter, así que `1x2y3` coincidiría.
(-) `grep -w 1.2.3 fichero` :: Sigue siendo una expresión regular.
(-) `grep -v 1.2.3 fichero` :: Invierte la selección.

@@q single | Entrecomillar los patrones
¿Por qué hay que poner entre comillas un patrón como `a*b` en la línea de mandatos?
(+) Para que la shell no trate `*` como comodín de nombres de fichero antes de que `grep` lo vea. :: Sin comillas, `a*b` puede expandirse a nombres de ficheros existentes.
(-) Porque `grep` rechaza los patrones sin comillas e imprime un error de sintaxis. :: El problema lo causa la expansión de la shell.
(-) Porque las comillas son lo que convierte el texto en una expresión regular para `grep`. :: Los patrones son expresiones regulares por defecto.
(-) Porque las comillas hacen que la búsqueda no distinga mayúsculas, como la opción `-i`. :: Eso es `-i`.

@@q single | Buscar un dólar
¿Cómo buscas el texto literal `$HOME` en un fichero?
(+) `grep -F '$HOME' fichero` :: Las comillas simples impiden que la shell lo expanda; `-F` impide que `$` sea un ancla.
(-) `grep "$HOME" fichero` :: Las comillas dobles dejan que la shell lo sustituya por la ruta de tu directorio personal.
(-) `grep $HOME fichero` :: La misma expansión.
(-) `grep '^HOME' fichero` :: Busca líneas que empiezan por `HOME`.

@@q single | Escapar un corchete
¿Qué patrón coincide con el texto literal `[ERROR]` (con los corchetes)?
(+) `grep '\[ERROR\]' log` :: Las barras invertidas hacen literales los corchetes.
(-) `grep '[ERROR]' log` :: Coincide con cualquiera de las letras E, R u O.
(-) `grep -w [ERROR] log` :: El mismo problema del conjunto.
(-) `grep -v ERROR log` :: Invierte.

@@q single | El tabulador
Un campo de un fichero está separado por un tabulador. ¿Qué mandato encuentra de forma fiable las líneas con un tabulador?
(+) `grep -P '\t' fichero` :: `-P` activa las secuencias de escape al estilo Perl, como `\t`.
(-) `grep '\t' fichero` :: En la sintaxis básica, `\t` coincide con la letra `t`.
(-) `grep -E 't' fichero` :: Coincide con toda línea que tenga la letra `t`.
(-) `grep -F 'tab' fichero` :: Busca la palabra `tab`.

@@group Expresiones regulares en uso
@@q single | Usuarios sin shell de inicio
¿Qué mandato imprime las líneas de `/etc/passwd` cuya shell es `/usr/sbin/nologin`?
(+) `grep 'nologin$' /etc/passwd` :: La shell es el último campo; anclar al final es preciso.
(-) `grep -v 'nologin' /etc/passwd` :: Imprime lo contrario.
(-) `grep '^nologin' /etc/passwd` :: Las líneas no empiezan así.
(-) `grep -c nologin /etc/passwd` :: Imprime una cuenta.

@@q single | Usuarios con uid mayor que 999
¿Qué patrón selecciona las líneas de `/etc/passwd` cuyo tercer campo es un número de cuatro o más dígitos?
(+) `grep -E '^[^:]*:[^:]*:[0-9]{4,}:' /etc/passwd` :: Dos campos sin dos puntos, luego cuatro o más dígitos y luego dos puntos.
(-) `grep '[0-9]{4}' /etc/passwd`, con las llaves tomadas literalmente en modo básico :: Sin `-E` las llaves son literales; y coincidiría con dígitos en cualquier sitio.
(-) `grep -E '^[0-9]{4,}' /etc/passwd`, que mira el principio de la línea entera :: Mira el principio de la línea, donde está el nombre de usuario.
(-) `grep -w 1000 /etc/passwd`, que solo encuentra el número concreto 1000 :: Solo un número concreto.

@@q single | Inicios de sesión fallidos
¿Qué tubería cuenta los intentos fallidos de contraseña por SSH en un `auth.log` cuyas líneas contienen `Failed password`?
(+) `grep -c 'Failed password' /var/log/auth.log` :: `-c` cuenta las líneas que coinciden.
(-) `grep -v 'Failed password' /var/log/auth.log | wc -l` :: Cuenta las líneas que *no* coinciden.
(-) `grep -l 'Failed password' /var/log/auth.log` :: Imprime el nombre del fichero.
(-) `cat /var/log/auth.log | wc -w` :: Cuenta las palabras de todo el registro.

@@q single | Extraer las IP
¿Qué mandato imprime solo las direcciones IPv4 que aparecen en `auth.log`, una por coincidencia?
(+) `grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' auth.log` :: `-o` imprime solo la parte que coincide.
(-) `grep -E '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' auth.log` :: Imprime las líneas completas.
(-) `grep -c '[0-9]' auth.log` :: Cuenta las líneas con algún dígito.
(-) `cut -d' ' -f1 auth.log` :: Toma el primer campo de cada línea, que no tiene por qué ser una dirección.

@@q order | Los principales atacantes
Ordena las etapas para listar las cinco direcciones IP con más inicios de sesión fallidos en `auth.log`, de más a menos frecuente.
(>) `grep 'Failed password' auth.log` :: Quedarse solo con las líneas de inicios fallidos.
(>) `grep -oE '[0-9]+(\.[0-9]+){3}'` :: Extraer la dirección de cada línea.
(>) `sort | uniq -c` :: Agrupar las direcciones iguales y contarlas.
(>) `sort -nr | head -n 5` :: Ordenar por la cuenta y quedarse con las cinco primeras.

@@q single | ¿Qué expresión regular?
Tienes que encontrar las líneas que contienen la palabra `error` seguida de uno o más dígitos, como `error42`. ¿Qué patrón lo hace?
(+) `grep -E 'error[0-9]+'` :: Un corchete para un dígito, repetido al menos una vez.
(-) `grep 'error[0-9]*'` :: `*` permite cero dígitos, así que también coincide `error` a secas.
(-) `grep 'error.+'` :: Necesita `-E` y acepta cualquier cosa tras `error`, no solo dígitos.
(-) `grep -E 'error|[0-9]'` :: Coincide con las líneas que tienen cualquiera de las dos partes.

@@q single | grep y la shell
Tras `grep -r "TODO" .`, ves muchas líneas de ficheros llamados `*.bak`. ¿Cómo te saltas esos ficheros?
(+) `grep -r --exclude='*.bak' TODO .` :: El grep de GNU puede excluir los nombres de fichero que coinciden con un comodín.
(-) `grep -r TODO . -v .bak`, donde `-v` excluye los nombres de fichero que coinciden :: `-v` invierte líneas, no nombres de fichero.
(-) `grep -r TODO .bak`, que solo busca en el directorio llamado `.bak` :: Busca en un fichero o directorio llamado `.bak`.
(-) `grep -r -i TODO .`, que ignora las mayúsculas y minúsculas de los ficheros :: Las mayúsculas no son el problema.

@@group Práctica variada
@@q fill | Líneas que empiezan por mayúscula
Imprime las líneas de `fichero` que empiezan por una letra mayúscula: `grep '{{^[A-Z]}}' fichero`
(x) [A-Z] :: Sin `^` coincide con una mayúscula en cualquier parte de la línea.
(x) ^A-Z :: Sin corchetes busca el texto literal `A-Z` al principio.
@@note
`^[[:upper:]]` es la forma que respeta la configuración regional.

@@q fill | Líneas con un número
Extrae los números de uno o más dígitos con `grep -o`: `grep -oE '{{[0-9]+}}' fichero`
(x) [0-9] :: Imprime un dígito por coincidencia, no números completos.
(x) [0-9]* :: Puede coincidir con la cadena vacía y no es lo que quieres aquí.
@@note
`-o` imprime cada coincidencia en su propia línea.

@@q fill | Invertir la coincidencia
Muestra las líneas de `log` que NO contienen la palabra `DEBUG`: `grep {{-v}} DEBUG log`
(x) -c :: Cuenta las líneas que coinciden.
(x) -l :: Lista los nombres de los ficheros con alguna coincidencia.
@@note
`-v` se combina a menudo con `-i` (`-vi`).

@@q sort | ¿Coincide el patrón?
@@buckets Coincide | No coincide
El patrón es `grep -E '^[0-9]{3}-[0-9]{4}$'`. Decide para cada línea.
(Coincide) `555-1234` :: Tres dígitos, un guion, cuatro dígitos y nada más.
(Coincide) `000-0000` :: Los dígitos pueden ser cualesquiera.
(No coincide) `5551234` :: Falta el guion.
(No coincide) `555-12345` :: Cinco dígitos tras el guion, y el patrón quiere exactamente cuatro.
(No coincide) `llama 555-1234` :: Las anclas exigen que toda la línea sea el número.
(No coincide) `555-123a` :: El último carácter no es un dígito.

@@q multi | Patrones que coinciden con la palabra cat
Marca los patrones que coinciden con la línea `a cat here`.
(+) `cat` :: El texto literal está dentro de la línea.
(+) `c.t` :: El punto representa la `a`.
(+) `^a c` :: La línea empieza por `a c`.
(+) `[cb]at` :: O bien `cat` o bien `bat`.
(-) `^cat` :: La línea no empieza por `cat`.
(-) `cat$` :: La línea no termina en `cat`.

@@q order | Extraer las direcciones con inicios fallidos
Ordena las etapas para listar cada dirección IPv4 que tuvo una contraseña SSH fallida, una sola vez, con más intentos primero.
(>) `grep 'Failed password' auth.log` :: Quedarse solo con los intentos fallidos.
(>) `grep -oE '[0-9]+(\.[0-9]+){3}'` :: Sacar la dirección de cada línea.
(>) `sort | uniq -c` :: Contar los intentos por dirección.
(>) `sort -nr` :: Poner primero las más frecuentes.

@@q match | Símbolos y su significado
Empareja cada fragmento de expresión regular con lo que significa en la sintaxis extendida.
(=) `a{2,3}` => Dos o tres `a` :: Una repetición acotada.
(=) `(ab)+` => Una o más repeticiones del grupo `ab` :: El más se aplica al grupo.
(=) `[^,]*` => Cualquier número de caracteres que no sean comas :: Un corchete negado con asterisco.
(=) `\.` => Un punto literal :: La barra invertida quita el significado especial.
(=) `^$` => Una línea vacía :: El principio seguido inmediatamente del final.
(-) Cualquier carácter :: Eso es un `.` a secas.
