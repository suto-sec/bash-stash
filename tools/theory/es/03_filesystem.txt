@@collection 03_filesystem | Ficheros, directorios, enlaces y archivos
@@about
El árbol de directorios y las rutas, los i-nodos, los enlaces físicos y simbólicos, copiar, mover y borrar, montar sistemas de ficheros y espacio en disco, y archivos con tar y gzip.

@@group El árbol de directorios y las rutas
@@q single | Un solo árbol para todo
¿Cómo presenta Linux sus dispositivos de almacenamiento al usuario?
(+) Como un único árbol jerárquico que empieza en `/`, donde otros sistemas de ficheros se enganchan en directorios. :: No hay letras de unidad; un segundo disco simplemente aparece bajo algún directorio.
(-) Como árboles separados llamados `C:`, `D:`, etc., uno por cada disco o partición conectados. :: Ese es el modelo de Windows.
(-) Como una lista plana de ficheros sin directorios, ordenada por nombre y por fecha. :: Los directorios son fundamentales en Unix.
(-) Como un árbol por usuario, cada uno con su raíz en el directorio personal de ese usuario. :: Hay un único árbol para todo el sistema; los directorios personales son ramas de él.

@@q sort | ¿Absoluta o relativa?
@@buckets Ruta absoluta | Ruta relativa
Clasifica cada ruta.
(Ruta absoluta) `/usr/local/bin` :: Empieza por `/`, así que se resuelve desde la raíz estés donde estés.
(Ruta absoluta) `/` :: El propio directorio raíz.
(Ruta absoluta) `/home/alumno/../alumno/docs` :: Empieza en la raíz; el `..` de dentro no cambia eso.
(Ruta relativa) `docs/notas.txt` :: No empieza por barra: se resuelve desde el directorio actual.
(Ruta relativa) `../lib/modules` :: Parte del padre del directorio actual.
(Ruta relativa) `./run.sh` :: `.` es el directorio actual; la ruta sigue siendo relativa.

@@q match | Nombres especiales de directorio
Empareja cada notación con su significado.
(=) `.` => El directorio actual :: Se usa, por ejemplo, en `./script.sh`.
(=) `..` => El directorio padre :: Un nivel más arriba.
(=) `~` => Tu directorio personal :: La shell lo expande a `$HOME`.
(=) `~luke` => El directorio personal del usuario luke :: La shell busca a ese usuario.
(=) `-` (como en `cd -`) => El directorio anterior :: Te devuelve a donde estabas.
(-) La raíz del sistema de ficheros :: Eso es `/`, nunca `~`.

@@q single | La raíz y su padre
¿Qué hace `cd ..` si ya estás en `/`?
(+) Te quedas en `/`, porque el padre de la raíz es la propia raíz. :: No hay nada por encima de la raíz.
(-) Falla con un mensaje de error, porque el directorio raíz no tiene un padre al que ir. :: Funciona sin decir nada.
(-) Te lleva a tu directorio personal, como haría un `cd` a secas. :: Eso lo hace `cd` sin argumentos.
(-) Te lleva a `/home`, el directorio que contiene los directorios personales. :: No tiene relación.

@@q single | cd sin argumentos
¿Qué mandato te lleva siempre a tu directorio personal?
(+) `cd` (sin argumento), o `cd ~` :: Bash lee `$HOME` cuando no se indica directorio.
(-) `cd /` :: Ese es el directorio raíz.
(-) `cd .` :: Te deja en el directorio actual.
(-) `cd ..` :: Sube un nivel.

@@q multi | Formas de imprimir el directorio actual
¿Cuáles de estos imprimen el directorio de trabajo actual?
(+) `pwd` :: El mandato estándar.
(+) `echo $PWD` :: La shell guarda la ruta en esta variable.
(-) `ls` :: Lista el *contenido*, no la ruta del propio directorio.
(-) `cd` :: Cambia de directorio y no imprime nada.

@@q single | Ficheros ocultos
¿Qué afirmación sobre los ficheros ocultos es correcta?
(+) Un fichero está oculto simplemente porque su nombre empieza por un punto; `ls -a` lo muestra. :: En Unix no existe un atributo de oculto aparte.
(-) Los ficheros ocultos tienen un bit de permiso especial llamado `h` que hace que `ls` se los salte. :: No existe nada parecido.
(-) Los ficheros ocultos no los pueden abrir los usuarios normales, solo el administrador. :: Los ficheros ocultos se leen como cualquier otro.
(-) Los ficheros ocultos se guardan en una zona aparte y secreta del disco que `ls` ignora. :: Solo cambia el nombre.

@@q match | Opciones de ls
Empareja cada opción con su efecto.
(=) `ls -a` => Incluir los ficheros ocultos, también `.` y `..` :: «All», todo.
(=) `ls -A` => Incluir los ficheros ocultos, pero no `.` ni `..` :: «Almost all», casi todo.
(=) `ls -l` => Formato largo con permisos, propietario, tamaño y fecha :: Una línea de detalle por entrada.
(=) `ls -R` => Entrar recursivamente en los subdirectorios :: Lista todo el subárbol.
(=) `ls -i` => Mostrar el número de i-nodo de cada entrada :: Útil para detectar enlaces físicos.
(-) Ordenar la salida por tamaño :: Eso es `-S`, ninguna de estas.

@@q single | Primer carácter de ls -l
En la salida de `ls -l`, ¿qué te indica el primer carácter del campo de modo, la `d` de `drwxr-xr-x`?
(+) Que la entrada es un directorio. :: Un `-` sería un fichero regular y una `l` un enlace simbólico.
(-) Que la entrada se puede borrar. :: Poder borrarla depende de los permisos del directorio padre.
(-) Que la entrada es un dispositivo. :: Los dispositivos muestran `b` o `c`.
(-) Que la entrada es un fichero oculto. :: Los ficheros ocultos se reconocen por su nombre, no por esta marca.

@@q fill | Crear directorios anidados
Para crear `a/b/c` de una vez, aunque todavía no existan `a` ni `b`: `mkdir {{-p}} a/b/c`
(x) -r :: `-r` no es una opción de `mkdir`; `-r` es para la recursión en `cp`, `rm` y `ls -R`.
(x) -a :: `mkdir` no tiene esa opción.
@@note
Sin `-p`, `mkdir a/b/c` falla si falta `a/b`.

@@q single | Borrar un directorio
¿Qué afirmación sobre `rmdir` es correcta?
(+) Solo borra un directorio si está vacío. :: Para borrar un directorio con contenido usa `rm -r`.
(-) Borra un directorio y todo lo que contiene. :: Eso es `rm -r`.
(-) Solo borra directorios ocultos. :: No filtra por nombre.
(-) Mueve el directorio a una papelera. :: En la shell de Unix no hay una papelera global.

@@q single | rm sobre un directorio
¿Qué hace `rm undir` (sin opciones) cuando `undir` es un directorio?
(+) Se niega e imprime `Is a directory`. :: Necesitas `-r` (o `rmdir` si está vacío).
(-) Borra el directorio si está vacío. :: Eso lo hace `rmdir`, no `rm` a secas.
(-) Borra el directorio y su contenido. :: Para eso hace falta `-r`.
(-) Cambia el nombre del directorio. :: Renombrar es `mv`.

@@group I-nodos y enlaces
@@q multi | Lo que guarda un i-nodo
Marca la información que se guarda en un i-nodo.
(+) El propietario y el grupo. :: Forman parte de los metadatos del fichero.
(+) Los bits de permiso. :: Se guardan en el i-nodo, no en el directorio.
(+) El tamaño y las marcas de tiempo. :: También son metadatos del i-nodo.
(+) La ubicación en disco de los bloques de datos del fichero. :: El i-nodo apunta a dónde está el contenido.
(-) El nombre del fichero. :: Los nombres están en las entradas de directorio, que apuntan a i-nodos.

@@q single | Qué es un directorio
¿Qué es un directorio, por dentro?
(+) Un fichero especial que contiene una lista de nombres, cada uno emparejado con el número de i-nodo del fichero al que nombra. :: Los nombres pertenecen a los directorios, no a los i-nodos.
(-) Una carpeta que contiene físicamente los datos de los ficheros que aparecen en ella. :: Los datos están en bloques a los que apuntan los i-nodos.
(-) Una copia completa de cada fichero que cuelga de él, que se guarda para poder reconstruir el árbol tras un fallo del sistema. :: Los directorios solo guardan la correspondencia nombre→i-nodo.
(-) Una tabla con los permisos de cada fichero, que `ls -l` lee para imprimir el modo. :: Los permisos están en los i-nodos.

@@q single | Por qué renombrar es barato
¿Por qué `mv fichero1 fichero2` dentro de un mismo sistema de ficheros es prácticamente instantáneo, incluso con un fichero enorme?
(+) Solo cambia la entrada de directorio (el nombre); el i-nodo y los bloques de datos se quedan donde están. :: No se copia ningún dato.
(-) Porque `mv` comprime antes el fichero, de modo que la copia de los datos es pequeña y rápida. :: No lo hace.
(-) Porque el fichero se mueve primero a una papelera, lo que hace que la operación sea instantánea. :: No hay ningún paso por una papelera.
(-) Porque en Linux los ficheros siempre son pequeños, así que copiarlos no lleva un tiempo apreciable. :: El tamaño es irrelevante al renombrar.

@@q single | Qué es un enlace físico
¿Qué es un enlace físico (duro) creado con `ln f fisico`?
(+) Una segunda entrada de directorio (nombre) que apunta al mismo i-nodo que `f`. :: Los dos nombres son iguales; ninguno es «el original».
(-) Un fichero pequeño que guarda la ruta `f` y se resuelve cada vez que se abre. :: Eso describe un enlace simbólico.
(-) Una copia de `f` con su propio i-nodo y sus propios bloques de datos en disco. :: Una copia sería independiente; un enlace físico no lo es.
(-) Una referencia a `f` que deja de funcionar en cuanto se borra `f`. :: Los enlaces físicos sobreviven al borrado de cualquiera de los nombres.

@@q sort | ¿Enlace físico o simbólico?
@@buckets Enlace físico | Enlace simbólico
¿Qué tipo de enlace tiene la propiedad descrita?
(Enlace físico) Comparte el i-nodo del original :: Los dos nombres apuntan exactamente al mismo número de i-nodo.
(Enlace físico) Sigue funcionando después de borrar el otro nombre :: Los datos existen hasta que se borra el último nombre.
(Enlace físico) No puede apuntar a un directorio (normalmente) :: El núcleo prohíbe los enlaces físicos a directorios para evitar ciclos.
(Enlace simbólico) Puede apuntar a un fichero de otro sistema de ficheros :: Solo guarda una ruta, así que puede cruzar sistemas de ficheros.
(Enlace simbólico) Se queda roto si se borra el destino :: La ruta pasa a no apuntar a nada.
(Enlace simbólico) Tiene su propio i-nodo y aparece con tipo `l` en `ls -l` :: Es un fichero diminuto que contiene una ruta.

@@q single | Contador de enlaces
`ls -l` muestra un número justo después del campo de modo, por ejemplo `-rw-r--r-- 2 user group`. ¿Qué es ese `2`?
(+) El número de entradas de directorio (enlaces físicos) que apuntan a ese i-nodo. :: Un fichero normal suele tener 1.
(-) El número de usuarios distintos que tienen permiso para leer el fichero. :: Eso no se registra ahí.
(-) El tamaño del fichero, contado en bloques del sistema de ficheros. :: El tamaño es otra columna.
(-) El número de veces que se ha abierto el fichero desde que se creó. :: Eso no se registra.

@@q single | Borrar un nombre
Un fichero `f` tiene un enlace físico `g`. Tras `rm f`, ¿qué es cierto?
(+) El contenido sigue disponible a través de `g`, y el contador de enlaces baja de 2 a 1. :: El fichero solo desaparece cuando el contador llega a 0 y nadie lo tiene abierto.
(-) `g` pasa a ser un enlace roto que apunta a un nombre que ya no existe, y `cat g` falla con un mensaje de error. :: Así se comporta un enlace *simbólico*.
(-) Los dos nombres desaparecen a la vez, porque se refieren a los mismos datos. :: `rm` solo borra el nombre que le das.
(-) Los datos se trasladan a `g`, que pasa a ser la única copia del fichero. :: No se traslada nada; `g` siempre apuntó a los mismos datos.

@@q single | Enlace simbólico roto
Creas `ln -s f simb` y después ejecutas `rm f`. ¿Qué pasa con `cat simb`?
(+) Falla con «No such file or directory», porque el enlace existe pero su destino no. :: `ls -l simb` sigue mostrando `simb -> f`.
(-) Sigue imprimiendo el contenido antiguo de `f`, porque el enlace guarda una copia de él. :: Los datos eran de `f`; un enlace simbólico solo guarda su nombre.
(-) Crea un fichero vacío nuevo llamado `f` y después no imprime nada. :: `cat` nunca crea ficheros.
(-) Al enlace no le pasa nada raro: `simb` se borró junto con `f`, así que la shell avisa de que no existe el fichero. :: El enlace es una entrada de directorio distinta.

@@q fill | Crear un enlace simbólico
Para crear un enlace simbólico llamado `corto` que apunte a `/usr/share/dict/words`: `ln {{-s}} /usr/share/dict/words corto`
(x) -h :: No es la opción de `ln` para crear un enlace simbólico.
@@note
El orden de los argumentos es como en `cp`: primero el destino y después el nombre del enlace. Sin `-s` obtienes un enlace físico.

@@q single | Orden de los argumentos de ln
En `ln -s destino nombreenlace`, ¿qué argumento es el fichero que ya existe?
(+) `destino` :: El primero es aquello *a lo que* enlazas; el segundo es el nombre nuevo que creas.
(-) `nombreenlace` :: Ese es el nombre que se va a crear.
(-) Se crean los dos. :: Solo se crea el enlace.
(-) Ninguno: `ln` necesita un tercer argumento con el directorio. :: Con dos argumentos basta.

@@q single | Contador de enlaces de un directorio
Un directorio vacío muestra un contador de enlaces de 2 en `ls -ld`. ¿Qué le pasa a ese contador cuando creas un subdirectorio dentro?
(+) Pasa a 3, porque la entrada `..` del subdirectorio apunta de vuelta al padre. :: El contador es 2 más el número de subdirectorios.
(-) Se queda en 2, porque en el contador de enlaces solo cuentan los ficheros, no los directorios. :: Las entradas `..` suman al contador del padre.
(-) Baja a 1, porque el subdirectorio se queda con uno de los dos enlaces. :: Los directorios nunca bajan de 2.
(-) Aumenta con cada fichero que se crea dentro, pero no con los directorios. :: Los ficheros no añaden enlaces a su padre.

@@q multi | Datos sobre los enlaces simbólicos
Marca las afirmaciones ciertas sobre los enlaces simbólicos.
(+) Pueden apuntar a directorios. :: Es habitual para atajos como `current -> release-12`.
(+) Pueden apuntar a un fichero que no existe (un enlace colgante). :: La ruta no se comprueba al crearlo.
(+) `ls -l` muestra el destino con `->`. :: Por ejemplo `simb -> f`.
(-) Comparten el i-nodo de su destino. :: Tienen su propio i-nodo.
(-) Mantienen vivos los datos después de borrar el destino. :: Los datos pertenecen al i-nodo del destino.

@@q single | Permisos de un enlace simbólico
¿Por qué `ls -l` muestra `lrwxrwxrwx` en todos los enlaces simbólicos?
(+) Los permisos del propio enlace nunca se usan; el acceso lo decide el fichero al que apunta. :: El núcleo sigue primero el enlace.
(-) Porque todo enlace simbólico tiene que ser ejecutable para que la shell pueda seguirlo. :: Los bits que se muestran no significan nada.
(-) Porque solo root puede crear enlaces simbólicos, y root necesita todos los permisos sobre todo lo que toca. :: Cualquiera puede crear uno.
(-) Porque al crear el enlace se copian en él los permisos del destino. :: No se copia nada.

@@group Copiar, mover, borrar y touch
@@q match | Mandatos básicos de ficheros
Empareja cada mandato con lo que hace.
(=) `cp a b` => Hace una copia de `a` llamada `b` :: Un fichero nuevo con su propio i-nodo.
(=) `mv a b` => Renombra `a` como `b`, o lo mueve :: El mismo i-nodo si es en el mismo sistema de ficheros.
(=) `rm a` => Borra el nombre `a` :: Los datos desaparecen cuando no queda ningún nombre.
(=) `touch a` => Crea `a` si no existe, o actualiza su marca de tiempo :: Se usa a menudo para crear un fichero vacío.
(=) `mkdir d` => Crea el directorio `d` :: Un directorio vacío.
(-) Comprime `a` :: Eso es `gzip`.

@@q multi | Opciones de cp
Marca las afirmaciones correctas sobre las opciones de `cp`.
(+) `-r` copia directorios de forma recursiva. :: Sin ella, `cp` se niega a copiar un directorio.
(+) `-i` pregunta antes de sobrescribir. :: Una red de seguridad contra sobrescrituras accidentales.
(+) `-u` solo copia cuando el origen es más nuevo o falta el destino. :: Actualiza.
(+) `-a` conserva los atributos y copia de forma recursiva, manteniendo los enlaces simbólicos como enlaces. :: Modo archivo.
(-) `-l` lista los ficheros que se van copiando. :: `-l` crea enlaces físicos en lugar de copias; el que lista es `-v`.

@@q single | Copiar un enlace simbólico
`cp simb copia`, donde `simb` es un enlace simbólico a un fichero regular. ¿Qué es `copia`?
(+) Un fichero regular con el contenido del destino, porque `cp` sigue el enlace por defecto. :: Usa `-P` o `-a` para copiar el propio enlace.
(-) Un enlace simbólico que apunta al mismo destino que `simb`, de modo que los dos nombres se refieren al mismo fichero. :: Eso pasa con `cp -P` o `cp -a`.
(-) Un enlace físico al destino, que comparte su i-nodo. :: Para eso haría falta `cp -l`.
(-) Un fichero vacío con el mismo nombre que el enlace. :: Contiene los datos del destino.

@@q single | mv de un directorio
`mv dirA dirB` cuando `dirB` ya existe y es un directorio. ¿Qué pasa?
(+) `dirA` se mueve dentro de `dirB` y pasa a ser `dirB/dirA`. :: Si `dirB` no existiera, sería un cambio de nombre.
(-) `dirA` sobrescribe a `dirB`. :: `mv` no sustituye directorios que no están vacíos.
(-) El contenido de `dirA` se fusiona, fichero a fichero, con el directorio `dirB` que ya existe. :: `mv` no fusiona.
(-) El mandato falla porque el destino existe. :: Funciona y anida el directorio.

@@q single | rm -i
¿Qué opción hace que `rm` pida confirmación antes de cada borrado?
(+) `-i` :: Modo interactivo; muy útil cuando trabajas como root.
(-) `-f` :: Fuerza el borrado sin preguntar e ignora los ficheros que no existen.
(-) `-r` :: Recursión; por sí sola no pregunta.
(-) `-v` :: Solo da una salida detallada.

@@q single | El rm peligroso
¿Qué mandato es el más peligroso si una variable resulta estar vacía, como en `rm -rf "$DIR"/*` con `DIR` sin definir?
(+) `rm -rf "$DIR"/*`, que se expande a `rm -rf /*` e intenta borrar todo lo que el usuario pueda. :: Comprueba siempre las variables antes de un borrado recursivo.
(-) `rm -i "$DIR"/*`, que es igual de arriesgado, ya que también borra todos los ficheros que el usuario confirma uno a uno. :: Pregunta por cada fichero, lo que te da ocasión de parar.
(-) `rmdir "$DIR"/*`, que borra todos los directorios que cuelgan de la raíz. :: `rmdir` solo borra directorios vacíos.
(-) `ls "$DIR"/*`, que lista ficheros y por tanto puede estropearlos. :: Solo lista.

@@q single | touch sobre un fichero que no existe
¿Qué hace `touch nuevo` cuando `nuevo` no existe?
(+) Crea un fichero vacío con ese nombre. :: Su principal uso secundario.
(-) Falla con un error, porque el fichero que se toca ya tiene que existir. :: No da error.
(-) Crea un directorio vacío con ese nombre en lugar de un fichero. :: Los directorios necesitan `mkdir`.
(-) Abre un editor para que puedas escribir el contenido del fichero. :: `touch` no tiene ninguna parte interactiva.

@@q fill | Fijar una fecha
Para crear `viejo` con la fecha de modificación del 2 de enero de 2020 (solo la fecha): `touch {{-d}} "2020-01-02" viejo`
(x) -t :: `-t` también fija una hora, pero necesita otro formato `[[CC]YY]MMDDhhmm[.ss]`, no esta cadena.
@@note
`--date="..."` es la forma larga de `-d`.

@@q single | Ficheros temporales
¿Qué aporta `mktemp` frente a elegir un nombre como `/tmp/salida`?
(+) Un nombre único e impredecible, creado de forma segura, para que dos ejecuciones no choquen. :: Imprime el nombre del fichero nuevo.
(-) Un fichero que se borra automáticamente cuando termina el script que lo creó. :: Tienes que borrarlo tú.
(-) Un fichero que solo se guarda en memoria y desaparece en cuanto se va la luz. :: `/tmp` puede estar en RAM en algunos sistemas, pero `mktemp` no lo garantiza.
(-) Un fichero comprimido, que se vuelve a descomprimir cuando el script lo necesita. :: Crea un fichero o un directorio vacío.

@@q single | Borrar con comodines
En un directorio ejecutas `rm *.txt`. ¿Qué ficheros le pasa la shell a `rm`?
(+) Todos los ficheros cuyo nombre termina en `.txt`, expandidos antes de que arranque `rm`. :: La expansión de comodines la hace la shell, no `rm`.
(-) Solo un fichero cada vez. :: Todas las coincidencias se pasan como argumentos.
(-) El texto literal `*.txt`, que luego `rm` interpreta por su cuenta buscando los nombres que coinciden en el directorio. :: Solo si ningún fichero coincide y `nullglob` está desactivado.
(-) Todos los ficheros del directorio. :: Solo los que coinciden.

@@group Montaje y espacio en disco
@@q single | Qué hace montar
¿Qué hace `mount /dev/sdb1 /mnt/usb`?
(+) Engancha el sistema de ficheros de ese dispositivo en el directorio `/mnt/usb`, de modo que sus ficheros aparecen ahí. :: Ese directorio es el punto de montaje.
(-) Formatea el dispositivo y crea en él un sistema de ficheros nuevo y vacío, que después se monta en `/mnt/usb`. :: Formatear es `mkfs`.
(-) Copia todo el contenido del dispositivo en el directorio `/mnt/usb`. :: No se copia nada.
(-) Borra el nodo del dispositivo y todos los ficheros que había guardados en él. :: Montar no destruye nada.

@@q single | Desmontar
¿Qué mandato desengancha un sistema de ficheros montado?
(+) `umount /mnt/usb` :: Fíjate en cómo se escribe: no hay `n` después de la `u`.
(-) `unmount /mnt/usb` :: Una errata muy común.
(-) `mount -d /mnt/usb` :: No es una opción para eso.
(-) `rm /mnt/usb` :: Intentaría borrar un directorio.

@@q match | Herramientas de espacio en disco
Empareja cada mandato con su salida.
(=) `df -h` => Espacio libre y usado de cada sistema de ficheros montado, en unidades legibles :: Mira sistemas de ficheros completos.
(=) `du -sh dir` => Tamaño total que ocupa un árbol de directorios, en unidades legibles :: Mira los ficheros que cuelgan de una ruta.
(=) `mount` (sin argumentos) => La lista de sistemas de ficheros montados :: Muestra dispositivos y puntos de montaje.
(=) `stat fichero` => Metadatos del i-nodo de un fichero (tamaño, enlaces, tiempos, permisos) :: Los atributos en bruto.
(=) `tree` => Un dibujo sangrado de un árbol de directorios :: A menudo no viene instalado por defecto.
(-) Comprime un directorio :: Eso sería `tar` con `-z`.

@@q single | df frente a du
¿Cuál es la diferencia principal entre `df` y `du`?
(+) `df` informa del espacio libre y usado de cada sistema de ficheros, mientras que `du` suma el espacio que ocupan los ficheros de una ruta. :: Uno mira desde el disco y el otro desde los ficheros.
(-) `df` solo funciona con directorios y `du` solo funciona con ficheros sueltos. :: Los dos trabajan a escalas distintas; este reparto es falso.
(-) `du` muestra el espacio libre de discos y particiones, mientras que `df` muestra el tamaño de los ficheros de un directorio. :: Es al revés.
(-) Son el mismo programa, instalado con dos nombres distintos. :: Son mandatos diferentes.

@@q single | Legible para humanos
¿Qué hace la opción `-h` en `df -h` y en `du -h`?
(+) Imprime los tamaños en unidades como K, M y G en lugar de bloques en bruto. :: «Human readable», legible para humanos.
(-) Oculta la línea de cabecera, con lo que solo quedan los números de los sistemas de ficheros. :: No.
(-) Muestra también los ficheros ocultos, como la opción `-a` de `ls`. :: Eso es `ls -a`.
(-) Imprime un breve mensaje de ayuda sobre las opciones del mandato. :: Eso es `--help`.

@@q single | Profundidad de du
¿Qué mandato muestra el espacio que ocupa cada subdirectorio del directorio actual, pero sin bajar más?
(+) `du -h --max-depth=1` :: Limita la recursión a un nivel por debajo del punto de partida.
(-) `du -s` :: Imprime un único total.
(-) `df -d 1` :: `df` no recorre directorios.
(-) `ls -R` :: Lista nombres, no tamaños.

@@q single | Disco lleno frente a du
`df` dice que un sistema de ficheros está lleno al 100 %, pero `du` de su directorio superior suma mucho menos. ¿Qué explicación es plausible?
(+) Un fichero borrado sigue abierto por un proceso en ejecución, así que su espacio aún no se ha liberado. :: `du` ya no ve el nombre, pero `df` sigue contando los bloques.
(-) `du` cuenta dos veces los ficheros ocultos, lo que hace que su total parezca mayor, aunque el que acierta es `df`. :: Eso lo haría mayor, no menor.
(-) `df` mide en bits y `du` en bytes, así que nunca pueden coincidir. :: Los dos usan bloques/bytes de forma coherente.
(-) Solo `du` aplica compresión, así que informa de tamaños menores que `df`. :: Ninguno de los dos comprime.

@@group Archivos y compresión
@@q single | Archivar frente a comprimir
¿Qué diferencia hay entre tar y gzip?
(+) `tar` agrupa ficheros y directorios en un único fichero de archivo; `gzip` comprime un único fichero o flujo. :: Se suelen combinar para obtener `.tar.gz` o `.tgz`.
(-) `tar` comprime los ficheros que recibe, mientras que `gzip` solo los agrupa en un único fichero de archivo. :: Es al revés.
(-) Son herramientas idénticas, instaladas con dos nombres por razones históricas. :: Resuelven problemas distintos.
(-) `gzip` cifra el archivo que ha creado `tar`, protegiéndolo con una clave. :: No cifra nada.

@@q match | Opciones de tar
Empareja cada opción de tar con su significado.
(=) `c` => Crear un archivo :: Escribe un archivo nuevo.
(=) `x` => Extraer ficheros de un archivo :: Restaura los ficheros.
(=) `t` => Listar el contenido de un archivo :: Muestra los nombres sin extraer.
(=) `z` => Pasar por gzip :: Comprime al crear y descomprime al extraer.
(=) `f` => El siguiente argumento es el nombre del fichero de archivo :: Sin ella, tar usa un dispositivo por defecto.
(=) `v` => Modo detallado: mostrar los ficheros según se procesan :: Útil para ver qué está pasando.
(-) Borrar después los ficheros originales :: `tar` nunca borra los originales por su cuenta.

@@q fill | Crear un archivo comprimido
Para crear un archivo comprimido con gzip `backup.tgz` que contenga el directorio `docs`: `tar {{czf}} backup.tgz docs`
(x) xzf :: `x` extrae; fallaría porque `backup.tgz` todavía no existe.
(x) tzf :: `t` solo lista un archivo que ya existe.
@@note
Las letras de opción se pueden juntar; `f` tiene que ir la última del grupo porque toma el siguiente argumento.

@@q fill | Extraer un archivo comprimido
Para extraer `backup.tgz` en el directorio actual: `tar {{xzf ;; xvzf ;; zxf ;; zxvf}} backup.tgz`
(x) czf :: `c` intentaría crear (y sobrescribir) el archivo.
@@note
Añade `-C dir` para extraer en otro sitio.

@@q single | Listar antes de extraer
Antes de extraer un archivo de una fuente poco fiable, quieres ver qué ficheros contiene. ¿Qué mandato lo hace?
(+) `tar tzf archivo.tgz` :: `t` lista sin extraer.
(-) `tar xzf archivo.tgz` :: Extrae inmediatamente.
(-) `tar czf archivo.tgz` :: Intentaría crear un archivo.
(-) `gzip -l archivo.tgz` :: Muestra estadísticas de compresión, no los ficheros que hay dentro del tar.

@@q single | gzip borra el original
¿Qué hace por defecto `gzip notas.txt`?
(+) Sustituye `notas.txt` por el comprimido `notas.txt.gz`. :: Usa `-k` para conservar el original.
(-) Crea `notas.txt.gz` y conserva `notas.txt`. :: Solo con `-k`.
(-) Comprime el fichero en el sitio y mantiene el mismo nombre, así que ahora `notas.txt` está comprimido. :: Se añade el sufijo `.gz`.
(-) Archiva el directorio actual. :: Eso es `tar`.

@@q single | gunzip
¿Cómo descomprimes `notas.txt.gz`?
(+) `gunzip notas.txt.gz` (o `gzip -d notas.txt.gz`) :: Restaura `notas.txt` y quita el `.gz`.
(-) `ungzip notas.txt.gz`, la pareja de `gzip` de la misma familia :: No existe ese mandato.
(-) `tar x notas.txt.gz`, ya que `tar` extrae cualquier tipo de fichero comprimido :: `tar` extrae archivos, no ficheros gzip sueltos.
(-) `cat notas.txt.gz > notas.txt`, que copia los bytes en un fichero nuevo :: Eso copia los bytes comprimidos.

@@q match | Extensiones de fichero
Empareja cada extensión con lo que esperas encontrar.
(=) `.tar` => Un archivo tar sin comprimir :: Agrupado, pero no comprimido.
(=) `.gz` => Un fichero comprimido con gzip :: Un único fichero comprimido.
(=) `.tgz` o `.tar.gz` => Un archivo tar comprimido con gzip :: Los dos pasos.
(=) `.Z` => Un fichero comprimido con el antiguo mandato `compress` :: Se descomprime con `uncompress`.
(-) Una copia de seguridad cifrada :: Ninguno de estos formatos cifra.

@@q order | Flujo de una copia de seguridad
Ordena estos pasos para hacer y verificar una copia de seguridad comprimida.
(>) Crear el archivo: `tar czf b.tgz docs` :: No puede pasar nada más hasta que exista el fichero.
(>) Listarlo: `tar tzf b.tgz` :: Comprueba que dentro están los ficheros que esperas.
(>) Copiarlo a un sitio seguro: `cp b.tgz /backup/` :: Solo merece la pena copiarlo tras la comprobación.
(>) Extraer una copia de prueba en un directorio temporal :: La prueba de verdad de una copia de seguridad es restaurarla.

@@q single | Orden de los argumentos de tar
Querías archivar `notas.txt` en `notas.tgz`, pero escribiste `tar czf notas.txt notas.tgz`. ¿Qué daño has hecho?
(+) El primer nombre tras `f` es el archivo, así que `notas.txt` queda sobrescrito por un archivo gzip que contiene `notas.tgz`. :: El nombre del archivo va justo después de `f`; los ficheros que añadir van detrás.
(-) Ninguno: tar siempre reordena sus argumentos para que el nombre del archivo quede el último. :: No adivina nada; decide la posición tras `f`.
(-) tar se niega a ejecutarse e imprime un mensaje de ayuda que explica al usuario el orden correcto de los argumentos. :: Hace exactamente lo que escribiste.
(-) La opción `z` borra el fichero de origen una vez comprimido. :: `z` solo comprime.
@@note
Con un directorio en esa posición, tar fallaría con «Is a directory»; con un fichero normal, los datos originales se pierden sin aviso.

@@group Predice el resultado
@@q single | Contar entradas
En un directorio vacío `d` ejecutas `touch a b; mkdir c` dentro de él y luego, desde su padre, `ls -l d | wc -l`. ¿Qué número se imprime?
(+) 4 :: `ls -l` imprime una línea «total» más una línea por entrada (a, b, c).
(-) 3 :: Olvida la línea de cabecera `total N`.
(-) 5 :: `.` y `..` no se muestran sin `-a`.
(-) 2 :: No es correcto para tres entradas.

@@q single | Copiar dentro de sí mismo
¿Qué hace `cp -r dir dir/copia` (copiar un directorio dentro de sí mismo) en el `cp` de GNU?
(+) Se niega con un error del tipo «cannot copy a directory into itself». :: Si no, entraría en una recursión infinita.
(-) Crea `dir/copia` con una copia completa del contenido de `dir` y luego para. :: Eso haría una copia a un sitio *distinto*.
(-) Cambia el nombre de `dir` a `copia` y mete dentro todo lo que contiene. :: Eso es `mv`.
(-) No hace nada, en silencio, y devuelve el valor de retorno 0. :: Imprime el mensaje de error.

@@q single | Contador tras crear enlaces
Un fichero tiene un contador de enlaces de 1. Ejecutas `ln f h` y `ln -s f s`. ¿Cuál es ahora el contador de enlaces de `f`?
(+) 2 :: El enlace físico `h` suma uno; el enlace simbólico `s` es un fichero aparte y no cuenta.
(-) 3 :: Un enlace simbólico no aumenta el contador del destino.
(-) 1 :: El enlace físico añadió un nombre.
(-) 0 :: El contador nunca llega a cero mientras existan nombres.

@@q single | Sobrescrito al hacer mv
`mv a b`, donde `b` ya existe como fichero regular (y sin `-i` ni alias). ¿Qué pasa?
(+) `a` sustituye a `b` sin avisar. :: Por eso mucha gente define el alias `mv` como `mv -i`.
(-) El mandato pide confirmación por defecto. :: No sin `-i`.
(-) `a` se añade al final de `b`. :: `mv` nunca concatena.
(-) Falla porque `b` existe. :: No falla.

@@q single | Directorio actual en un script
Justo después de `mkdir -p a/b/c && cd a/b/c && cd ../..`, ¿dónde estás respecto al directorio de partida?
(+) En `a` :: Dos niveles por encima de `a/b/c` está `a`.
(-) En `a/b` :: Eso sería un solo `..`.
(-) En el directorio de partida :: Para eso hacen falta tres `..`.
(-) En `c` :: `cd ../..` te sacó de ahí.

@@group Práctica variada
@@q fill | Copiar un directorio entero
Copia el directorio `proy` con todo lo que contiene en `proy_backup`: `cp {{-r ;; -R ;; -a ;; -ra ;; -ar}} proy proy_backup`
(x) -i :: Solo pregunta antes de sobrescribir; `cp` seguiría negándose a copiar un directorio.
(x) -u :: Solo copia los ficheros más nuevos; no hace que `cp` entre en los directorios.
@@note
`-a` además conserva los permisos, las fechas y los enlaces simbólicos.

@@q fill | Nombre de un enlace simbólico
Haz que `latest` sea un enlace simbólico que apunte a `release-12`: `ln -s {{release-12}} latest`
(x) latest :: El primer argumento es el destino; el nombre del enlace va el segundo.
@@note
Después, `ls -l latest` muestra `latest -> release-12`.

@@q fill | Borrar un árbol de directorios
Borra el directorio `viejo` junto con todo su contenido: `rm {{-r ;; -rf ;; -fr ;; -R ;; -Rf}} viejo`
(x) -d :: Solo borra directorios vacíos (como `rmdir`).
(x) -i :: Solo pide confirmación antes de cada borrado.
@@note
Revisa bien el nombre antes: no se puede deshacer.

@@q sort | ¿Enlace o copia?
@@buckets Los cambios se ven en los dos nombres | Independientes tras la operación
Después de la operación, editas uno de los dos nombres.
(Los cambios se ven en los dos nombres) `ln a b` (enlace físico) :: Los dos nombres apuntan al mismo i-nodo.
(Los cambios se ven en los dos nombres) `ln -s a b` (enlace simbólico) :: Al abrir `b` se sigue hasta `a`.
(Independientes tras la operación) `cp a b` :: Un fichero nuevo con su propio i-nodo y sus propios datos.
(Independientes tras la operación) `cp -a a b` :: También copia los atributos, pero sigue siendo un fichero aparte.

@@q multi | Cosas que cambian el contador de enlaces
Marca los mandatos que cambian el contador de enlaces del fichero `f`.
(+) `ln f g` :: Un enlace físico nuevo suma uno.
(+) `rm g` (cuando `g` es un enlace físico a `f`) :: Borrar un nombre baja el contador.
(-) `ln -s f s` :: Un enlace simbólico es un fichero aparte; no sube el contador de `f`.
(-) `cp f h` :: Una copia es un fichero nuevo con su propio contador a 1.
(-) `chmod 600 f` :: Los permisos no cambian el contador de enlaces.

@@q order | Ida y vuelta segura de un archivo
Ordena los mandatos para hacer una copia de `docs`, comprobar el archivo y restaurarlo en otro sitio.
(>) `tar czf docs.tgz docs` :: Crear el archivo comprimido.
(>) `tar tzf docs.tgz` :: Listarlo para comprobar el contenido sin extraer.
(>) `mkdir restaurar` :: Un directorio limpio donde extraer.
(>) `tar xzf docs.tgz -C restaurar` :: Extraer en el directorio nuevo con `-C`.

@@q match | Información de disco y de ficheros
Empareja cada mandato con lo que muestra.
(=) `df -h /` => Espacio libre y usado del sistema de ficheros que contiene `/` :: Tamaños legibles.
(=) `du -sh ~` => El tamaño total de tu directorio personal :: `-s` resume.
(=) `stat fichero` => Datos del i-nodo: tamaño, permisos, propietario, tiempos y contador de enlaces :: Los atributos en bruto.
(=) `ls -i fichero` => El número de i-nodo del fichero :: Útil para reconocer enlaces físicos.
(=) `mount` => La lista de sistemas de ficheros montados :: Dispositivos y puntos de montaje.
(-) El contenido de un archivo comprimido :: Eso es `tar tzf`.
