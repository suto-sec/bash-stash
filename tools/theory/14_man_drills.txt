Questions you can answer with the manual pages installed in the lab: the terminal is open beside each one, so look it up (`man`, `help`, `whatis`, `apropos`) instead of guessing. Choices, fill in the blank, ordering, matching and sorting.

@@group Finding your way around man
@@q single [man-section-for-file-formats] | Which page describes /etc/passwd?
You want the **layout of the fields of the file `/etc/passwd`**, not the `passwd` command that changes a password. Which command opens that page? Try them in the terminal.
(+) `man 5 passwd` :: Section 5 holds file formats and configuration files. `passwd (5)` is the page about the file.
(-) `man passwd` :: It opens the first page called `passwd`, which is the command (section 1), not the file format.
(-) `man 1 passwd` :: Section 1 is for commands: this is the same page as plain `man passwd`.
(-) `man 5 etc` :: There is no page named `etc`; the page is named after the file, `passwd`, and the number only picks the section.
@@note
`whatis passwd` lists every section that has a page with that name, and `man -k passwd` lists every page that mentions it.

@@q match [man-keys-in-pager] | Keys inside a man page
`man` shows its pages with the pager `less`. Press `h` inside one to see its keys, then pair each key with what it does.
(=) `/word` then Enter => searches forward for `word` :: The slash starts a search; matches are highlighted.
(=) `n` => jumps to the next match of the last search :: `N` (capital) goes to the previous one.
(=) `g` => goes back to the top of the page :: Handy after jumping around with searches.
(=) `G` => goes to the end of the page :: The last lines are often the SEE ALSO and examples.
(=) `q` => leaves the page :: It returns to the shell prompt.
(-) `x` :: `less` has no such key: redirect the output of `man` yourself if you want a copy.

@@q fill [apropos-by-keyword] | List the pages about a word
To list every manual entry whose one-line description mentions a word, type `{{apropos ;; man -k}} word`.
(x) `whatis` :: `whatis` looks a name up and prints its own one-line description; it does not search the descriptions for a word.
(x) `man -f` :: `man -f` is the same as `whatis`: it matches the name of a page.
@@note
`apropos` and `man -k` are the same search. When you do not know the name of the command, describe it: `apropos 'list directory'`.

@@q sort [builtin-or-program] | help or man?
Bash builtins are documented with `help`, external programs with `man`. Check with `type NAME` in the terminal, then put each command in the right group.
@@buckets Builtin: help NAME | Program: man NAME
(Builtin: help NAME) cd :: `type cd` says it is a shell builtin: it must change the directory of the shell itself.
(Builtin: help NAME) read :: A builtin of bash. Careful: `man read` opens a different page (the POSIX utility, or the system call), not bash's `read`.
(Builtin: help NAME) shift :: A builtin: it works on the positional parameters of the running shell.
(Builtin: help NAME) export :: A builtin: it changes the environment of the shell.
(Program: man NAME) find :: A program in `/usr/bin`: its page is `man find`.
(Program: man NAME) tar :: A program in `/usr/bin`.
(Program: man NAME) cut :: A program in `/usr/bin`.
(Program: man NAME) sort :: A program in `/usr/bin`.

@@q order [find-option-in-man] | Look up an option

(>) Type `man grep` and press Enter :: The page opens in the pager.
(>) Press `/`, type `only-matching` and press Enter :: The pager jumps to the first place where the word appears.

@@q multi [docs-for-builtin] | Documentation of a builtin

@@group Files and directories
@@q single [cp-never-overwrite] | Copy without overwriting
You copy `docs/*` into `backup/`. Which `cp` option guarantees that **no existing file of `backup/` is replaced**, silently? Check `man cp`.
(+) `cp -n` :: `-n` (`--no-clobber`): do not overwrite an existing file, and do not fail.
(-) `cp -i` :: It asks before each overwrite: nothing silent, and a script would wait for an answer.
(-) `cp -u` :: It copies only when the source is newer than the destination, so it still overwrites older files.
(-) `cp -p` :: It preserves mode, ownership and timestamps of the copies; it does not protect existing files.

@@q match [ls-options] | ls options
Pair each option of `ls` with its effect (`man ls`).
(=) `-a` => shows the hidden entries (names starting with a dot) :: `-A` does the same without `.` and `..`.
(=) `-d` => lists a directory itself, not its contents :: `ls -ld dir` shows the permissions of `dir`.
(=) `-R` => lists subdirectories recursively :: Every directory gets its own heading.
(=) `-h` => prints sizes as 4.0K, 1.2M... :: Only meaningful together with `-l`.
(=) `-1` => prints one name per line :: Useful when the output goes to a pipe or a loop.
(=) `-S` => sorts by size, biggest first :: `-r` reverses it.

@@q multi [ls-order-options] | What changes the order
Which of these options of `ls` change **the order** of the listing?
(+) `-S` :: Sorts by file size, largest first.
(+) `-t` :: Sorts by modification time, newest first.
(+) `-r` :: Reverses whatever order is in use.
(-) `-l` :: It only changes the format (long listing); the order stays alphabetical.
(-) `-a` :: It adds the hidden entries, but they are sorted the same way.
(-) `-h` :: It changes how sizes are written, not the order.

@@q single [rm-empty-dir] | Only if it is empty
You want a command that removes the directory `old` **only if it is empty** and fails otherwise, using `rm`. Which one is it (`man rm`)?
(+) `rm -d old` :: `-d` (`--dir`) removes empty directories: a non-empty one is refused.
(-) `rm -r old` :: `-r` removes the directory and everything inside it, empty or not.
(-) `rm -f old` :: `-f` only suppresses errors and prompts; on a directory `rm` still refuses without `-d` or `-r`.
(-) `rm -i old` :: `-i` asks before removing, but it still refuses a directory without `-d` or `-r`.

(x) `du -c fotos` :: `-c` adds a grand total line after the listing, but the listing is still there.

@@group find
@@q single [find-perm-modes] | Any execute bit
Which test selects the regular files that have the **execute permission set for at least one** of owner, group or others? Read the `-perm` entries in `man find`.
(+) `find . -type f -perm /111` :: With a slash, **any** of the listed bits makes the file match.
(-) `find . -type f -perm 111` :: Without a sign it means **exactly** `--x--x--x`: a file with mode 755 does not match.
(-) `find . -type f -perm -111` :: With a minus, **all** the listed bits must be set: x for owner, group and others.
(-) `find . -type f -executable` :: It tests whether **you** may execute the file (a permission check for the user running `find`), not the permission bits.

@@q sort [find-tests-actions] | Tests or actions
In a `find` command line, **tests** select files and **actions** do something with the selected ones. Sort the expressions (the EXPRESSION sections of `man find` list them).
@@buckets Test | Action
(Test) `-name` :: Matches the file name against a pattern.
(Test) `-size` :: Matches the size, with `+` / `-` for larger / smaller.
(Test) `-mtime` :: Matches the time of the last modification, counted in days.
(Test) `-newer` :: Matches files modified more recently than a reference file.
(Action) `-print` :: Prints the name: it is the default action when you give none.
(Action) `-delete` :: Removes the file. Put it last, after every test.
(Action) `-exec` :: Runs a command for the selected files.
(Action) `-ls` :: Prints a long listing, like `ls -dils`.

@@q fill [find-mtime-today] | The last 24 hours
`find . -type f -mtime {{0 ;; -1}}` lists the regular files modified **in the last 24 hours**.
(x) `+1` :: `+1` means more than 1 day ago (the rounding is explained under `-atime`): the opposite.
(x) `1` :: `1` means exactly 1 day ago, after discarding the fraction.
@@note
`-mtime n` counts whole days and ignores fractions: `0` and `-1` both mean "less than 24 hours ago". For minutes use `-mmin`.

@@q single [exec-semicolon-plus] | \; or +
What is the difference between `find . -type f -exec ls -l {} \;` and `find . -type f -exec ls -l {} +`? Read the `-exec` entries.
(+) `+` puts many names on one command line, `\;` runs the command once per file. :: That is also why `+` is faster on large trees.
(-) `+` processes just the first match and then stops, while `\;` goes through all of them. :: Both variants process every selected file.
(-) `\;` lets the command use the file name through `{}`, but `+` has no way to pass it. :: `{}` is the file name in both forms; with `+` it must be the last argument.
(-) `\;` asks the user for a confirmation before each file and `+` runs without asking. :: That is `-ok`; `-exec` never asks.

@@q match [find-printf] | -printf formats
`find -printf` prints what you ask for. Pair each directive with its meaning (`man find`, the `-printf` section).
(=) `%s` => size in bytes :: As in `find . -type f -printf '%s %p\n'`.
(=) `%p` => the file name, as `find` found it (the whole path) :: `./docs/a.txt`.
(=) `%P` => the path without the starting point :: `docs/a.txt` when you searched from `.`.
(=) `%m` => permission bits in octal :: `644`, `755`...
(-) `%z` :: There is no such directive for the owner (it is `%u`).

@@q order [delete-empty-tmp] | Delete with care

@@q fill [sort-field-numeric] | Sort by a column
A file has lines like `ana:35:madrid`. To sort them by the **2nd field**, **numerically**, type `sort -t{{:}} -k{{2}} -n file`.
(x) `-k1` :: `-k1` would sort by the name, the first field.
(x) `-t,` :: The fields are separated by `:`, so `-t,` would treat each line as one single field.
@@note

@@q single [uniq-adjacent] | Why uniq is not enough
`uniq names.txt` leaves duplicates in the output of an unsorted file. Why (`man uniq`)?
(+) It only compares **adjacent** lines, so the file must be sorted first (`sort names.txt | uniq`). :: The first line of the page says it: "Filter adjacent matching lines".
(-) It only compares the first word of each line, so use `-f` to compare all of it. :: It compares the whole line unless you ask otherwise with `-f`, `-s` or `-w`.
(-) It removes duplicates only when `-u` is given, because by default it just counts them. :: Without options it already prints each group of identical adjacent lines once; `-c` counts, `-u` keeps the unique ones.
(-) It only works on files with at most 100 lines. :: There is no such limit.

@@q multi [tr-options] | Options of tr
`tr` translates characters. Which of these are options of `tr`? Check `man tr`.
(+) `-d` :: Deletes the characters of SET1.
(+) `-s` :: Squeezes runs of a repeated character into one.
(+) `-c` :: Complements SET1: acts on everything that is **not** in it.
(-) `-r` :: There is no `-r` option in `tr`.
(-) `-l` :: There is no `-l` option; lines are not a concept `tr` knows.

@@q single [chmod-symbolic] | A symbolic mode
What does `chmod g-w,o= file` do? Read the MODES part of `man chmod`.
(+) It removes write permission from the group, and removes every permission from others. :: `-` takes bits away; `o=` assigns an empty set to others.
(-) It adds write permission to the group, and gives others no permissions. :: `-` removes, it does not add: the sign for adding is `+`.
(-) It removes write permission from the group and from others. :: `o=` sets others to exactly nothing: it removes read and execute as well.
(-) It sets the group to write-only and leaves others alone. :: `g-w` only removes the write bit; `=` would be the sign that sets exact permissions.

@@q fill [umask-file] | New files and the umask
With `umask 027`, a **new regular file** that the program asked to create with mode 666 gets the permissions `{{640}}` (in octal).
(x) `750` :: That is what a new **directory** (asked with 777) gets: files never start with the execute bit.
(x) `027` :: `027` is the mask itself: the bits that are taken away.
@@note
`help umask` explains the mask: the permissions requested (666 for files, 777 for directories) minus the bits of the mask: 666 - 027 = 640.

@@q match [mode-octal-symbolic] | Octal and symbolic
Pair each octal mode with its symbolic form.
(=) `755` => `rwxr-xr-x` :: 7 = rwx for the owner, 5 = r-x for group and others.
(=) `640` => `rw-r-----` :: 6 = rw-, 4 = r--, 0 = ---.
(=) `700` => `rwx------` :: Only the owner can do anything.
(=) `444` => `r--r--r--` :: Everyone can read, nobody can write.
(=) `664` => `rw-rw-r--` :: Typical for a file shared by a group.

@@q single [chown-user-group] | Owner and group at once
Which command changes **both the owner and the group** of `data.txt` to `ana` and `dev` (`man chown`)? Changing the owner needs root, so only read the page.
(+) `chown ana:dev data.txt` :: `OWNER:GROUP` sets both in one go.
(-) `chown ana dev data.txt` :: It would treat `dev` as a second file name.
(-) `chown :ana:dev data.txt` :: A leading colon means "only the group", and the name would be wrong anyway.
(-) `chmod ana:dev data.txt` :: `chmod` changes permission bits, not owners.

@@q single [shadow-locked] | A ! in /etc/shadow
In `/etc/shadow`, the second field of a user is `!` (or `*`). What does it mean (`man 5 shadow`)?
(+) The account has no valid password: nobody can log in with a password as that user. :: A string that is not a valid result of `crypt(3)` can never match what is typed.
(-) The user has an empty password, so anyone can log in without typing one. :: An empty field would mean that; `!` blocks the password login.
(-) The password has expired and must be changed at the next login. :: Expiry is controlled by other fields (the dates), not by this one.
(-) The user is an administrator. :: Nothing in this file marks administrators; that is done by groups and `sudoers`.

@@q single [crontab-meaning] | Reading a crontab line
When does `30 2 * * 1 /usr/local/bin/backup` run (`man 5 crontab`)?
(+) At 02:30 every Monday. :: The fields are minute, hour, day of month, month, day of week: minute 30, hour 2, any day, any month, weekday 1 (Monday).
(-) Every 30 minutes between 2 and 3 in the morning on the first day of the month. :: A `1` in the 5th field is a weekday; and `30` is a fixed minute, not a step.
(-) At 02:30 on the first day of every month. :: The first day of the month would be a `1` in the **third** field; here it is in the fifth.
(-) At 01:02 on the 30th of every month. :: The order of the fields is minute, hour, day: the first field is minutes.

@@q order [crontab-field-order] | Fields of a crontab line
Put the five time fields of a crontab line in their order, from left to right.
(>) minute :: 0-59.
(>) hour :: 0-23.
(>) day of month :: 1-31.
(>) month :: 1-12.
(>) day of week :: 0-7, where both 0 and 7 are Sunday.

@@q single [sudoers-nopasswd] | The NOPASSWD tag

(+) `ana` to run any command as any user via `sudo`, with no password prompt. :: `NOPASSWD:` is a tag of the command list: the password prompt is skipped for those commands.
(-) every user of the system to run any command as `ana`, without a password prompt. :: The first field is **who** may use sudo: here it is `ana`, not "anybody".
(-) `ana` to log in to the machine without typing a password at the login prompt. :: It concerns `sudo` only; login passwords are not part of `sudoers`.
(-) `ana` to run only one program, whose file is literally called `ALL`, with a password. :: `ALL` is a keyword that matches every command.

Which command prints the **names** (not the numbers) of **all the groups** of the user `ana` (`man id`)?
(+) `id -Gn ana` :: `-G` prints all group IDs and `-n` asks for names instead of numbers.
(-) `id -gn ana` :: `-g` prints only the primary group.
(-) `id -un ana` :: `-u` is the user, not the groups.
(-) `id -G ana` :: It prints the numbers of all the groups, because `-n` is missing.

@@q sort [who-or-last] | who or last?
`who` reports the **current** state of the system and `last` reads the **history** of logins. Check `man who` and `man last`, then sort the facts.
@@buckets who | last
(who) Who is logged in right now, and from which terminal :: The default output of `who`.
(who) The time of the last system boot, with `-b` :: `who -b`.
(last) Every past login of every user, newest first :: `last` reads the history file `/var/log/wtmp`.
(last) The list of reboots, with `last reboot` :: `reboot` works as a pseudo user that logs in at every boot.

@@q single [job-background] | To the background
You started `sleep 300` in the foreground and pressed `Ctrl+Z`, which **suspended** it. Which command now lets it **continue running in the background**? (`help bg`)
(+) `bg` :: It resumes the suspended job in the background.
(-) `fg` :: It resumes the job in the **foreground**: the shell waits for it again.
(-) `jobs` :: It only lists the jobs and their state.
(-) `wait` :: It waits until the background jobs end: it does not resume a stopped one.
