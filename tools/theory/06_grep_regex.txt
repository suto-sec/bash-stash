@@collection 06_grep_regex | grep & regular expressions
@@about
Searching text with grep: its options and exit status, basic and extended regular expressions, anchors, brackets, repetition, groups, and how regular expressions differ from shell wildcards.

@@group grep basics
@@q single | What grep does
What does `grep pattern file` print?
(+) Every line of `file` that contains text matching `pattern`. :: It selects whole lines; it does not print only the matching word unless you ask with `-o`.
(-) The names of the files that contain the pattern, without the lines themselves. :: That is `grep -l`, or `grep -r` with a directory.
(-) Only the first match in the whole file, and then it stops reading. :: All matching lines are printed (unless `-m` limits them).
(-) The number of matches, instead of the lines that contain the pattern. :: That is `grep -c`.

@@q single | Where the text comes from
What does `grep root` do with no file operand?
(+) It reads standard input, so it can be used in the middle of a pipeline. :: For example `ps aux | grep root`.
(-) It searches the whole file system for files that contain the word, starting from `/`. :: That is `grep -r root /`.
(-) It fails with the error "missing file", because no file to search was given. :: Like most filters it falls back to standard input.
(-) It searches all the files of the current directory, without descending into directories. :: Not without `-r`.

@@q match | Common grep options
Match each option with its effect.
(=) `-i` => Ignore case :: `Root`, `ROOT` and `root` all match.
(=) `-v` => Invert: print the lines that do NOT match :: A way to filter things out.
(=) `-c` => Print the number of matching lines :: Not the lines themselves.
(=) `-n` => Prefix each line with its line number :: Helpful to find the place in an editor.
(=) `-l` => Print only the names of files with a match :: One name per file.
(-) Edit the matching lines :: `grep` never changes its input.

@@q match | More grep options
Match each option with its effect.
(=) `-r` => Search directories recursively :: Descends into sub-directories.
(=) `-o` => Print only the matched part of each line :: Each match on its own line.
(=) `-w` => Match whole words only :: `cat` no longer matches `concatenate`.
(=) `-x` => The whole line must match :: Stronger than `-w`.
(=) `-F` => Treat the pattern as a fixed string, not as a regular expression :: Dots and stars lose their meaning.
(-) Replace the match with another text :: Substitution is `sed`.

@@q multi | Options that change what is printed
Select the options that make `grep` print something other than the matching lines.
(+) `-c` :: Prints a count.
(+) `-l` :: Prints file names.
(+) `-o` :: Prints only the matched text.
(-) `-i` :: Only changes how the matching is done.
(-) `-E` :: Only chooses the regular-expression dialect.

@@q single | Exit status of grep
What exit status does `grep` return when it finds no match in a readable file?
(+) 1 :: 0 means at least one match, 1 no match, 2 an error (for example a missing file).
(-) 0 :: That means a line matched.
(-) 2 :: That is for errors.
(-) 255 :: Not used by grep.

@@q match | grep statuses
Match each command with its exit status.
(=) `grep root /etc/passwd` (present) => 0 :: A match was found.
(=) `grep zzzqqq /etc/passwd` => 1 :: Nothing matched.
(=) `grep root /no/such/file` => 2 :: Error: the file could not be read.
(-) 3 :: Not produced by any of these.

@@q single | Quiet mode
What does `grep -q root /etc/passwd` do, and why is it useful in `if`?
(+) It prints nothing and only sets the exit status, so `if grep -q ...; then` can test for a pattern. :: `-q` stops at the first match, too.
(-) It prints the matching line without the colours that `grep` normally adds to it. :: `-q` prints nothing.
(-) It quotes the pattern for the shell, so that special characters in it are kept safe. :: Quoting is done by the shell.
(-) It searches faster because it ignores the case of the letters in the file and in the pattern, which skips some comparisons. :: Case is not affected.

@@q single | Case and count
Which command counts how many lines contain `error` in any capitalisation?
(+) `grep -ic error log` :: Combined options: ignore case and count.
(-) `grep -c error log | sort` :: Counts only exact-case matches.
(-) `grep -n error log` :: Prints lines with numbers, not a count.
(-) `grep -v error log` :: Prints the lines without the word.

@@q single | Filtering out noise
Which command shows the lines of `config` that are not comments (comments start with `#`)?
(+) `grep -v '^#' config` :: `-v` inverts; `^#` matches lines starting with a hash.
(-) `grep '^#' config` :: That shows *only* the comments.
(-) `grep -c '#' config` :: Counts lines containing a hash.
(-) `grep -l '#' config` :: Prints the file name.

@@q single | Searching a tree
Which command lists the files below `/etc` that contain the text `ssh`, printing only the file names?
(+) `grep -rl ssh /etc` :: Recursive, list names only.
(-) `grep ssh /etc` :: Without `-r`, grep complains that `/etc` is a directory.
(-) `grep -c ssh /etc` :: Also a directory error, and it would print counts.
(-) `ls /etc | grep ssh` :: Matches file *names*, not contents.

@@q single | grep on file names versus contents
What is the difference between `ls | grep foo` and `grep foo *`?
(+) The first keeps the file names that contain `foo`; the second searches the text inside every file of the directory. :: Names versus contents.
(-) They do the same thing, because `grep` always looks at the names of the files. :: They look at different data.
(-) The first searches inside the files of the directory, while the second looks only at the names of the files in it. :: Reversed.
(-) The second works only when the argument is a directory and fails for ordinary files. :: It works on the files matching the glob `*`.

@@q single | Several files
When `grep root /etc/passwd /etc/group` searches two files, how does the output change compared to one file?
(+) Each line is prefixed with the name of the file it came from. :: Use `-h` to hide the names.
(-) The output is sorted alphabetically, with the lines of both files mixed together. :: Order follows the files given.
(-) Only the first file is searched, and the second one is ignored by `grep`. :: Every file is.
(-) Identical lines found in both files are merged into a single line of output. :: That would be `sort -u`.

@@q single | Context lines
What does `grep -C 2 error log` add to the output?
(+) Two lines of context before and after each matching line. :: `-B` is before, `-A` after, `-C` both.
(-) Two more matching lines after the first match, and then the search stops. :: That would be `-m`.
(-) A count of two matches, printed at the end of the output of `grep`. :: Not a count.
(-) The last two lines of the file `log`, in addition to the matching lines. :: That is `tail`.

@@q match | Context options
Match each option with its effect.
(=) `-A 3` => Also print 3 lines after each match :: "After".
(=) `-B 3` => Also print 3 lines before each match :: "Before".
(=) `-C 3` => 3 lines before and after :: "Context".
(=) `-m 3` => Stop after 3 matching lines :: "Max count".
(-) Skip the first 3 lines :: That is `tail -n +4`.

@@group Basic regular expressions
@@q single | Pattern versus wildcard
What is the most important difference between a regular expression and a shell wildcard (glob)?
(+) A glob matches *file names* and is expanded by the shell; a regular expression matches *text* and is used by programs like `grep`. :: Their symbols also mean different things.
(-) There is no difference: both use the same symbols with the same meaning everywhere. :: `*` means "anything" in a glob but "repeat the previous item" in a regex.
(-) Regular expressions only work inside scripts, while globs work at the prompt. :: They work on the command line.
(-) Globs are more powerful than regular expressions, because the shell is a full language and expands them before any other program runs. :: Regular expressions are far more expressive.

@@q match | Star in glob and regex
Match each pattern with what it matches.
(=) glob `*.txt` => Any file name ending in `.txt` :: `*` stands for any characters.
(=) regex `a*` => Zero or more letters `a` :: `*` repeats the previous item.
(=) regex `.*` => Any text, including nothing :: A dot followed by a star: any character, repeated.
(=) glob `?` => Exactly one character of a file name :: A single-character wildcard.
(=) regex `.` => Exactly one character of any kind :: The regex counterpart of the glob `?`.
(-) A literal asterisk :: That needs an escape, `\*`.

@@q single | Dot
In a regular expression, what does `.` match?
(+) Any single character. :: Use `\.` to match a literal dot.
(-) A literal dot only. :: That needs a backslash.
(-) Zero or more characters. :: That is `.*`.
(-) The end of a line. :: That is `$`.

@@q fill | Literal dot
To match the text `c.t` but **not** `cat`, escape the dot: `grep 'c{{\. ;; [.]}}t' file`
(x) . :: Unescaped, the dot matches any character, so `cat` would match too.
@@note
Inside a bracket expression most special characters lose their meaning, so `[.]` is an equally good spelling.

@@q single | Anchors
What do `^` and `$` match in a regular expression?
(+) The start and the end of a line. :: They do not match characters, but positions.
(-) A literal caret and a literal dollar. :: Without context they are anchors.
(-) The start and end of a word. :: Word boundaries are `\<` and `\>`.
(-) The start and end of the file. :: `grep` works line by line.

@@q match | Anchored patterns
Match each pattern with the lines it selects.
(=) `^root` => Lines that start with `root` :: The caret anchors the start.
(=) `bash$` => Lines that end with `bash` :: The dollar anchors the end.
(=) `^$` => Empty lines :: Start immediately followed by end.
(=) `^root$` => Lines that consist of exactly `root` :: Anchored at both ends.
(-) Lines that contain a caret :: `^` would need an escape or a bracket: `[\^]`.

@@q single | Counting empty lines
Which command counts the empty lines of a file?
(+) `grep -c '^$' file` :: Start of line directly followed by end of line.
(-) `grep -c '$' file` :: Every line has an end, so this counts all lines.
(-) `grep -c '^' file` :: Also matches every line.
(-) `grep -c ' ' file` :: Counts lines that contain a space.

@@q sort | Which lines does `^[A-Z]` select
@@buckets Matches | Does not match
The pattern `^[A-Z]` requires the line to start with an upper-case letter. Classify each line.
(Matches) `Root login` :: Starts with `R`.
(Matches) `X` :: A single capital letter qualifies.
(Matches) `Zebra crossing` :: Starts with `Z`.
(Does not match) `root login` :: Lower-case first letter.
(Does not match) ` Root` :: A leading space: the first character is not a capital.
(Does not match) `3 Roots` :: Starts with a digit.

@@q single | Bracket expression
What does the pattern `b[ae]g` match?
(+) `bag` and `beg` :: Exactly one character out of the set inside the brackets.
(-) `baeg` :: A bracket matches a single character.
(-) `bg` :: One character from the set is required.
(-) `b[ae]g` literally. :: The brackets are special.

@@q match | Brackets in practice
Match each pattern with what it matches.
(=) `[aeiou]` => One vowel :: A list of characters.
(=) `[0-9]` => One digit :: A range.
(=) `[^0-9]` => One character that is not a digit :: The caret inside the bracket negates.
(=) `[A-Za-z]` => One ASCII letter :: Two ranges.
(=) `[[:space:]]` => One blank, tab or other white-space character :: A POSIX character class.
(-) A word made of vowels :: A bracket matches a single character; repeat it with `*` or `+` for a word.

@@q single | Caret meaning
What are the two different meanings of the caret `^` in a regular expression?
(+) Outside brackets it anchors the start of a line; as the first character inside brackets it negates the set. :: `^a` versus `[^a]`.
(-) It always negates the pattern that follows it, both inside and outside of brackets. :: Only inside a bracket.
(-) It always means the start of the line, also when it is the first character in a bracket, where it marks the start as well. :: Inside a bracket it negates.
(-) It means "or" between two alternatives, like the vertical bar does in `-E` patterns. :: That is `|` in extended expressions.

@@q single | Star and zero
Given the lines `ac`, `abc`, `abbc`, `abbbc`, how many of them does `ab*c` match?
(+) All four :: `b*` means zero or more `b`, so even `ac` matches.
(-) Three :: The line `ac` has zero `b`, which `*` allows.
(-) Two :: Every line fits.
(-) One :: `*` would need to be exact for that.

@@q single | A star that matches everything
Why does `grep 'f*' file` print every line of the file?
(+) `f*` means zero or more `f`, and "zero `f`" matches at any position of any line. :: A regex that can match the empty string matches all lines.
(-) Because `*` is a wildcard that stands for all the files of the current directory. :: That is a glob, not a regex.
(-) Because `grep` ignores the patterns that contain a star and prints everything instead. :: Nothing is ignored.
(-) Because the file happens to contain only lines that have the letter `f` in them. :: Not necessary.

@@q single | Pattern for words
Which pattern matches a line consisting of a four-letter word that starts with `c` and ends with `h` (such as `cash`)?
(+) `^c..h$` :: Anchored, `c`, two arbitrary characters, `h`.
(-) `^c*h$` :: Zero or more `c` followed by `h`.
(-) `c..h` :: Matches inside longer words too, such as `catch`.
(-) `^c.h$` :: Only one character in the middle.

@@q single | Whole words
Why is `grep -w cat` different from `grep cat`?
(+) `-w` accepts `cat` only as a whole word, so `concatenate` and `cats` are not matched. :: Word characters on either side block the match.
(-) `-w` matches words written in any language, not only the English ones. :: Not its purpose.
(-) `-w` writes the matching words to a file instead of printing them on the screen. :: No.
(-) `-w` makes the match case-insensitive, so `Cat` and `CAT` are found too. :: That is `-i`.

@@q fill | Three-letter b_g words
A word of exactly three letters, starting with `b`, ending in `g`, with `a` or `e` in the middle: `grep -w 'b{{[ae]}}g' words`
(x) (a|e) :: Alternation with parentheses needs `-E` (or a backslash) in basic expressions.
(x) a|e :: Without `-E`, `|` is an ordinary character.
@@note
A bracket expression works everywhere; alternation `a|e` needs extended syntax.

@@q single | Negated bracket
Which words of `bag`, `beg`, `big`, `bog` does `b[^ae]g` match?
(+) `big` and `bog` :: The middle character must be something other than `a` or `e`.
(-) `bag` and `beg` :: That is what `b[ae]g` matches.
(-) All four :: The set excludes two of them.
(-) None :: Two of them fit.

@@group Extended regular expressions and groups
@@q single | -E
What does the `-E` option (or the command `egrep`) change?
(+) It enables extended regular expressions, where `+`, `?`, `|`, `{}` and `()` are operators without backslashes. :: Easier to read than the basic dialect.
(-) It makes the search case-insensitive, so that capital letters match lower case ones. :: That is `-i`.
(-) It prints only the part of each line that matches, instead of printing the whole line, one match per output line. :: That is `-o`.
(-) It excludes the lines that match, printing only those that do not contain the pattern. :: That is `-v`.

@@q match | Repetition operators
Match each operator with its meaning in extended regular expressions.
(=) `+` => One or more of the previous item :: At least one.
(=) `?` => Zero or one of the previous item :: Optional.
(=) `*` => Zero or more of the previous item :: Any number, including none.
(=) `{2,4}` => Between two and four of the previous item :: A bounded repeat.
(=) `{3}` => Exactly three of the previous item :: An exact repeat.
(-) One or more of any character :: That would be `.+`.

@@q single | Basic versus extended plus
In basic regular expressions (plain `grep`), what does `a+b` match?
(+) The literal text `a+b`: `+` has no special meaning unless escaped (`a\+b`) or `-E` is used. :: GNU grep also accepts `\+`.
(-) One or more letters `a` followed by the letter `b`, as in `aab` and `ab`. :: That is the extended meaning.
(-) Nothing: it is an invalid pattern that makes `grep` print an error message. :: It is a valid pattern.
(-) Any text at all, since the plus sign stands for any characters in a pattern, so every line of the file is printed. :: No.

@@q single | Optional letter
Given the lines `ac`, `abc`, `abbc`, which does `grep -E 'ab?c'` select?
(+) `ac` and `abc` :: `b?` allows zero or one `b`.
(-) All three :: `abbc` has two `b`.
(-) Only `abc` :: Zero `b` is allowed.
(-) None :: Two lines fit.

@@q single | Plain grep and question mark
Given the same lines `ac`, `abc`, `abbc`, what does `grep 'ab?c'` (basic syntax, no `-E`) print?
(+) Nothing, because in basic syntax `?` is an ordinary character and no line contains `ab?c`. :: Use `-E` or `ab\?c`.
(-) `ac` and `abc`, because `?` makes the preceding letter optional in every dialect of regular expressions, basic ones included. :: That is the extended behaviour.
(-) All three lines, because `?` matches any single character in the middle. :: No.
(-) An error about an invalid pattern, because a question mark needs `-E`. :: The pattern is valid, just literal.

@@q fill | Alternatives
Print the lines that contain `cat` or `cut`: `grep -E 'cat{{|}}cut' file`
(x) , :: There is no comma operator in regular expressions.
(x) || :: The shell uses that between commands; in a regex a single bar separates alternatives.
@@note
In basic syntax the same is written `cat\|cut` with GNU grep.

@@q single | Grouping alternatives
Which pattern matches a line that consists of exactly `one` or exactly `two`?
(+) `grep -E '^(one|two)$'` :: The parentheses keep the anchors outside the alternation.
(-) `grep -E '^one|two$'` :: The anchors bind to the individual alternatives: lines starting with `one` or ending with `two`.
(-) `grep '^[one|two]$'` :: A bracket matches a single character.
(-) `grep -E '^onetwo$'` :: Matches the text `onetwo`.

@@q single | Anchors and alternation
Why does `grep -E '^root|daemon'` match the line `the daemon runs`?
(+) `^root` applies only to the first alternative; the second, `daemon`, matches anywhere on the line. :: Use `^(root|daemon)` to anchor both.
(-) `-E` ignores the `^` anchor, so the pattern matches at any position in the line. :: The anchor is honoured, but only for its own alternative.
(-) Because `|` is a literal character in this pattern, so `daemon` is just part of a longer word that the line has to contain. :: In `-E` it is the alternation operator.
(-) Because the line happens to end with the word `daemon`, which the anchor selects. :: Its end is irrelevant.

@@q single | Repeated group
What does `echo abcabc | grep -oE '(abc){2}'` print?
(+) `abcabc` :: The group `abc` repeated exactly twice.
(-) `abc` :: Only one copy would match `(abc){1}`.
(-) `abcabcabc` :: The input has only two copies.
(-) Nothing :: There is a match.

@@q single | Backreference
What does `\1` mean in `grep -E '(.)\1'`?
(+) A repeat of whatever the first group matched, so the pattern finds two identical characters in a row. :: It would match `aa` but not `ab`.
(-) The first character of the line, which the group `(.)` matches and then remembers for the rest of the pattern. :: It refers to the group's *match*.
(-) A literal digit `1`, which has to follow any character for the line to match. :: After a backslash a digit refers to a group.
(-) The first file given to `grep`, from which the matches are then printed. :: Not related.

@@q fill | IP address shape
Match something shaped like an IPv4 address (four groups of digits separated by dots): `grep -oE '[0-9]+(\.[0-9]+){{{3}}}'`
(x) {4} :: The first group of digits is already written; with four repeats the address would have five parts.
(x) * :: That would accept any number of dotted groups, including none.
@@note
Such a pattern accepts numbers like 999.1.1.1, so a validating script should also check the ranges.

@@q single | Extended or basic
Which of these commands behave the same?
(+) `grep -E 'a+'` and `grep 'a\+'` :: GNU grep supports `\+` in basic mode.
(-) `grep -E 'a+'` and `grep 'a+'` :: The second looks for a literal plus.
(-) `grep 'a|b'` and `grep -E 'a|b'` :: In basic syntax `|` is a literal character.
(-) `grep -E '(a)'` and `grep '(a)'` :: The second looks for literal parentheses.

@@group Fixed strings and special characters
@@q single | Literal search
You want to find lines containing the text `1.2.3` exactly, dots included. Which command is best?
(+) `grep -F '1.2.3' file` :: `-F` takes the pattern literally.
(-) `grep '1.2.3' file` :: Dots match any character, so `1x2y3` would match.
(-) `grep -w 1.2.3 file` :: Still a regular expression.
(-) `grep -v 1.2.3 file` :: That inverts the selection.

@@q single | Quoting patterns
Why should a pattern such as `a*b` be put in quotes on the command line?
(+) So that the shell does not treat `*` as a file-name wildcard before `grep` sees it. :: Without quotes `a*b` may expand to existing file names.
(-) Because `grep` refuses patterns without quotes and prints a syntax error instead. :: It is the shell's expansion that causes trouble.
(-) Because quotes are what turns the text into a regular expression for `grep`. :: Patterns are regular expressions by default.
(-) Because quotes make the search case-insensitive, like the option `-i` does. :: That is `-i`.

@@q single | Searching for a dollar
How do you search for the literal text `$HOME` in a file?
(+) `grep -F '$HOME' file` :: Single quotes keep the shell from expanding it; `-F` keeps `$` from being an anchor.
(-) `grep "$HOME" file` :: Double quotes let the shell replace it with your home path.
(-) `grep $HOME file` :: The same expansion.
(-) `grep '^HOME' file` :: That looks for lines that start with `HOME`.

@@q single | Escaping a bracket
Which pattern matches the literal text `[ERROR]` (with the square brackets)?
(+) `grep '\[ERROR\]' log` :: The backslashes make the brackets literal.
(-) `grep '[ERROR]' log` :: That matches any one of the letters E, R or O.
(-) `grep -w [ERROR] log` :: Same set problem.
(-) `grep -v ERROR log` :: Inverts.

@@q single | Tab character
A field in a file is separated by a tab. Which command reliably finds lines with a tab?
(+) `grep -P '\t' file` :: `-P` enables Perl-style escapes such as `\t`.
(-) `grep '\t' file` :: In basic syntax `\t` matches the letter `t`.
(-) `grep -E 't' file` :: Matches every line with the letter `t`.
(-) `grep -F 'tab' file` :: Searches for the word `tab`.

@@group Regexes in use
@@q single | Users without a login shell
Which command prints the lines of `/etc/passwd` whose shell is `/usr/sbin/nologin`?
(+) `grep 'nologin$' /etc/passwd` :: The shell is the last field; anchoring to the end is precise.
(-) `grep -v 'nologin' /etc/passwd` :: Prints the opposite.
(-) `grep '^nologin' /etc/passwd` :: Lines do not start with it.
(-) `grep -c nologin /etc/passwd` :: Prints a count.

@@q single | Users with uid over 999
Which pattern selects the lines of `/etc/passwd` where the third field is a number of four or more digits?
(+) `grep -E '^[^:]*:[^:]*:[0-9]{4,}:' /etc/passwd` :: Two fields without colons, then four or more digits, then a colon.
(-) `grep '[0-9]{4}' /etc/passwd`, with the braces taken literally in basic mode :: Without `-E` the braces are literal; and it would match digits anywhere.
(-) `grep -E '^[0-9]{4,}' /etc/passwd`, which looks at the start of the whole line :: That looks at the start of the line, where the user name is.
(-) `grep -w 1000 /etc/passwd`, which only finds the one specific number 1000 :: Only one specific number.

@@q single | Failed logins
Which pipeline counts the failed SSH password attempts in an `auth.log` whose lines contain `Failed password`?
(+) `grep -c 'Failed password' /var/log/auth.log` :: `-c` counts the matching lines.
(-) `grep -v 'Failed password' /var/log/auth.log | wc -l` :: Counts the lines that do *not* match.
(-) `grep -l 'Failed password' /var/log/auth.log` :: Prints the file name.
(-) `cat /var/log/auth.log | wc -w` :: Counts the words of the entire log.

@@q single | Extract the IPs
Which command prints only the IPv4 addresses found in `auth.log`, one per match?
(+) `grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' auth.log` :: `-o` prints only the matched part.
(-) `grep -E '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' auth.log` :: Prints the complete lines.
(-) `grep -c '[0-9]' auth.log` :: Counts lines with a digit.
(-) `cut -d' ' -f1 auth.log` :: Takes the first field of each line, not necessarily an address.

@@q order | Top attackers
Put the stages in order to list the five IP addresses with the most failed logins in `auth.log`, most frequent first.
(>) `grep 'Failed password' auth.log` :: Keep only failed-login lines.
(>) `grep -oE '[0-9]+(\.[0-9]+){3}'` :: Extract the address from each line.
(>) `sort | uniq -c` :: Group equal addresses and count them.
(>) `sort -nr | head -n 5` :: Rank by count and keep the top five.

@@q single | Which regex
You must match the lines that contain the word `error` followed by one or more digits, such as `error42`. Which pattern does it?
(+) `grep -E 'error[0-9]+'` :: A bracket for one digit, repeated at least once.
(-) `grep 'error[0-9]*'` :: `*` allows zero digits, so `error` alone matches too.
(-) `grep 'error.+'` :: Needs `-E` and accepts anything after `error`, not only digits.
(-) `grep -E 'error|[0-9]'` :: Matches lines that have either part.

@@q single | grep and the shell
After `grep -r "TODO" .`, you see many lines from files named `*.bak`. How can you skip those files?
(+) `grep -r --exclude='*.bak' TODO .` :: GNU grep can exclude file names that match a glob.
(-) `grep -r TODO . -v .bak`, where `-v` excludes the file names that match :: `-v` inverts lines, not file names.
(-) `grep -r TODO .bak`, which searches the directory called `.bak` only :: That searches a file or directory called `.bak`.
(-) `grep -r -i TODO .`, which ignores the case of the letters in the files :: Case is not the issue.

@@group Mixed practice
@@q fill | Lines that start with a capital
Print the lines of `file` that start with an upper-case letter: `grep '{{^[A-Z]}}' file`
(x) [A-Z] :: Without `^` it matches a capital anywhere in the line.
(x) ^A-Z :: Without brackets it looks for the literal text `A-Z` at the start.
@@note

@@q fill | Lines with a number
Extract the numbers of one or more digits with `grep -o`: `grep -oE '{{[0-9]+}}' file`
(x) [0-9] :: That prints one digit per match, not whole numbers.
(x) [0-9]* :: That can match the empty string and is not what you want here.
@@note
`-o` prints each match on its own line.

@@q fill | Invert the match
Show the lines of `log` that do NOT contain the word `DEBUG`: `grep {{-v}} DEBUG log`
(x) -c :: That counts the matching lines.
(x) -l :: That lists file names with a match.
@@note
`-v` is often combined with `-i` (`-vi`).

@@q sort | Does the pattern match
@@buckets Matches | Does not match
The pattern is `grep -E '^[0-9]{3}-[0-9]{4}$'`. Decide for each line.
(Matches) `555-1234` :: Three digits, a dash, four digits, nothing else.
(Matches) `000-0000` :: The digits can be anything.
(Does not match) `5551234` :: The dash is missing.
(Does not match) `555-12345` :: Five digits after the dash, but the pattern wants exactly four.
(Does not match) `call 555-1234` :: The anchors require the whole line to be the number.
(Does not match) `555-123a` :: The last character is not a digit.

@@q multi | Patterns that match the word cat
Select the patterns that match the line `a cat here`.
(+) `cat` :: The literal text is inside the line.
(+) `c.t` :: The dot stands for the `a`.
(+) `^a c` :: The line starts with `a c`.
(+) `[cb]at` :: Either `cat` or `bat`.
(-) `^cat` :: The line does not start with `cat`.
(-) `cat$` :: The line does not end with `cat`.

@@q order | Extract failed login addresses
Put the stages in order to list each IPv4 address that had a failed SSH password, once, most attempts first.
(>) `grep 'Failed password' auth.log` :: Keep only the failed attempts.
(>) `grep -oE '[0-9]+(\.[0-9]+){3}'` :: Pull out the address of each line.
(>) `sort | uniq -c` :: Count the attempts per address.
(>) `sort -nr` :: Put the most frequent first.

@@q match | Symbols and their meaning
Match each regular-expression fragment with what it means in extended syntax.
(=) `a{2,3}` => Two or three `a` :: A bounded repetition.
(=) `(ab)+` => One or more repetitions of the group `ab` :: The plus applies to the group.
(=) `[^,]*` => Any number of characters that are not commas :: A negated bracket with a star.
(=) `\.` => A literal dot :: The backslash removes the special meaning.
(=) `^$` => An empty line :: Start immediately followed by end.
(-) Any character :: That is a plain `.`.
