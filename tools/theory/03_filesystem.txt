@@collection 03_filesystem | Files, directories, links & archives
@@about
The directory tree and paths, inodes, hard and symbolic links, copying, moving and removing, mounting and disk space, and archives with tar and gzip.

@@group The directory tree and paths
@@q single | One tree for everything
How does Linux present its storage devices to the user?
(+) As a single hierarchical tree starting at `/`, where other file systems are attached at directories. :: There are no drive letters; a second disk simply appears under some directory.
(-) As separate trees named `C:`, `D:`, and so on. :: That is the Windows model.
(-) As a flat list of files with no directories. :: Directories are central to Unix.
(-) As one tree per user, each rooted in the home directory. :: There is one system-wide tree; homes are branches of it.

@@q sort | Absolute or relative
@@buckets Absolute path | Relative path
Classify each path.
(Absolute path) `/usr/local/bin` :: Starts with `/`, so it is resolved from the root regardless of where you are.
(Absolute path) `/` :: The root directory itself.
(Absolute path) `/home/alumno/../alumno/docs` :: It begins at the root; the `..` inside does not change that.
(Relative path) `docs/notes.txt` :: No leading slash: resolved from the current directory.
(Relative path) `../lib/modules` :: Starts from the parent of the current directory.
(Relative path) `./run.sh` :: `.` is the current directory; the path is still relative.

@@q match | Special directory names
Match each notation with its meaning.
(=) `.` => The current directory :: Used, for example, as `./script.sh`.
(=) `..` => The parent directory :: One level up.
(=) `~` => Your home directory :: Expanded by the shell to `$HOME`.
(=) `~luke` => The home directory of user luke :: The shell looks the user up.
(=) `-` (as in `cd -`) => The previous directory :: Jumps back to where you were.
(-) The root of the file system :: That is `/`, never `~`.

@@q single | Root directory and parent
What does `cd ..` do when you are already in `/`?
(+) You stay in `/`, because the root's parent is itself. :: There is nothing above the root.
(-) It fails with an error. :: It succeeds silently.
(-) It moves you to your home directory. :: `cd` without arguments does that.
(-) It moves you to `/home`. :: Not related.

@@q single | cd without arguments
Which command always takes you to your home directory?
(+) `cd` (no argument), or `cd ~` :: Bash reads `$HOME` when no directory is given.
(-) `cd /` :: That is the root directory.
(-) `cd .` :: That stays in the current directory.
(-) `cd ..` :: That goes one level up.

@@q multi | Ways to print the current directory
Which of these print the current working directory?
(+) `pwd` :: The standard command.
(+) `echo $PWD` :: The shell keeps the path in this variable.
(-) `ls` :: It lists the *contents*, not the directory's own path.
(-) `cd` :: It changes directory and prints nothing.

@@q single | Hidden files
Which statement about hidden files is correct?
(+) A file is "hidden" simply because its name starts with a dot; `ls -a` shows it. :: There is no separate hidden attribute in Unix.
(-) They have a special permission bit called `h`. :: Nothing like that exists.
(-) They cannot be opened by normal users. :: Hidden files are readable like any other.
(-) They are stored in a secret area of the disk. :: Only the name differs.

@@q match | ls options
Match each option with its effect.
(=) `ls -a` => Include hidden files, also `.` and `..` :: "All".
(=) `ls -A` => Include hidden files, but not `.` and `..` :: "Almost all".
(=) `ls -l` => Long format with permissions, owner, size and date :: One line of detail per entry.
(=) `ls -R` => Recurse into sub-directories :: Lists the whole sub-tree.
(=) `ls -i` => Show the inode number of each entry :: Useful to spot hard links.
(-) Sort the output by size :: That is `-S`, not any of these.

@@q single | First character of ls -l
In the output of `ls -l`, what does the first character of the mode field, `d` in `drwxr-xr-x`, tell you?
(+) The entry is a directory. :: `-` would be a regular file and `l` a symbolic link.
(-) The entry is deletable. :: Deletability depends on the parent directory's permissions.
(-) The entry is a device. :: Devices show `b` or `c`.
(-) The entry is a hidden file. :: Hidden files are recognised by their name, not by this flag.

@@q fill | Create nested directories
To create `a/b/c` in one go, even when `a` and `b` do not exist yet: `mkdir {{-p}} a/b/c`
(x) -r :: `-r` is not an option of `mkdir`; `-r` is for recursion in `cp`, `rm` and `ls -R`.
(x) -a :: `mkdir` has no such option.
@@note
Without `-p`, `mkdir a/b/c` fails if `a/b` is missing.

@@q single | Removing a directory
Which statement about `rmdir` is correct?
(+) It removes a directory only if it is empty. :: To delete a directory with contents use `rm -r`.
(-) It removes a directory and everything inside it. :: That is `rm -r`.
(-) It removes only hidden directories. :: It does not filter by name.
(-) It moves the directory to a trash folder. :: Unix has no global trash in the shell.

@@q single | rm on a directory
What does `rm somedir` (no options) do when `somedir` is a directory?
(+) It refuses and prints `Is a directory`. :: You need `-r` (or `rmdir` for an empty one).
(-) It deletes the directory if it is empty. :: That is what `rmdir` does, not plain `rm`.
(-) It deletes the directory and its contents. :: That needs `-r`.
(-) It renames the directory. :: Renaming is `mv`.

@@group Inodes and links
@@q multi | What an inode stores
Select the information that is stored in an inode.
(+) The owner and group. :: Part of the file's metadata.
(+) The permission bits. :: Stored in the inode, not in the directory.
(+) The size and the time stamps. :: Also metadata of the inode.
(+) The location of the file's data blocks on disk. :: The inode points to where the contents are.
(-) The file's name. :: Names live in directory entries, which point to inodes.

@@q single | What a directory is
What is a directory, internally?
(+) A special file containing a list of names, each paired with the inode number of the file it names. :: Names belong to directories, not to inodes.
(-) A folder that physically contains the file data. :: Data lives in blocks referenced by inodes.
(-) A copy of every file below it. :: Directories hold only the name→inode mapping.
(-) A table of permissions. :: Permissions are in the inodes.

@@q single | Why a rename is cheap
Why is `mv file1 file2` inside one file system practically instant, even for a huge file?
(+) Only the directory entry (the name) changes; the inode and the data blocks stay exactly where they are. :: No data is copied.
(-) Because `mv` compresses the file first. :: It does not.
(-) Because the file is moved to the trash. :: There is no trash step.
(-) Because the data is always small in Linux. :: Size is irrelevant to a rename.

@@q single | Hard link meaning
What is a hard link created with `ln f hard`?
(+) A second directory entry (name) that points to the same inode as `f`. :: Both names are equal; neither is "the original".
(-) A small file that stores the path `f`. :: That describes a symbolic link.
(-) A copy of `f` with its own inode and data blocks. :: A copy would be independent; a hard link is not.
(-) A reference that dies when `f` is deleted. :: Hard links survive the removal of any one name.

@@q sort | Hard or symbolic link
@@buckets Hard link | Symbolic link
Which kind of link has the described property?
(Hard link) Shares the inode of the original :: Both names point to the very same inode number.
(Hard link) Still works after the other name is deleted :: The data exists until the last name is removed.
(Hard link) Cannot point to a directory (normally) :: The kernel forbids hard links to directories to avoid loops.
(Symbolic link) Can point to a file on another file system :: It stores only a path, so it can cross file systems.
(Symbolic link) Becomes a broken link if the target is removed :: The path then points to nothing.
(Symbolic link) Has its own inode, shown with type `l` in `ls -l` :: It is a tiny file containing a path.

@@q single | Link count
`ls -l` shows a number right after the mode field, for example `-rw-r--r-- 2 user group`. What is that `2`?
(+) The number of directory entries (hard links) that point to that inode. :: A plain file normally has 1.
(-) The number of users who can read the file. :: Not tracked there.
(-) The size of the file in blocks. :: Size is a separate column.
(-) The number of times the file was opened. :: Not recorded.

@@q single | Delete one name
A file `f` has a hard link `g`. After `rm f`, what is true?
(+) The contents remain available through `g`, and the link count drops from 2 to 1. :: The file disappears only when the count reaches 0 and nothing has it open.
(-) `g` becomes a broken link. :: That is how a *symbolic* link behaves.
(-) Both names vanish. :: `rm` removes only the name you give.
(-) The data is moved into `g`. :: Nothing is moved; `g` always pointed to the same data.

@@q single | Broken symlink
You create `ln -s f soft`, then run `rm f`. What happens with `cat soft`?
(+) It fails with "No such file or directory", because the link still exists but its target does not. :: `ls -l soft` still shows `soft -> f`.
(-) It prints the old contents of `f`. :: The data belonged to `f`; a symlink stores only its name.
(-) It creates a new empty `f`. :: `cat` never creates files.
(-) `soft` was deleted together with `f`. :: The link is a separate directory entry.

@@q fill | Create a symbolic link
To create a symbolic link named `short` that points to `/usr/share/dict/words`: `ln {{-s}} /usr/share/dict/words short`
(x) -h :: Not the option to make a symbolic link in `ln`.
@@note
The argument order is like `cp`: target first, link name second. Without `-s` you get a hard link.

@@q single | ln argument order
In `ln -s target linkname`, which argument is the existing file?
(+) `target` :: The first is what you link *to*; the second is the new name you create.
(-) `linkname` :: That is the name that will be created.
(-) Both are created. :: Only the link is created.
(-) Neither, `ln` needs a third argument with the directory. :: Two arguments suffice.

@@q single | Directory link counts
An empty directory shows a link count of 2 in `ls -ld`. What happens to that count when you create a sub-directory inside it?
(+) It becomes 3, because each sub-directory's `..` entry points back to the parent. :: The count is 2 plus the number of sub-directories.
(-) It stays 2. :: The `..` entries add to the parent's count.
(-) It becomes 1. :: Directories never drop below 2.
(-) It increases for every file, not for directories. :: Files do not add links to their parent.

@@q multi | Symbolic link facts
Select the true statements about symbolic links.
(+) They can point to directories. :: Common for shortcuts like `current -> release-12`.
(+) They can point to a file that does not exist (a dangling link). :: The path is not checked at creation time.
(+) `ls -l` shows the target with `->`. :: For example `soft -> f`.
(-) They share the inode of their target. :: They have their own inode.
(-) They keep the data alive after the target is deleted. :: The data is owned by the target's inode.

@@q single | Permissions of a symlink
Why does `ls -l` show `lrwxrwxrwx` for every symbolic link?
(+) The permissions of the link itself are not used; access is decided by the permissions of the file it points to. :: The kernel follows the link first.
(-) Because every symbolic link is executable. :: The shown bits mean nothing.
(-) Because only root can create them. :: Anyone can create one.
(-) Because the target's permissions are copied into the link. :: Nothing is copied.

@@group Copying, moving, removing, touching
@@q match | Basic file commands
Match each command with what it does.
(=) `cp a b` => Makes a copy of `a` named `b` :: A new file with its own inode.
(=) `mv a b` => Renames `a` to `b`, or moves it :: Same inode when on the same file system.
(=) `rm a` => Removes the name `a` :: The data goes when no names remain.
(=) `touch a` => Creates `a` if absent, or updates its timestamp :: Often used to make an empty file.
(=) `mkdir d` => Creates the directory `d` :: An empty directory.
(-) Compresses `a` :: That is `gzip`.

@@q multi | cp options
Select the correct statements about options of `cp`.
(+) `-r` copies directories recursively. :: Without it `cp` refuses to copy a directory.
(+) `-i` asks before overwriting. :: A safety net against accidental overwrites.
(+) `-u` copies only when the source is newer or the destination is missing. :: It updates.
(+) `-a` preserves attributes and copies recursively, keeping symbolic links as links. :: Archive mode.
(-) `-l` lists the files being copied. :: `-l` makes hard links instead of copies; `-v` lists.

@@q single | Copying a symlink
`cp soft copy` where `soft` is a symbolic link to a regular file. What is `copy`?
(+) A regular file with the target's content, because `cp` follows the link by default. :: Use `-P` or `-a` to copy the link itself.
(-) A symbolic link to the same target. :: That happens with `cp -P` or `cp -a`.
(-) A hard link. :: That would need `cp -l`.
(-) An empty file. :: It contains the data of the target.

@@q single | mv a directory
`mv dirA dirB` when `dirB` already exists and is a directory. What happens?
(+) `dirA` is moved inside `dirB`, becoming `dirB/dirA`. :: If `dirB` did not exist it would be a rename.
(-) `dirB` is overwritten by `dirA`. :: Non-empty directories are not replaced by `mv`.
(-) The contents of `dirA` are merged into `dirB`. :: `mv` does not merge.
(-) The command fails because the target exists. :: It works and nests the directory.

@@q single | rm -i
Which option makes `rm` ask for confirmation before each removal?
(+) `-i` :: Interactive mode; handy when working as root.
(-) `-f` :: Forces removal without asking, ignoring non-existent files.
(-) `-r` :: Recursion, it does not ask by itself.
(-) `-v` :: Verbose output only.

@@q single | The dangerous rm
Which command is the most dangerous one if a variable turns out empty, as in `rm -rf "$DIR"/*` with `DIR` unset?
(+) It expands to `rm -rf /*`, attempting to delete everything the user can. :: Always check variables before recursive deletion.
(-) `rm -i` would be equally risky. :: It asks for every file, which gives you a chance to stop.
(-) `rmdir "$DIR"/*` :: `rmdir` removes only empty directories.
(-) `ls "$DIR"/*` :: It only lists.

@@q single | touch on a missing file
What does `touch newfile` do when `newfile` does not exist?
(+) It creates an empty file with that name. :: Its main side use.
(-) It fails with an error. :: No error.
(-) It creates an empty directory. :: Directories need `mkdir`.
(-) It opens an editor. :: `touch` has no interactive part.

@@q fill | Set a date
To create `old` with the modification date set to 2 January 2020 (date only): `touch {{-d}} "2020-01-02" old`
(x) -t :: `-t` also sets a time, but needs a different stamp format `[[CC]YY]MMDDhhmm[.ss]`, not this string.
@@note
`--date="..."` is the long form of `-d`.

@@q single | Temporary files
What does `mktemp` provide compared with choosing a name like `/tmp/out`?
(+) A unique, unpredictable file name, created safely, so two runs do not collide. :: It prints the name of the new file.
(-) A file that is deleted automatically when the script ends. :: You must remove it yourself.
(-) A file stored in memory. :: `/tmp` may be RAM-backed on some systems, but `mktemp` does not guarantee that.
(-) A compressed file. :: It creates an empty file or directory.

@@q single | Wildcard deletion
In a directory you run `rm *.txt`. Which files does the shell pass to `rm`?
(+) Every file whose name ends in `.txt`, expanded before `rm` starts. :: Globbing is done by the shell, not by `rm`.
(-) Only one file at a time. :: All matches are passed as arguments.
(-) The literal text `*.txt`, which `rm` then interprets. :: Only when no file matches and `nullglob` is off.
(-) Every file of the directory. :: Only those that match.

@@group Mounting and disk space
@@q single | What mounting does
What does `mount /dev/sdb1 /mnt/usb` do?
(+) It attaches the file system on that device to the directory `/mnt/usb`, so its files appear there. :: The directory is the mount point.
(-) It formats the device. :: Formatting is `mkfs`.
(-) It copies the device to `/mnt/usb`. :: Nothing is copied.
(-) It deletes the device. :: Mounting is non-destructive.

@@q single | Unmount
Which command detaches a mounted file system?
(+) `umount /mnt/usb` :: Note the spelling: there is no `n` after `u`.
(-) `unmount /mnt/usb` :: A common misspelling.
(-) `mount -d /mnt/usb` :: Not an option for that.
(-) `rm /mnt/usb` :: It would try to remove a directory.

@@q match | Disk space tools
Match each command with its output.
(=) `df -h` => Free and used space of each mounted file system in human-readable units :: Looks at whole file systems.
(=) `du -sh dir` => Total size used by a directory tree, human-readable :: Looks at the files below a path.
(=) `mount` (no arguments) => The list of mounted file systems :: Shows devices and mount points.
(=) `stat file` => Inode metadata of a file (size, links, times, permissions) :: The raw attributes.
(=) `tree` => An indented picture of a directory tree :: Often not installed by default.
(-) Compresses a directory :: That would be `tar` with `-z`.

@@q single | df versus du
What is the main difference between `df` and `du`?
(+) `df` reports space per file system (free and used), while `du` adds up the space used by the files of a path. :: One looks from the disk, the other from the files.
(-) `df` works only for directories, `du` only for files. :: Both work at different scopes; this split is wrong.
(-) `du` shows free space, `df` shows file sizes. :: Reversed.
(-) They are the same program with two names. :: They are separate commands.

@@q single | Human-readable
What does the `-h` option do in `df -h` and `du -h`?
(+) Prints sizes in units like K, M and G instead of raw blocks. :: "Human readable".
(-) Hides the header line. :: No.
(-) Shows hidden files. :: That is `ls -a`.
(-) Prints a help message. :: That is `--help`.

@@q single | Depth of du
Which command shows the space used by each sub-directory of the current directory, but not deeper?
(+) `du -h --max-depth=1` :: Limits the recursion to one level below the starting point.
(-) `du -s` :: Prints a single total only.
(-) `df -d 1` :: `df` does not walk directories.
(-) `ls -R` :: It lists names, not sizes.

@@q single | Full disk vs. du
`df` says a file system is 100% full, yet `du` of its top directory adds up to much less. Which explanation is plausible?
(+) A deleted file is still held open by a running process, so its space is not freed yet. :: `du` no longer sees the name, `df` still counts the blocks.
(-) `du` counts hidden files twice. :: That would make it higher, not lower.
(-) `df` measures in bits and `du` in bytes. :: Both use blocks/bytes consistently.
(-) Compression is applied only by `du`. :: Neither command compresses.

@@group Archives and compression
@@q single | Archive versus compression
What is the difference between tar and gzip?
(+) `tar` bundles several files and directories into one archive file; `gzip` compresses one file or stream. :: They are often combined to get `.tar.gz` or `.tgz`.
(-) `tar` compresses, `gzip` bundles. :: Reversed.
(-) They are identical. :: They solve different problems.
(-) `gzip` encrypts the archive. :: It does not encrypt.

@@q match | tar options
Match each tar option with its meaning.
(=) `c` => Create an archive :: Writes a new archive.
(=) `x` => Extract files from an archive :: Restores the files.
(=) `t` => List the contents of an archive :: Shows names without extracting.
(=) `z` => Filter through gzip :: Compresses on creation, decompresses on extraction.
(=) `f` => The next argument is the archive file name :: Without it tar uses a default device.
(=) `v` => Verbose: show files as they are processed :: Helpful for feedback.
(-) Delete the original files afterwards :: `tar` never removes the originals on its own.

@@q fill | Create a compressed archive
To create a gzip-compressed archive `backup.tgz` containing the directory `docs`: `tar {{czf}} backup.tgz docs`
(x) xzf :: `x` extracts; it would fail because `backup.tgz` does not exist yet.
(x) tzf :: `t` only lists an existing archive.
@@note
The option letters may be combined; `f` has to be last of the group since it takes the next argument.

@@q fill | Extract a compressed archive
To extract `backup.tgz` into the current directory: `tar {{xzf ;; xvzf ;; zxf ;; zxvf}} backup.tgz`
(x) czf :: `c` would try to create (and overwrite) the archive.
@@note
Add `-C dir` to extract somewhere else.

@@q single | List before extracting
Before extracting an archive from an untrusted source, you want to see which files it contains. Which command does that?
(+) `tar tzf archive.tgz` :: `t` lists without extracting.
(-) `tar xzf archive.tgz` :: Extracts immediately.
(-) `tar czf archive.tgz` :: Would try to create an archive.
(-) `gzip -l archive.tgz` :: It shows compression statistics, not the files inside the tar.

@@q single | gzip removes the original
What does `gzip notes.txt` do by default?
(+) It replaces `notes.txt` with the compressed `notes.txt.gz`. :: Use `-k` to keep the original.
(-) It creates `notes.txt.gz` and keeps `notes.txt`. :: Only with `-k`.
(-) It compresses the file in place without renaming it. :: The suffix `.gz` is added.
(-) It archives the current directory. :: That is `tar`.

@@q single | gunzip
How do you decompress `notes.txt.gz`?
(+) `gunzip notes.txt.gz` (or `gzip -d notes.txt.gz`) :: Restores `notes.txt` and removes the `.gz`.
(-) `ungzip notes.txt.gz` :: No such command.
(-) `tar x notes.txt.gz` :: `tar` extracts archives, not single gzip files.
(-) `cat notes.txt.gz > notes.txt` :: That copies the compressed bytes.

@@q match | File extensions
Match each extension with what you expect.
(=) `.tar` => An uncompressed tar archive :: Bundled, not compressed.
(=) `.gz` => A file compressed with gzip :: One compressed file.
(=) `.tgz` or `.tar.gz` => A tar archive compressed with gzip :: Both steps.
(=) `.Z` => A file compressed with the old `compress` command :: Decompressed with `uncompress`.
(-) An encrypted backup :: None of these formats encrypts.

@@q order | Backup workflow
Put these steps of making and verifying a compressed backup in order.
(>) Create the archive: `tar czf b.tgz docs` :: Nothing else can happen before the file exists.
(>) List it: `tar tzf b.tgz` :: Check that the files you expect are inside.
(>) Copy it somewhere safe: `cp b.tgz /backup/` :: Only worth copying after the check.
(>) Extract a test copy in a temporary directory :: The real test of a backup is restoring it.

@@q single | Order of tar arguments
You meant to archive `notes.txt` into `notes.tgz` but typed `tar czf notes.txt notes.tgz`. What is the damage?
(+) The first name after `f` is the archive to write, so `notes.txt` is overwritten by a gzip archive, which contains the file `notes.tgz`. :: The archive name goes right after `f`; the files to add follow.
(-) None: tar always sorts its arguments so that the archive comes last. :: It does not guess; the position after `f` decides.
(-) tar refuses and prints a help message. :: It performs exactly what you wrote.
(-) `z` deletes the source file. :: `z` only compresses.
@@note
With a directory in that position tar would fail with "Is a directory" instead; with a plain file, the original data is silently lost.

@@group Predict the result
@@q single | Count entries
In an empty directory `d` you run `touch a b; mkdir c; ls -l d | wc -l` from its parent. What number is printed?
(+) 4 :: `ls -l` prints a "total" line plus one line per entry (a, b, c).
(-) 3 :: That forgets the header line `total N`.
(-) 5 :: `.` and `..` are not shown without `-a`.
(-) 2 :: Not correct for three entries.

@@q single | Copy into itself
What does `cp -r dir dir/copy` (copying a directory into itself) do in GNU `cp`?
(+) It refuses with an error like "cannot copy a directory into itself". :: Otherwise it would recurse forever.
(-) It creates `dir/copy` with all the contents of `dir`. :: That is what a copy to a *different* place would do.
(-) It renames `dir` to `copy`. :: That is `mv`.
(-) It silently does nothing. :: The error message is printed.

@@q single | Link count after creating links
A file has a link count of 1. You run `ln f h` and `ln -s f s`. What is the link count of `f` now?
(+) 2 :: The hard link `h` adds one; the symbolic link `s` is a separate file and does not count.
(-) 3 :: A symbolic link does not increase the target's count.
(-) 1 :: The hard link added a name.
(-) 0 :: Counts never go to zero while names exist.

@@q single | Overwritten on mv
`mv a b` where `b` already exists as a regular file (and no `-i` or alias). What happens?
(+) `b` is silently replaced by `a`. :: That is why many people alias `mv` to `mv -i`.
(-) The command asks for confirmation by default. :: Not without `-i`.
(-) `a` is appended to `b`. :: `mv` never concatenates.
(-) It fails because `b` exists. :: It does not fail.

@@q single | Current dir in a script
Immediately after `mkdir -p a/b/c && cd a/b/c && cd ../..`, where are you relative to the starting directory?
(+) In `a` :: Two levels up from `a/b/c` is `a`.
(-) In `a/b` :: That would be a single `..`.
(-) In the starting directory :: That takes three `..`.
(-) In `c` :: `cd ../..` moved you away from it.
