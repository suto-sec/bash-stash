@@ex 1223 ps_intro | ps: checking a process exists
@@level 1
@@cmds ps -p
@@readme
`ps -p PID` succeeds (exit status 0) if a process with that PID exists, and fails if it does not.

1. Start `sleep 300` in the background (add `&` at the end of the line) and save its PID with `PID=$!` (`$!` is the PID of the last background command).
2. If `ps -p "$PID" > /dev/null` succeeds print `found`, otherwise print `not found` (`> /dev/null` hides the table that `ps` prints).
3. Kill the process with `kill "$PID"` so it does not keep running.

Expected output:

```
found
```

Hint: `if COMMAND; then echo one; else echo two; fi`
@@check
SEEDS=1
extra_check() { must_use ps kill; }
@@solution
#!/bin/bash
sleep 300 &
P=$!
if ps -p "$P" > /dev/null; then echo found; else echo "not found"; fi
kill "$P" 2>/dev/null

@@ex 1224 kill_intro | kill: terminating a background process
@@level 1
@@cmds kill, wait
@@readme
`kill PID` asks a process to end (it sends the signal SIGTERM). `wait PID` waits for a background process to finish; afterwards `$?` holds the exit status of that process. A process ended by SIGTERM has the exit status `143`.

1. Start `sleep 300` in the background and save its PID (`PID=$!`).
2. End it with `kill "$PID"`.
3. Wait for it with `wait "$PID"`.
4. Print the exit status with `echo $?`.

Expected output:

```
143
```
@@check
SEEDS=1
extra_check() { must_use kill wait; }
@@solution
#!/bin/bash
sleep 300 &
P=$!
kill "$P"
wait "$P"
echo $?

@@ex 1225 jobs_intro | jobs: listing background jobs
@@level 1
@@cmds jobs
@@readme
`jobs` lists the background jobs of the current shell, one per line, with their number and state.

1. Start `sleep 0.3` in the background (`&`).
2. Start `sleep 0.4` in the background.
3. Immediately run `jobs` to print the list.

Expected output (the amount of spaces does not matter):

```
[1]-  Running                 sleep 0.3 &
[2]+  Running                 sleep 0.4 &
```

Run `jobs` right after starting the two commands, before they finish.
@@check
SEEDS=1
filter() { sed 's/  */ /g'; }
extra_check() { must_use jobs; }
@@solution
#!/bin/bash
sleep 0.3 &
sleep 0.4 &
jobs

@@ex 1226 background_intro | &: running a command in the background
@@level 1
@@cmds &, $!, wait
@@readme
Ending a command with `&` runs it in the background: the shell does not wait and goes on with the next line. `$!` holds the PID of the last background command and `wait PID` waits for it to finish.

1. Start `sleep 0.2` in the background (`&`) and save its PID (`PID=$!`).
2. Print `launched` right away.
3. Wait for the process with `wait "$PID"`.
4. Print `done`.

Expected output:

```
launched
done
```
@@check
SEEDS=1
extra_check() { must_use wait; }
@@solution
#!/bin/bash
sleep 0.2 &
P=$!
echo launched
wait "$P"
echo done
